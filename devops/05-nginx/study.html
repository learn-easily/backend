Nginx — საიტი შენს სერვერზე

წაიკითხე ლექციის შემდეგ, ან პრეზენტაციასთან ერთად: პრეზენტაციაში დააჭირე P და ეს გვერდი სლაიდებს გაჰყვება. კოდი და AI-ს პრომპტები კოპირდება ერთი დაჭერით.

გამეორება

გავიხსენოთ წინა ლექცია

სლაიდი 1

ლექცია 4 — SSH და Droplet — საკუთარი სერვერი. ახალ თემამდე ვამოწმებთ, რა დაგვამახსოვრდა. ჯერ თვითონ უპასუხე, მერე გახსენი პასუხი. თუ რომელიმე გაგიჭირდა, წინა ლექციის კონსპექტს გადახედე.

✅ შეამოწმე თავი დაფიქრდი, მერე გახსენი პასუხი
SSH-ის რომელი გასაღები რჩება შენთან და რომელი მიდის სერვერზე?
პირადი (id_ed25519) — მხოლოდ შენს კომპიუტერზე, არავის აჩვენო. საჯარო (id_ed25519.pub) — სერვერზე, ~/.ssh/authorized_keys-ში
რატომ ჯობია გასაღები პაროლს?
პაროლს ბოტები უწყვეტად არჩევენ (brute force); გასაღების გამოცნობა პრაქტიკულად შეუძლებელია და მისი „მოპარვა“ სერვერიდან არ შეიძლება — იქ მხოლოდ საჯარო ნაწილია
რატომ ვქმნით ცალკე user-ს და ვკრძალავთ root-ით შესვლას?
root-ს ყველაფრის უფლება აქვს და მის სახელს ყველა ბოტი იცის. ცალკე user-ით ვმუშაობთ, საჭიროებისას sudo-თი — შეცდომაც და შეტევაც ნაკლებ ზიანს აყენებს
რას აკეთებს ufw და რომელი port უნდა გავხსნათ ჩართვამდე?
ufw — firewall: ყველა შემოსულ კავშირს ბლოკავს, გარდა ნებადართულისა. ჩართვამდე აუცილებლად ufw allow OpenSSH (port 22) — თორემ საკუთარ თავს ჩაკეტავ
SSH-ის კონფიგი შეცვალე. რა გააკეთო, ძველ ფანჯარას რომ დახურავ?
ჯერ Termius-ის ახალ tab-ში შეამოწმე, რომ ახალი user-ით შესვლა მუშაობს. ძველი სესია ღია დატოვე — თუ რამე გაფუჭდა, მისით გაასწორებ
Droplet გამოვრთე (Power Off). ფული აღარ ჩამოგეჭრება?
ჩამოგეჭრება — გამორთული Droplet-იც ფასიანია, რადგან რესურსი შენთვისაა დაჯავშნილი. გადახდა მხოლოდ Destroy-ის შემდეგ ჩერდება

საშინაოს განხილვა

საშინაოს განხილვა

სლაიდი 3

წინა ლექციის საშინაო: სერვერის დაცვა. ქვემოთ არის ერთ-ერთი სწორი ამოხსნა. შენი კოდი შეიძლება სხვანაირად იყოს დაწერილი — მთავარია, მოთხოვნები სრულდებოდეს.

მოთხოვნები

  • apt upgrade · 00-hardening.conf: root და პაროლი აკრძალულია → restart ssh (ჯერ Termius-ის ახალ tab-ში შეამოწმეთ!)
  • ufw: მხოლოდ OpenSSH → enable
  • swap 2 GB (/etc/fstab-ითაც) · WSL-ში ~/.ssh/config → ssh lms

ამოხსნა

Termius · lms-server
$ sudo nano /etc/ssh/sshd_config.d/00-hardening.confPermitRootLogin noPasswordAuthentication no $ sudo sshd -t                     # ცარიელი პასუხი = OK$ sudo systemctl restart ssh $ sudo ufw allow OpenSSH$ sudo ufw enable$ sudo ufw statusStatus: active
Termius · lms-server
$ sudo apt update && sudo apt upgrade -y $ sudo fallocate -l 2G /swapfile$ sudo chmod 600 /swapfile$ sudo mkswap /swapfile$ sudo swapon /swapfile$ echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
~/.ssh/config (WSL-ში)
Host lms    HostName 164.90.12.34    User giorgi    IdentityFile ~/.ssh/id_ed25519

ფაილის სახელი 00- იწყება, რადგან SSH ერთ პარამეტრზე პირველ ნანახ მნიშვნელობას იღებს, ფაილებს კი ანბანით კითხულობს — 00 ყველაზე ადრე იკითხება.

დღის თემა

დღის თემა: Nginx — საიტი შენს სერვერზე

სლაიდი 4

სერვერი გვაქვს, მაგრამ ბრაუზერში მის IP-ს თუ გახსნი — არაფერი: port 80-ს არავინ უსმენს. გვჭირდება ვებ-სერვერი — პროგრამა, რომელიც ბრაუზერის მოთხოვნებს იღებს და ფაილებს აბრუნებს. დღეს ვაყენებთ Nginx-ს და ვაქვეყნებთ ორ საიტს: my-portfolio-ს და შენს Angular აპს — ამჯერად GitHub-ის გარეშე, საკუთარ სერვერზე.

ლექციის ბოლოს შეძლებ:

  • Nginx-ის დაყენება და მართვა systemctl-ით
  • ფაილების ატვირთვა სერვერზე rsync-ით
  • server block-ის დაწერა: listen, root, index, try_files
  • Angular SPA-ს გამოქვეყნება და „refresh → 404“ პრობლემის გადაჭრა
  • Nginx-ის ლოგების კითხვა და 403/404/connection refused-ის მიზეზის პოვნა

1 · Nginx

ნაწილი 1 · ვებ-სერვერი Nginx

სლაიდი 5

სერვერი გვაქვს. ახლა გვჭირდება პროგრამა, რომელიც ბრაუზერს უპასუხებს.

პრობლემა: სერვერის IP → არაფერი

სლაიდი 6

ბრაუზერში http://164.90.12.34 გახსენი — „This site can't be reached“. წინა ლექციის ბრძანებებით ვხედავთ მიზეზს:

Termius · lms-server
$ sudo ss -tlnpState   Local Address:Port   Process

port 80-ს (HTTP) არავინ უსმენს — მხოლოდ SSH (22). თან ufw 80-ს ბლოკავს.

გვჭირდება ვებ-სერვერი — პროგრამა, რომელიც port 80-ს უსმენს, ბრაუზერის მოთხოვნას იღებს და პასუხად ფაილს აძლევს. GitHub Pages-ზე ამას GitHub აკეთებდა — ახლა ამას ჩვენ ვაწყობთ.

ნაბიჯი 1 · Nginx-ის დაყენება

სლაიდი 7

Nginx („ენჯინ-ექს“) — ერთ-ერთი ყველაზე პოპულარული ვებ-სერვერი: სწრაფი, მსუბუქი, ათასობით მომხმარებელს ერთდროულად უძლებს. ის ფაილებს (HTML, CSS, JS, სურათები) აძლევს ბრაუზერს — და შემდეგ ლექციაზე API-ს წინაც დადგება, როგორც reverse proxy.

Termius · lms-server
$ sudo apt install -y nginx$ systemctl status nginx● nginx.service - A high performance web server and a reverse proxy server     Active: active (running) $ sudo ufw allow 'Nginx HTTP'      # port 80$ sudo ufw statusOpenSSH      ALLOW   Anywhere

ბრაუზერში http://<IP> — Welcome to nginx! 🎉 სერვერმა ინტერნეტს პირველად უპასუხა.

💡

'Nginx HTTP' — ufw-ის მზა პროფილი (port 80). არის 'Nginx HTTPS' (443) და 'Nginx Full' (ორივე) — HTTPS-ს მე-9 ლექციაზე ჩავრთავთ.

systemctl — ფონური პროგრამების მართვა

სლაიდი 8

Nginx სერვისია — პროგრამა, რომელიც ფონზე მუშაობს: terminal-ის დახურვის შემდეგაც და სერვერის გადატვირთვის შემდეგაც. Linux-ში სერვისებს systemd მართავს, ბრძანებით systemctl:

ბრძანება რას აკეთებს
systemctl status nginx მუშაობს? ბოლო ლოგის ხაზები
sudo systemctl stop nginx გაჩერება
sudo systemctl start nginx ჩართვა
sudo systemctl restart nginx გამორთვა და ჩართვა
sudo systemctl reload nginx კონფიგის თავიდან წაკითხვა — მომხმარებლების გათიშვის გარეშე
sudo systemctl enable nginx ავტომატურად ჩაირთოს სერვერის ჩართვისას

apt install nginx სერვისს თვითონ რთავს და enable-საც აკეთებს.

👉

მე-2 ლექციაზე dotnet run-ის პრობლემა ვნახეთ: terminal დახურე — API გაჩერდა. შემდეგ ლექციაზე API-ს ჩვენს საკუთარ systemd სერვისად ვაქცევთ — ზუსტად ისე, როგორც Nginx მუშაობს.

Nginx-ის რუკა: სად რა დევს

სლაიდი 9
Termius · lms-server
/etc/nginx/├── nginx.conf           ← მთავარი კონფიგი (არ ვეხებით)├── sites-available/     ← ყველა საიტის კონფიგი│   ├── default          ← „Welcome to nginx!“│   └── portfolio        ← ჩვენ ვწერთ└── sites-enabled/       ← ჩართული საიტები (symlink-ები)    └── portfolio → ../sites-available/portfolio /var/www/portfolio/      ← საიტის ფაილები/var/log/nginx/          ← access.log · error.log
  • sites-available/ — „თარო“: ყველა საიტის კონფიგი, ჩართულიც და გამორთულიც.
  • sites-enabled/ — რასაც Nginx რეალურად კითხულობს. აქ ფაილები კი არა, symlink-ებია — მალსახმობები sites-available-ის ფაილებზე (როგორც Windows-ის Shortcut).

საიტის გამოსართავად symlink-ს შლი — კონფიგი თაროზე რჩება და ერთი ბრძანებით ისევ ჩაირთვება.

ნაწილი 2 · my-portfolio → სერვერზე

სლაიდი 10

სამი ნაბიჯი: ფაილების ატვირთვა, server block-ის დაწერა, ჩართვა.

ნაბიჯი 2 · ფაილები სერვერზე — rsync

სლაიდი 11

ჯერ სერვერზე საქაღალდე, რომელიც შენს user-ს ეკუთვნის (რომ ატვირთვას sudo არ სჭირდებოდეს):

Termius · lms-server
$ sudo mkdir -p /var/www/portfolio

მერე შენს კომპიუტერზე (WSL), my-portfolio-ს საქაღალდეში:

WSL · ~/my-portfolio
$ rsync -avz --delete --exclude .git ./ lms:/var/www/portfolio/sending incremental file list./index.htmlprojects.html
ოფცია რას ნიშნავს
-a archive: ყველა ფაილი და საქაღალდე, უფლებებით
-v / -z აჩვენე რა მიდის / შეკუმშე გზაში
--delete რაც შენთან წაშალე, სერვერზეც წაიშალოს
--exclude .git Git-ის ისტორია სერვერზე არ გვჭირდება
./ → lms:/var/www/portfolio/ საიდან → სად (lms — ~/.ssh/config-იდან)

rsync SSH-ით მუშაობს და ჭკვიანია: მეორედ მხოლოდ შეცვლილ ფაილებს აგზავნის.

⚠️

./-ის ბოლოს / მნიშვნელოვანია: ./ = საქაღალდის შიგთავსი. --delete-ით ფრთხილად: თუ დანიშნულება შეგეშალა, იქ არსებულ ფაილებს წაშლის.

ნაბიჯი 3 · server block

სლაიდი 12
Termius · lms-server
sites-available/portfolio
server {    listen 80 default_server;    server_name _;     root /var/www/portfolio;    index index.html;     location / {        try_files $uri $uri/ =404;    }}
დირექტივა რას ნიშნავს
listen 80 default_server port 80-ს უსმინე; ეს არის ნაგულისხმევი საიტი ამ port-ზე
server_name _ რომელ დომენზე პასუხობს; _ = ნებისმიერი (დომენი მე-9 ლექციაზე გვექნება)
root სად დევს საიტის ფაილები
index რა გაიხსნას, როცა მისამართი /-ით მთავრდება
location / { … } წესები ყველა მისამართისთვის
try_files $uri $uri/ =404 მოძებნე ასეთი ფაილი → ასეთი საქაღალდე → თუ არ არის, 404

$uri — მოთხოვნილი გზა: /projects.html-ზე Nginx ეძებს /var/www/portfolio/projects.html-ს.

⚠️

Nginx-ის კონფიგში ყოველი ხაზი ;-ით მთავრდება, ბლოკები { }-შია. გამოტოვებული ; — ყველაზე ხშირი შეცდომა. ამიტომ ყოველი ცვლილების შემდეგ — nginx -t.

ნაბიჯი 4 · ჩართვა: symlink → test → reload

სლაიდი 13
Termius · lms-server
$ sudo ln -s /etc/nginx/sites-available/portfolio /etc/nginx/sites-enabled/$ sudo rm /etc/nginx/sites-enabled/default      # „Welcome to nginx“ აღარ გვჭირდება $ sudo nginx -tnginx: the configuration file /etc/nginx/nginx.conf syntax is oknginx: configuration file /etc/nginx/nginx.conf test is successful
  1. ln -s — symlink sites-enabled-ში: საიტი ჩართულია.
  2. default-ის symlink-ს ვშლით (ფაილი sites-available-ში რჩება) — ორი default_server 80-ზე ერთად ვერ იქნება.
  3. nginx -t — კონფიგის შემოწმება ამოქმედებამდე.
  4. reload — ახალი კონფიგი, გათიშვის გარეშე.

ბრაუზერში http://<IP> — შენი portfolio, შენს სერვერზე. 🎉

⚠️

ყოველთვის sudo nginx -t reload/restart-მდე. თუ კონფიგში შეცდომაა და restart გაუშვი, Nginx ვეღარ ჩაირთვება — და ერთ სერვერზე მყოფი ყველა საიტი გაჩერდება. nginx -t გეტყვის ფაილს და ხაზს, სადაც შეცდომაა.

ლოგები: რა გაფუჭდა?

SPA-ს ხაფანგი: refresh → 404

სლაიდი 18

Angular — SPA (Single Page Application): index.html ერთხელ იტვირთება, მერე გვერდებს Angular Router ცვლის ბრაუზერში, სერვერთან ახალი მოთხოვნის გარეშე.

  • აპში ლინკზე „კურსები“ — მისამართი ხდება /courses, გვერდი იხსნება. სერვერი ამაში არ მონაწილეობს. ✅
  • refresh /courses-ზე (ან ლინკი მეგობრისგან) — ბრაუზერი სერვერს ეკითხება GET /courses. Nginx ეძებს ფაილს /var/www/app/courses — არ არის → 404. ❌

გადაწყვეტა — თუ ფაილი არ მოიძებნა, დააბრუნე index.html:

sites-available/app
location / {    try_files $uri $uri/ /index.html;}

ახლა /courses-ზე Nginx აბრუნებს index.html-ს → Angular იტვირთება → Router ხედავს /courses-ს და სწორ კომპონენტს აჩვენებს. ნამდვილი ფაილები (main-HX3K.js, styles.css) ისევ პირდაპირ იძებნება — პირველი პირობით ($uri).

💡

ეს ეხება ყველა SPA-ს: Angular, React, Vue. portfolio-ში კი =404 სწორია — იქ ყოველი გვერდი ნამდვილი ფაილია.

სლაიდი 22
  • 🌐 Nginx — ვებ-სერვერი: port 80-ს უსმენს და ფაილებს აძლევს. ის სერვისია — systemctl status/start/stop/restart/reload.
