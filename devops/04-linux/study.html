Linux — სერვერის ენა

წაიკითხე ლექციის შემდეგ, ან პრეზენტაციასთან ერთად: პრეზენტაციაში დააჭირე P და ეს გვერდი სლაიდებს გაჰყვება. კოდი და AI-ს პრომპტები კოპირდება ერთი დაჭერით.

გამეორება

გავიხსენოთ წინა ლექცია

სლაიდი 1

ლექცია 3 — SSH და Droplet — საკუთარი სერვერი. ახალ თემამდე ვამოწმებთ, რა დაგვამახსოვრდა. ჯერ თვითონ უპასუხე, მერე გახსენი პასუხი. თუ რომელიმე გაგიჭირდა, წინა ლექციის კონსპექტს გადახედე.

✅ შეამოწმე თავი დაფიქრდი, მერე გახსენი პასუხი
SSH-ის რომელი გასაღები რჩება შენთან და რომელი მიდის სერვერზე?
პირადი (id_ed25519) — მხოლოდ შენს კომპიუტერზე, არავის აჩვენო. საჯარო (id_ed25519.pub) — სერვერზე, ~/.ssh/authorized_keys-ში
რატომ ჯობია გასაღები პაროლს?
პაროლს ბოტები უწყვეტად არჩევენ (brute force); გასაღების გამოცნობა პრაქტიკულად შეუძლებელია და მისი „მოპარვა“ სერვერიდან არ შეიძლება — იქ მხოლოდ საჯარო ნაწილია
რატომ ვქმნით ცალკე user-ს და ვკრძალავთ root-ით შესვლას?
root-ს ყველაფრის უფლება აქვს და მის სახელს ყველა ბოტი იცის. ცალკე user-ით ვმუშაობთ, საჭიროებისას sudo-თი — შეცდომაც და შეტევაც ნაკლებ ზიანს აყენებს
რას აკეთებს ufw და რომელი port უნდა გავხსნათ ჩართვამდე?
ufw — firewall: ყველა შემოსულ კავშირს ბლოკავს, გარდა ნებადართულისა. ჩართვამდე აუცილებლად ufw allow OpenSSH (port 22) — თორემ საკუთარ თავს ჩაკეტავ
SSH-ის კონფიგი შეცვალე. რა გააკეთო, ძველ ფანჯარას რომ დახურავ?
ჯერ Termius-ის ახალ tab-ში შეამოწმე, რომ ახალი user-ით შესვლა მუშაობს. ძველი სესია ღია დატოვე — თუ რამე გაფუჭდა, მისით გაასწორებ
Droplet გამოვრთე (Power Off). ფული აღარ ჩამოგეჭრება?
ჩამოგეჭრება — გამორთული Droplet-იც ფასიანია, რადგან რესურსი შენთვისაა დაჯავშნილი. გადახდა მხოლოდ Destroy-ის შემდეგ ჩერდება

საშინაოს განხილვა

სლაიდი 3

წინა ლექციის საშინაო: სერვერის დაცვა. ქვემოთ არის ერთ-ერთი სწორი ამოხსნა. შენი კოდი შეიძლება სხვანაირად იყოს დაწერილი — მთავარია, მოთხოვნები სრულდებოდეს.

მოთხოვნები

  • apt upgrade · 00-hardening.conf: root და პაროლი აკრძალულია → restart ssh (ჯერ Termius-ის ახალ tab-ში შეამოწმეთ!)
  • ufw: მხოლოდ OpenSSH → enable
  • swap 2 GB (/etc/fstab-ითაც) · WSL-ში ~/.ssh/config → ssh lms

ამოხსნა

Termius · lms-server
$ sudo nano /etc/ssh/sshd_config.d/00-hardening.confPermitRootLogin noPasswordAuthentication no $ sudo sshd -t                     # ცარიელი პასუხი = OK$ sudo systemctl restart ssh $ sudo ufw allow OpenSSH$ sudo ufw enable$ sudo ufw statusStatus: active
Termius · lms-server
$ sudo apt update && sudo apt upgrade -y $ sudo fallocate -l 2G /swapfile$ sudo chmod 600 /swapfile$ sudo mkswap /swapfile$ sudo swapon /swapfile$ echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
~/.ssh/config (WSL-ში)
Host lms    HostName 164.90.12.34    User giorgi    IdentityFile ~/.ssh/id_ed25519

ფაილის სახელი 00- იწყება, რადგან SSH ერთ პარამეტრზე პირველ ნანახ მნიშვნელობას იღებს, ფაილებს კი ანბანით კითხულობს — 00 ყველაზე ადრე იკითხება.

დღის თემა: Linux — სერვერის ენა

სლაიდი 4

სერვერს ეკრანი, მაუსი და „Start“ ღილაკი არ აქვს — მხოლოდ შავი ფანჯარა და ტერმინალი. წინა ლექციაზე სერვერი შევქმენით — და მასზე ყველაფერს ბრძანებებით გააკეთებ: ფაილების ატვირთვას, პროგრამების დაყენებას, ლოგების კითხვას. დღეს ამ ენას ვსწავლობთ — პირდაპირ სერვერზე, Termius-ში.

ლექციის ბოლოს შეძლებ:

  • Linux-ის ფაილურ სისტემაში ორიენტირება: /, ~, /etc, /var/log, /var/www
  • ფაილებთან მუშაობა: ls, cd, mkdir, cp, mv, rm, cat, tail -f, nano
  • sudo და apt-ით პროგრამების დაყენება
  • უფლებების წაკითხვა და შეცვლა: ls -l, chmod 644/755/600, chown
  • პროცესების და port-ების ნახვა: ps, htop, kill, ss -tlnp

პრობლემა: სერვერზე არ არის ეკრანი და მაუსი

სლაიდი 6

Windows-ში ფანჯრებით, ღილაკებით და მაუსით მუშაობ. სერვერზე ამის არცერთი არ არის: გრაფიკული ინტერფეისი მეხსიერებას ჭამს და დამატებითი რისკია. დაგხვდება მხოლოდ ტერმინალი:

სერვერი

რატომ Linux და არა Windows სერვერებზე:

  • 🆓 უფასოა — ლიცენზია არც ერთ სერვერზე არ სჭირდება;
  • 🪶 მსუბუქია — 1 GB RAM-იან ყველაზე იაფ სერვერზეც კომფორტულად მუშაობს;
  • 🏗️ სტანდარტია — ინტერნეტის სერვერების აბსოლუტური უმრავლესობა, Docker-ის კონტეინერები და Cloud-ები Linux-ზე დგას.

Linux — ოპერაციული სისტემის ბირთვი. მის გარშემო აწყობილ სრულ სისტემას დისტრიბუტივი ჰქვია: Ubuntu, Debian, Fedora, Alpine... ჩვენ ვიყენებთ Ubuntu 24.04 LTS-ს — LTS ნიშნავს Long Term Support: განახლებები წლების განმავლობაში. სწორედ ის გვიდგას ჩვენს Droplet-ზე.

ფაილური სისტემა — ერთი ხე /-დან

სლაიდი 8

Windows-ში დისკები ასოებითაა (C:\, D:\). Linux-ში ერთი ხეა, რომელიც /-დან (root) იწყება — ყველაფერი, დისკებიც, მის შიგნითაა.

tree
/                    ← root, ყველაფრის დასაწყისი├── home/│   └── giorgi/      ← ~ (შენი სახლი)├── etc/             ← კონფიგურაცია│   └── nginx/├── var/│   ├── log/         ← ლოგები│   └── www/         ← საიტები├── usr/bin/         ← პროგრამები├── tmp/             ← დროებითი
საქაღალდე რა არის როდის დაგჭირდება
/home/<user> = ~ შენი ფაილები ყოველთვის
/etc პროგრამების კონფიგურაცია Nginx, SSH-ის პარამეტრები
/var/log ლოგები „რა გაფუჭდა?“
/var/www საიტების ფაილები portfolio სერვერზე
/usr/bin დაყენებული პროგრამები —
⚠️

Linux-ში დიდი და პატარა ასოები განსხვავდება: Index.html და index.html ორი სხვადასხვა ფაილია. წინა ლექციაზე GitHub Pages-ზე სწორედ ამის გამო „ქრებოდა“ CSS.

ნავიგაცია: pwd · ls · cd

  • pwd (print working directory) — სად ვარ.
  • ls — რა არის მიმდინარე საქაღალდეში. -l — დეტალურად (უფლებები, მფლობელი, ზომა), -a — ფარული ფაილებიც (რომელთა სახელი .-ით იწყება, მაგ. .bashrc, .git, .env).
  • cd <გზა> — გადასვლა.
Termius · giorgi@lms-server
$ cd /var/log      # აბსოლუტური გზა — ფესვიდან$ cd ..            # ერთით ზემოთ → /var$ cd www           # ფარდობითი — აქედან → /var/www$ cd ~             # სახლში (ან უბრალოდ: cd)

გზის ორი სახე: /-ით დაწყებული — აბსოლუტური, ფესვიდან ითვლება და ყველგან ერთნაირად მუშაობს. დანარჩენი — ფარდობითი, მიმდინარე საქაღალდიდან. . — მიმდინარე საქაღალდე, .. — ერთით ზემოთ.

ბრძანება რას აკეთებს

⚠️

Linux-ში სანაგვე ყუთი არ არის: rm ფაილს სამუდამოდ შლის, შეკითხვის გარეშე. -f (force) კიდევ უფრო „ჩუმად“ შლის. ინტერნეტში ნანახი sudo rm -rf / მთელ სისტემას შლის — არასოდეს გაუშვა ბრძანება, რომლის მნიშვნელობაც არ იცი.

კითხვა და რედაქტირება: cat · tail -f · nano

სლაიდი 11

წაკითხვა:

Termius · giorgi@lms-server
$ cat index.html          # მთლიანად ეკრანზე$ less /var/log/syslog    # გვერდებად: ↑↓, Space, / ძებნა, q — გასვლა$ head -n 5 app.log       # პირველი 5 ხაზი$ tail -n 20 app.log      # ბოლო 20 ხაზი

tail -f სერვერზე ერთ-ერთი ყველაზე ხშირი ბრძანებაა: გახსნი ლოგს, ბრაუზერში საიტს განაახლებ — და ხედავ, რა მოხდა იმ წამს. ეს მონიტორინგის უმარტივესი ფორმაა.

რედაქტირება — nano: ტერმინალის მარტივი ტექსტური რედაქტორი. ქვედა ზოლში წერია მთავარი ღილაკები (^ = Ctrl).

nano-ში რას აკეთებს
Ctrl + O → Enter შენახვა
Ctrl + X გასვლა (თუ არ შეინახე — გკითხავს)
Ctrl + W ძებნა
Ctrl + K / Ctrl + U ხაზის ამოჭრა / ჩასმა
👉

სერვერზე კონფიგურაციის ფაილებს (/etc/nginx/...) სწორედ nano-თი შეცვლი. სხვა პოპულარული რედაქტორია vim — ძლიერია, მაგრამ თავიდან რთული. თუ შემთხვევით გაიხსნა: Esc, მერე :q! და Enter.

user-ები, root და sudo

სლაიდი 14

Linux-ში ყველა მოქმედებას რომელიმე user აკეთებს (whoami — ვინ ვარ). განსაკუთრებული user-ია root — ადმინისტრატორი, რომელსაც ყველაფრის უფლება აქვს, მათ შორის სისტემის გაფუჭების.

ამიტომ ჩვეულებრივ user-ით ვმუშაობთ, და მხოლოდ საჭირო ბრძანებას ვუშვებთ root-ის უფლებით — sudo-თი (super user do). პირველად ის შენს პაროლს ითხოვს (რამდენიმე წუთი იმახსოვრებს). პაროლის აკრეფისას ეკრანზე არაფერი ჩანს — ეს ნორმალურია.

Termius · giorgi@lms-server
$ apt install treeE: Could not open lock file ... Permission deniedE: Unable to acquire the dpkg frontend lock, are you root? $ sudo apt update                # პაკეტების სიის განახლება

apt — Ubuntu-ს პროგრამების „მაღაზია“. apt update პაკეტების სიას აახლებს, apt install — აყენებს, apt upgrade — დაყენებულებს აახლებს, apt remove — შლის. სერვერზე Nginx-ს, .NET-ს და Docker-ს სწორედ ასე დავაყენებთ.

⚠️

ბრძანება „Permission denied“-ით ჩავარდა? ჯერ იფიქრე, რატომ სჭირდება root — და მხოლოდ მერე დაუმატე sudo. ყველაფრის sudo-თი გაშვება ცუდი ჩვევაა.

უფლებები: ვის რისი უფლება აქვს

სლაიდი 15

ls -l ყოველ ფაილზე აჩვენებს 10 სიმბოლოს:

Termius · giorgi@lms-server
$ ls -l index.html
  • პირველი სიმბოლო — ტიპი: - ფაილი, d საქაღალდე.
  • შემდეგ სამ-სამად: მფლობელი (rw-), ჯგუფი (r--), სხვები (r--).
  • მერე — მფლობელი user და ჯგუფი (giorgi giorgi).
ასო რიცხვი ფაილზე საქაღალდეზე
r 4 წაკითხვა შიგთავსის სიის ნახვა
w 2 ჩაწერა შიგნით შექმნა/წაშლა
x 1 გაშვება შესვლა (cd)

რიცხვი = ჯამი: rw- = 4+2 = 6, r-- = 4, rwx = 7. ასე -rw-r--r-- = 644.

რიცხვი ვისთვის მაგალითი
644 მე ვწერ, ყველა კითხულობს HTML, CSS, კონფიგი
755 მე ვწერ, ყველა შედის/უშვებს საქაღალდე, სკრიპტი
600 მხოლოდ მე SSH-ის პირადი გასაღები, .env
Termius · giorgi@lms-server
$ chmod 600 secret.txt           # უფლებები რიცხვით$ chmod +x deploy.sh             # გაშვების უფლება დაამატე
👉

SSH-ის გასაღებები (~/.ssh) უნდა იყოს 600 — თუ სხვებსაც შეუძლიათ მისი წაკითხვა, SSH მის გამოყენებაზე უარს იტყვის. ხოლო როცა Nginx საიტს ვერ აჩვენებს, ხშირად მიზეზი სწორედ უფლებებია.

პროცესები და port-ები: რა მუშაობს ახლა?

სლაიდი 16

პროცესი — გაშვებული პროგრამა. ყველას აქვს უნიკალური ნომერი — PID.

Termius · giorgi@lms-server
$ ps aux | grep dotnet     # ყველა პროცესიდან — მხოლოდ dotnetgiorgi  2481  3.1  2.4 ... dotnet run $ htop                     # „Task Manager“ ტერმინალში: CPU, RAM; q — გასვლა $ kill 2481                # PID 2481-ის გაჩერება

port — „კარი“, რომელსაც პროგრამა ქსელიდან მოთხოვნებისთვის უსმენს. API-ს dotnet run რომ გაუშვი, ის port 5080-ს უსმენდა. სტანდარტული port-ები: 22 — SSH, 80 — HTTP, 443 — HTTPS, 5432 — PostgreSQL.

Termius · giorgi@lms-server
$ sudo ss -tlnpState   Local Address:Port   ProcessLISTEN  0.0.0.0:22           sshdLISTEN  127.0.0.1:5080       dotnet

ss -tlnp — ვინ რომელ port-ს უსმენს (t TCP, l listening, n რიცხვებით, p პროცესი). 0.0.0.0 — ყველასთვის ღიაა; 127.0.0.1 — მხოლოდ ამავე კომპიუტერიდან.

| (pipe) — ერთი ბრძანების შედეგი მეორეს გადაეცემა: ps aux | grep dotnet — ყველა პროცესიდან grep მხოლოდ dotnet-იან ხაზებს ტოვებს. grep ლოგებშიც გამოგადგება: grep ERROR app.log.

👉

„საიტი არ იხსნება“ — DevOps-ის პირველი კითხვა: პროცესი გაშვებულია? (ps) და port-ს უსმენს? (ss -tlnp). ეს ორი ბრძანება პრობლემების ნახევარს პოულობს.

ვაკეთებთ ერთად: my-portfolio სერვერზე

სლაიდი 17

ვამზადებთ საიტის საქაღალდეს სერვერზე:

Termius · giorgi@lms-server
$ cd ~$ git clone https://github.com/giorgi/my-portfolio.git$ sudo mkdir -p /var/www/portfolio$ sudo cp -r my-portfolio/* /var/www/portfolio/$ ls -l /var/www/portfolio-rw-r--r-- 1 root root 1520 index.html

/var/www root-ს ეკუთვნის, ამიტომ საქაღალდის შექმნას და კოპირებას sudo სჭირდება — და ფაილებიც root-ის გახდა. ჩვენ გვინდა, რომ შემდეგში ფაილები sudo-ს გარეშე განვაახლოთ:

Termius · giorgi@lms-server
$ sudo chown -R $USER:$USER /var/www/portfolio$ ls -l /var/www/portfolio

$USER — ცვლადი, რომელშიც შენი user-ის სახელია. -R — რეკურსიულად, ყველა შიგნით არსებულ ფაილზე.

💡

git Ubuntu-ს სერვერზე უკვე დაყენებულია. თუ არა — sudo apt install -y git.

კლასში დავალება: საიტის საქაღალდე სერვერზე

სლაიდი 19

დავალება · my-portfolio „სერვერის სტილში“

ნაბიჯები

  • cd ~ → git clone https://github.com/<username>/my-portfolio.git → cd my-portfolio → ls -la
  • sudo mkdir -p /var/www/portfolio → sudo cp -r ~/my-portfolio/* /var/www/portfolio/
  • ls -l /var/www/portfolio — ვისია ფაილები? → sudo chown -R $USER:$USER /var/www/portfolio → ისევ ls -l
  • nano /var/www/portfolio/index.html — სათაურში დაამატეთ „(Linux-იდან)“ → შენახვა Ctrl+O, გასვლა Ctrl+X → cat-ით შეამოწმეთ
  • sudo apt update && sudo apt install -y tree htop → tree /var/www

✓ მზადაა, როცა

tree /var/www აჩვენებს portfolio-ს ფაილებით, ls -l-ში მფლობელი თქვენი user-ია, index.html-ში ცვლილება ჩანს

⭐ ბონუსი

  • htop გახსენით → იპოვეთ პროცესი bash → გამოდით q-თი. მეორე ტერმინალში sleep 1000 → პირველიდან იპოვეთ მისი PID ps aux | grep sleep-ით და kill-ით გააჩერეთ

შეამოწმე, რა დაგამახსოვრდა

სლაიდი 20

ეს კითხვები შემდეგი ლექციის დასაწყისშიც დაისმება.

✅ შეამოწმე თავი დაფიქრდი, მერე გახსენი პასუხი
რას ნიშნავს /, ~ და ..?
/ — ფაილური სისტემის ფესვი (root), ყველაფერი აქედან იწყება; ~ — შენი სახლის საქაღალდე (/home/giorgi); .. — ერთი საქაღალდით ზემოთ
სად ინახება Linux-ზე პროგრამების კონფიგურაცია, ლოგები და საიტები?
კონფიგურაცია — /etc, ლოგები — /var/log, საიტები — ჩვეულებრივ /var/www
რატომ არის rm -r სახიფათო?
Linux-ში სანაგვე ყუთი არ არის: წაშლილი ფაილი სამუდამოდ ქრება. rm -r საქაღალდეს მთელი შიგთავსით შლის
რას ნიშნავს -rw-r--r-- და რომელი რიცხვია?
მფლობელი: წაკითხვა+ჩაწერა (6), ჯგუფი: წაკითხვა (4), დანარჩენები: წაკითხვა (4) → 644
რისთვის ვიყენებთ sudo-ს?
ბრძანების ადმინისტრატორის (root) უფლებით გასაშვებად — მაგ. sudo apt install, ან ფაილის შეცვლა /etc-ში
როგორ ნახავ, რომელი პროგრამა უსმენს port 5080-ს?
sudo ss -tlnp — ჩამოთვლის port-ებს და პროცესებს, რომლებიც მათ უსმენენ (| grep 5080 — გასაფილტრად)
