გავიხსენოთ წინა ლექცია

სლაიდი 1

ლექცია 3 — Linux — სერვერის ენა. ახალ თემამდე ვამოწმებთ, რა დაგვამახსოვრდა. ჯერ თვითონ უპასუხე, მერე გახსენი პასუხი. თუ რომელიმე გაგიჭირდა, წინა ლექციის კონსპექტს გადახედე.

✅ შეამოწმე თავი დაფიქრდი, მერე გახსენი პასუხი
რას ნიშნავს /, ~ და ..?
/ — ფაილური სისტემის ფესვი (root), ყველაფერი აქედან იწყება; ~ — შენი სახლის საქაღალდე (/home/giorgi); .. — ერთი საქაღალდით ზემოთ
სად ინახება Linux-ზე პროგრამების კონფიგურაცია, ლოგები და საიტები?
კონფიგურაცია — /etc, ლოგები — /var/log, საიტები — ჩვეულებრივ /var/www
რატომ არის rm -r სახიფათო?
Linux-ში სანაგვე ყუთი არ არის: წაშლილი ფაილი სამუდამოდ ქრება. rm -r საქაღალდეს მთელი შიგთავსით შლის
რას ნიშნავს -rw-r--r-- და რომელი რიცხვია?
მფლობელი: წაკითხვა+ჩაწერა (6), ჯგუფი: წაკითხვა (4), დანარჩენები: წაკითხვა (4) → 644
რისთვის ვიყენებთ sudo-ს?
ბრძანების ადმინისტრატორის (root) უფლებით გასაშვებად — მაგ. sudo apt install, ან ფაილის შეცვლა /etc-ში
როგორ ნახავ, რომელი პროგრამა უსმენს port 5080-ს?
sudo ss -tlnp — ჩამოთვლის port-ებს და პროცესებს, რომლებიც მათ უსმენენ (| grep 5080 — გასაფილტრად)

საშინაოს განხილვა

სლაიდი 3

წინა ლექციის საშინაო: Linux-ის ქვესტი და DigitalOcean ანგარიში. ქვემოთ არის ერთ-ერთი სწორი ამოხსნა. შენი კოდი შეიძლება სხვანაირად იყოს დაწერილი — მთავარია, მოთხოვნები სრულდებოდეს.

მოთხოვნები

  • ~/linux-quest-ში: logs/, scripts/, notes/; notes/commands.md — 10 ბრძანება თქვენი ახსნით
  • scripts/hello.sh (echo "გამარჯობა, $USER") → გასაშვები → ./scripts/hello.sh
  • logs/app.log — 3 ხაზი, ერთში ERROR → grep-ით მხოლოდ ის
  • დარეგისტრირდით DigitalOcean-ზე (ბარათი/PayPal; შეამოწმეთ GitHub Student Pack)

ამოხსნა

Ubuntu
$ mkdir -p ~/linux-quest/{logs,scripts,notes}$ cd ~/linux-quest$ nano notes/commands.md $ echo 'echo "გამარჯობა, $USER"' > scripts/hello.sh$ chmod +x scripts/hello.sh        # ან: chmod 755$ ./scripts/hello.shგამარჯობა, giorgi $ echo "INFO app started"   >  logs/app.log$ echo "ERROR db not found" >> logs/app.log$ echo "INFO request done"  >> logs/app.log$ grep ERROR logs/app.log

> ფაილს თავიდან წერს, >> — ბოლოში ამატებს. {logs,scripts,notes} — სამი საქაღალდე ერთი ბრძანებით.

  • Termius-ით სერვერთან კავშირი და ~/.ssh/config WSL-ის ბრძანებებისთვის: rsync … lms:

1 · SSH

ნაწილი 1 · SSH

სლაიდი 5

ტერმინალი სხვა ქვეყანაში მდგარ კომპიუტერზე — დაშიფრული და პაროლის გარეშე.

პრობლემა: სერვერი ფრანკფურტშია — როგორ „დავჯდე“ მასთან?

სლაიდი 6

სერვერი მონაცემთა ცენტრშია, სხვა ქვეყანაში. ფიზიკურად მასთან ვერ მიხვალ — და არც გჭირდება. SSH (Secure Shell) შენს ტერმინალს სერვერს აკავშირებს: შენ კრეფ, ბრძანება სერვერზე სრულდება, შედეგი შენთან ჩანს. მთელი კავშირი დაშიფრულია.

WSL
$ ssh giorgi@164.90.12.34

პაროლის პრობლემა. ინტერნეტში ბოტები უწყვეტად ამოწმებენ ყველა IP მისამართს და SSH-ზე პაროლებს არჩევენ (admin/admin, root/123456...). ახალი სერვერის ლოგში ასეთი ხაზები რამდენიმე წუთში ჩნდება:

journalctl -u ssh
Invalid user admin from 45.x.x.xInvalid user test from 103.x.x.xFailed password for root from 194.x.x.x

გამოსავალი — პაროლის ნაცვლად SSH გასაღები.

SSH გასაღები: საკეტი და გასაღები

სლაიდი 7

SSH გასაღები წყვილია — ორი ფაილი, რომლებიც მათემატიკურად ერთმანეთს ემთხვევა:

ფაილი ანალოგია სად ცხოვრობს
~/.ssh/id_ed25519.pub — საჯარო 🔒 საკეტი სერვერზე (~/.ssh/authorized_keys), GitHub-ზე — ნებისმიერ ადგილას, სადაც შესვლა გინდა
~/.ssh/id_ed25519 — პირადი 🔑 გასაღები მხოლოდ შენს კომპიუტერზე

შესვლისას სერვერი გამოწვევას აგზავნის, რომლის სწორად „გახსნაც“ მხოლოდ შესაბამის პირად გასაღებს შეუძლია. თავად პირადი გასაღები ქსელში არასოდეს მიდის.

საჯარო ნაწილის მოპარვა საშიში არ არის — საკეტით კარს ვერ გააღებ. პირადი კი პაროლზე მნიშვნელოვანია: ვისაც ის აქვს, ის შედის შენს ყველა სერვერზე.

⚠️

პირადი გასაღები არ გაუგზავნო არავის, არ ჩასვა ჩატში და არ ატვირთო GitHub-ზე. მისი უფლება უნდა იყოს 600 (მხოლოდ შენ) — წინა ლექციის chmod სწორედ აქ გამოგვადგება.

ნაბიჯი 1 · გასაღების შექმნა

სლაიდი 8

WSL-ში (ერთხელ — ეს გასაღები ყველა სერვერზე და GitHub-ზეც გამოგადგება):

WSL
$ ssh-keygen -t ed25519 -C "giorgi@mail.ge"Generating public/private ed25519 key pair.Enter file in which to save the key (/home/giorgi/.ssh/id_ed25519):   ← EnterEnter passphrase (empty for no passphrase):                           ← სურვილისამებრYour identification has been saved in /home/giorgi/.ssh/id_ed25519
  • -t ed25519 — ალგორითმი: თანამედროვე, მოკლე და ძლიერი (ძველი ალტერნატივაა RSA).
  • -C — კომენტარი, რომ მოგვიანებით იცოდე, ვისი გასაღებია.
  • passphrase — პირადი გასაღების პაროლი. თუ ლეპტოპი მოიპარეს, მის გარეშე გასაღები უსარგებლოა. სწავლისას შეგიძლია ცარიელი დატოვო.
WSL
$ ls -l ~/.ssh-rw------- 1 giorgi giorgi 411 id_ed25519        ← 600: მხოლოდ შენ-rw-r--r-- 1 giorgi giorgi  98 id_ed25519.pub    ← 644: საჯარო $ cat ~/.ssh/id_ed25519.pub

.pub-ის ეს ერთი ხაზი არის ის, რასაც სერვერს მივცემთ.

⚠️

ფასი საათობრივად ითვლება, თვეში რამდენიმე დოლარამდე. Droplet-ის გამორთვა (Power Off) გადახდას არ აჩერებს — რესურსი შენთვისაა დაჯავშნილი. გადახდა მხოლოდ Destroy-ის შემდეგ ჩერდება. ანგარიშზე დააყენე Billing alert.

👉

თუ ოდესმე SSH-ით ვეღარ შედიხარ (მაგ. firewall-ით საკუთარი თავი ჩაკეტე), Droplet-ის გვერდზე არის Console — ტერმინალი პირდაპირ ბრაუზერში. ეს სათადარიგო კარია.

ნაბიჯი 3 · Termius — სერვერთან კავშირი

სლაიდი 11

Termius — SSH კლიენტი: სერვერების სია, შენახული გასაღებები, რამდენიმე tab ერთად და ჩაშენებული SFTP (ფაილების დათვალიერება). შიგნით ის ზუსტად იმას აკეთებს, რასაც ტერმინალში ssh root@164.90.12.34 — უბრალოდ IP-ს და პარამეტრებს ყოველ ჯერზე აღარ კრეფ.

1. გასაღების შემოტანა. გასაღები უკვე შევქმენით WSL-ში (ნაბიჯი 1). Termius-ს იგივე გასაღებს ვაძლევთ — ახალს არ ვქმნით, რომ WSL-იდანაც და Termius-იდანაც ერთი გასაღებით შევიდეთ:

WSL
$ cat ~/.ssh/id_ed25519-----BEGIN OPENSSH PRIVATE KEY-----...

Termius → Keychain → Key → Import (ან New Key) → მთელი ტექსტი, -----BEGIN-იდან -----END-ის ჩათვლით, ჩასვი Private key ველში.

2. Host. Hosts → New Host:

ველი მნიშვნელობა
Label lms-server
Address Droplet-ის IP
Username root (ცალკე user-ს მოგვიანებით შევქმნით)
Key ის, რაც ახლა შემოვიტანეთ

3. Connect. პირველად Termius იტყვის, რომ სერვერის „თითის ანაბეჭდი“ (fingerprint) უცნობია: ამ სერვერს პირველად ვხედავთ — Continue. Termius მას იმახსოვრებს და თუ შემდეგში შეიცვლება, გაგაფრთხილებს (შეიძლება ვინმე შუაში ჩაჯდა).

⚠️

გასაღების ტექსტი მხოლოდ Termius-ის ველში ჩასვი — არა ჩატში, არა სხვაგან. ის პაროლზე მნიშვნელოვანია.

💡

გასაღებს Termius-ში არ ვქმნით: მაშინ ის მხოლოდ Termius-ში იცხოვრებდა, WSL-ის ბრძანებები კი (rsync, scp, ssh-copy-id, deploy.sh) — მომდევნო ლექციებზე — ვერ შევიდოდნენ.

root-ის ნაცვლად ვქმნით ჩვეულებრივ user-ს, რომელსაც საჭიროებისას sudo შეუძლია:

Termius · root@lms-server
# adduser giorgi                   # ახალი user — ითხოვს პაროლს, დანარჩენზე Enter# usermod -aG sudo giorgi          # -aG: დაამატე ჯგუფში sudo

ბოლო ბრძანება root-ის ~/.ssh საქაღალდეს (შენი საჯარო გასაღებით) ახალ user-ს უკოპირებს და მფლობელად მას ნიშნავს — ასე giorgi-თიც გასაღებით შეხვალ.

Termius-ში შექმენი მეორე Host — იგივე IP და გასაღები, ოღონდ Username: giorgi (Label: lms-server). ძველი, root-ის Host შეგიძლია წაშალო, როცა ყველაფერი შემოწმდება. ახალი Host → Connect:

Termius · giorgi@lms-server
giorgi@lms-server:~$ sudo whoami[sudo] password for giorgi:

adduser-ში მითითებული პაროლი შესვლისთვის არ გამოიყენება — ის მხოლოდ sudo-სთვისაა. შესვლა ისევ გასაღებით ხდება.

ნაბიჯი 6 · SSH-ის კონფიგი: root-ით და პაროლით — აკრძალულია

სლაიდი 16

SSH სერვერის (sshd) პარამეტრები /etc/ssh/-შია. მთავარ ფაილს არ ვეხებით — ვქმნით საკუთარს sshd_config.d საქაღალდეში:

Termius · giorgi@lms-server
00-hardening.conf
PermitRootLogin noPasswordAuthentication no
  • PermitRootLogin no — root-ით შესვლა აკრძალულია (მის სახელს ყველა ბოტი იცის).
  • PasswordAuthentication no — პაროლით შესვლა აკრძალულია, მხოლოდ გასაღებით.
Termius · giorgi@lms-server
$ sudo sshd -t                  # სინტაქსის შემოწმება: ცარიელი პასუხი = OK$ sudo systemctl restart ssh    # ცვლილების ამოქმედება$ sudo sshd -T | grep -E "permitrootlogin|passwordauthentication"permitrootlogin no

sshd -T აჩვენებს საბოლოო პარამეტრებს, რომლითაც SSH რეალურად მუშაობს.

რატომ 00-? SSH ერთ პარამეტრზე პირველ ნანახ მნიშვნელობას იღებს, sshd_config.d-ის ფაილებს კი ანბანის მიხედვით კითხულობს. DigitalOcean-ს იქ შეიძლება უკვე ედოს 50-cloud-init.conf — 00 მასზე ადრე იკითხება.

⚠️

მიმდინარე Termius-ის tab არ დახურო, სანამ ახალ tab-ში არ შეამოწმებ, რომ giorgi-ს Host-ით შესვლა მუშაობს. თუ რამე შეგეშალა, ძველი სესიით გაასწორებ. თუ მაინც ჩაიკეტე — Droplet-ის Console ბრაუზერში.

ნაბიჯი 7 · firewall: ufw

სლაიდი 17

firewall — „დაცვა კარებთან“: წყვეტს, რომელ port-ზე შეიძლება ინტერნეტიდან შემოსვლა. Ubuntu-ში მისი მარტივი ინტერფეისია ufw (uncomplicated firewall). ჩართვის შემდეგ ყველა შემოსული კავშირი იბლოკება, გარდა იმისა, რაც ცალკე დაუშვი.

Termius · giorgi@lms-server
$ sudo ufw allow OpenSSH        # port 22 — ჯერ ეს!$ sudo ufw enableCommand may disrupt existing ssh connections. Proceed with operation (y|n)? yFirewall is active and enabled on system startup $ sudo ufw statusStatus: activeTo          Action   From

შემდეგ ლექციაზე, Nginx-ის დაყენებისას, დავამატებთ port 80-ს (HTTP), მოგვიანებით — 443-ს (HTTPS). ბაზის port (5432) კი არასოდეს გაიხსნება ინტერნეტისთვის.

⚠️

ufw enable-მდე აუცილებლად ufw allow OpenSSH — სხვა შემთხვევაში firewall შენს SSH კავშირსაც დაბლოკავს და სერვერზე ვეღარ შეხვალ (დაგრჩება მხოლოდ Droplet Console).

ნაბიჯი 8 · განახლება და swap

სლაიდი 18

განახლებები — ახალ სერვერზე პირველივე დღეს ვაყენებთ (უსაფრთხოების პატჩები):

Termius · giorgi@lms-server

&& — მეორე ბრძანება მხოლოდ მაშინ სრულდება, თუ პირველი წარმატებით დასრულდა.

swap — დისკზე გამოყოფილი ადგილი, რომელსაც სისტემა RAM-ად იყენებს, როცა ნამდვილი RAM ივსება. დისკი RAM-ზე ბევრად ნელია, მაგრამ swap-ის გარეშე მეხსიერების ამოწურვისას Linux პროცესებს კლავს (OOM killer). ჩვენს 1 GB-იან სერვერზე მოგვიანებით .NET-ის build-იც მოგვიწევს და ბაზაც — swap დაგვაზღვევს.

Termius · giorgi@lms-server
$ sudo fallocate -l 2G /swapfile                          # 2 GB ფაილი$ sudo chmod 600 /swapfile                                # მხოლოდ root$ sudo mkswap /swapfile                                   # swap-ად მომზადება$ sudo swapon /swapfile                                   # ჩართვა$ echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab   # reboot-ის შემდეგაც $ free -h       total   used   freeMem:   961Mi  320Mi  410Mi

/etc/fstab — ფაილი, რომელსაც სისტემა ჩართვისას კითხულობს. tee -a ფაილის ბოლოს ამატებს ხაზს root-ის უფლებით (sudo echo ... >> file არ იმუშავებს — გადამისამართებას შენი user აკეთებს და არა sudo).

ნაბიჯი 9 · ~/.ssh/config — WSL-ის ბრძანებებისთვის

სლაიდი 19

სერვერზე ჩვენ Termius-ით ვმუშაობთ. მაგრამ შემდეგ ლექციებზე შენი კომპიუტერიდან (WSL) გავუშვებთ ბრძანებებს, რომლებიც სერვერს თვითონ უკავშირდება: rsync (ფაილების ატვირთვა), scp, ssh-copy-id, deploy.sh. Termius-ის Host-ებს ისინი ვერ ხედავენ — მათ WSL-ის „მისამართების წიგნი“ სჭირდებათ, ~/.ssh/config:

~/.ssh/config
Host lms    HostName 164.90.12.34    User giorgi    IdentityFile ~/.ssh/id_ed25519

შემოწმება — WSL-იდან:

WSL
$ ssh lms

lms — შენ მიერ მოფიქრებული მოკლე სახელი. ის იმუშავებს ყველა SSH-ზე დაფუძნებულ ბრძანებაში — შემდეგ ლექციაზე ფაილებს ასე ავტვირთავთ: rsync -avz ./ lms:/var/www/portfolio/.
