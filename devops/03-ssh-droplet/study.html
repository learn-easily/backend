დღის თემა

დღის თემა: საკუთარი სერვერი — SSH, Droplet და Termius

სლაიდი 4

API-ს სჭირდება კომპიუტერი, რომელიც 24/7 ჩართულია და ინტერნეტიდან მისაწვდომია. დღეს ასეთს ვქირაობთ DigitalOcean-ზე — Droplet-ს — და ვუკავშირდებით მას Termius-ით, პაროლის გარეშე, გასაღებით. სერვერს ეკრანი და მაუსი არ აქვს — მხოლოდ ტერმინალი. ამიტომ Linux-ის ბრძანებებს პირდაპირ ამ სერვერზე ვსწავლობთ: სად ვარ, რა არის აქ, როგორ შევცვალო.

ლექციის ბოლოს შეძლებ:

  • SSH გასაღებების წყვილის შექმნა და ახსნა: public vs private
  • Droplet-ის შექმნა: region, Ubuntu 24.04, ზომა, SSH key
  • Termius-ით სერვერთან დაკავშირება: გასაღების შემოტანა, Host, Connect
  • Linux-ის ფაილურ სისტემაში ორიენტირება: /, ~, /etc, /var/log
  • ფაილებთან მუშაობა სერვერზე: ls, cd, mkdir, cp, mv, rm, cat, tail -f, grep, nano

1 · SSH

ნაწილი 1 · SSH

სლაიდი 5

ტერმინალი სხვა ქვეყანაში მდგარ კომპიუტერზე — დაშიფრული და პაროლის გარეშე.

პრობლემა: სერვერი ფრანკფურტშია — როგორ „დავჯდე“ მასთან?

სლაიდი 6

წინა ლექციაზე ვნახეთ, რომ API GitHub Pages-ზე ვერ გაეშვება — მას საკუთარი სერვერი სჭირდება. სერვერი მონაცემთა ცენტრშია, სხვა ქვეყანაში. ფიზიკურად მასთან ვერ მიხვალ — და არც გჭირდება. SSH (Secure Shell) შენს ტერმინალს სერვერს აკავშირებს: შენ კრეფ, ბრძანება სერვერზე სრულდება, შედეგი შენთან ჩანს. მთელი კავშირი დაშიფრულია.

შენი კომპიუტერი
$ ssh root@164.90.12.34

პაროლის პრობლემა. ინტერნეტში ბოტები უწყვეტად ამოწმებენ ყველა IP მისამართს და SSH-ზე პაროლებს არჩევენ (admin/admin, root/123456...). ახალი სერვერის ლოგში ასეთი ხაზები რამდენიმე წუთში ჩნდება:

/var/log/auth.log
Invalid user admin from 45.x.x.xInvalid user test from 103.x.x.xFailed password for root from 194.x.x.x

გამოსავალი — პაროლის ნაცვლად SSH გასაღები.

SSH გასაღები: საკეტი და გასაღები

სლაიდი 7

SSH გასაღები წყვილია — ორი ფაილი, რომლებიც მათემატიკურად ერთმანეთს ემთხვევა:

ფაილი ანალოგია სად ცხოვრობს
~/.ssh/id_ed25519.pub — საჯარო 🔒 საკეტი სერვერზე (~/.ssh/authorized_keys), GitHub-ზე — ნებისმიერ ადგილას, სადაც შესვლა გინდა
~/.ssh/id_ed25519 — პირადი 🔑 გასაღები მხოლოდ შენს კომპიუტერზე

შესვლისას სერვერი გამოწვევას აგზავნის, რომლის სწორად „გახსნაც“ მხოლოდ შესაბამის პირად გასაღებს შეუძლია. თავად პირადი გასაღები ქსელში არასოდეს მიდის.

საჯარო ნაწილის მოპარვა საშიში არ არის — საკეტით კარს ვერ გააღებ. პირადი კი პაროლზე მნიშვნელოვანია: ვისაც ის აქვს, ის შედის შენს ყველა სერვერზე.

⚠️

პირადი გასაღები არ გაუგზავნო არავის, არ ჩასვა ჩატში და არ ატვირთო GitHub-ზე.

ნაბიჯი 1 · გასაღების შექმნა

სლაიდი 8

გასაღებს შენს კომპიუტერზე ვქმნით — WSL-ში (macOS-ზე — Terminal-ში). ეს ორი ბრძანებაა; Linux-ს დღესვე ნამდვილ სერვერზე ვისწავლით. გასაღები ერთხელ იქმნება — ყველა სერვერზე და GitHub-ზეც გამოგადგება:

WSL
$ ssh-keygen -t ed25519 -C "giorgi@mail.ge"Generating public/private ed25519 key pair.Enter file in which to save the key (/home/giorgi/.ssh/id_ed25519):   ← EnterEnter passphrase (empty for no passphrase):                           ← სურვილისამებრYour identification has been saved in /home/giorgi/.ssh/id_ed25519
  • -t ed25519 — ალგორითმი: თანამედროვე, მოკლე და ძლიერი (ძველი ალტერნატივაა RSA).
  • -C — კომენტარი, რომ მოგვიანებით იცოდე, ვისი გასაღებია.
  • passphrase — პირადი გასაღების პაროლი. თუ ლეპტოპი მოიპარეს, მის გარეშე გასაღები უსარგებლოა. სწავლისას შეგიძლია ცარიელი დატოვო.
WSL
$ cat ~/.ssh/id_ed25519.pub        # cat — ფაილის შიგთავსის ჩვენება

.pub-ის ეს ერთი ხაზი არის ის, რასაც სერვერს მივცემთ.

2 · Droplet

ნაწილი 2 · Droplet

სლაიდი 9

Droplet — DigitalOcean-ის ვირტუალური სერვერი (VPS). პირველი ლექციის ანალოგიით — ნაქირავები ბინა.

ნაბიჯი 2 · Droplet-ის შექმნა

სლაიდი 10

DigitalOcean-ის panel-ში: Create → Droplets.

პარამეტრი რას ვირჩევთ რატომ
Region Frankfurt საქართველოსთან ახლოს — სწრაფი პასუხი
Image Ubuntu 24.04 (LTS) x64 სერვერების ყველაზე პოპულარული Linux; LTS — წლების განმავლობაში განახლებები
Size Basic → Regular → უმცირესი (1 vCPU, 1 GB RAM) საკმარისია API-სთვის და ბაზისთვის
Authentication SSH Key → New SSH Key → ჩასვი .pub-ის ხაზი პაროლი არ გვინდა
Hostname lms-server სერვერის სახელი prompt-ში

Create Droplet → დაახლოებით ერთ წუთში Droplet-ის გვერდზე გამოჩნდება მისი IPv4 მისამართი, მაგ. 164.90.12.34.

SSH Key-ით შექმნილ Droplet-ზე პაროლით შესვლა საერთოდ გამორთულია — ბოტები პაროლს ვერ გამოიცნობენ, რადგან ის არ არსებობს.

⚠️

ფასი საათობრივად ითვლება, თვეში რამდენიმე დოლარამდე. Droplet-ის გამორთვა (Power Off) გადახდას არ აჩერებს — რესურსი შენთვისაა დაჯავშნილი. გადახდა მხოლოდ Destroy-ის შემდეგ ჩერდება. ანგარიშზე დააყენე Billing alert.

👉

თუ ოდესმე SSH-ით ვეღარ შედიხარ, Droplet-ის გვერდზე არის Console — ტერმინალი პირდაპირ ბრაუზერში. ეს სათადარიგო კარია.

ნაბიჯი 3 · Termius — სერვერთან კავშირი

სლაიდი 11

Termius — SSH კლიენტი: სერვერების სია, შენახული გასაღებები, რამდენიმე tab ერთად და ჩაშენებული SFTP (ფაილების დათვალიერება). შიგნით ის ზუსტად იმას აკეთებს, რასაც ტერმინალში ssh root@164.90.12.34 — უბრალოდ IP-ს და პარამეტრებს ყოველ ჯერზე აღარ კრეფ.

1. გასაღების შემოტანა. გასაღები უკვე შევქმენით WSL-ში (ნაბიჯი 1). Termius-ს იგივე გასაღებს ვაძლევთ — ახალს არ ვქმნით, რომ WSL-იდანაც და Termius-იდანაც ერთი გასაღებით შევიდეთ:

WSL
$ cat ~/.ssh/id_ed25519-----BEGIN OPENSSH PRIVATE KEY-----...

Termius → Keychain → Key → Import (ან New Key) → მთელი ტექსტი, -----BEGIN-იდან -----END-ის ჩათვლით, ჩასვი Private key ველში.

2. Host. Hosts → New Host:

ველი მნიშვნელობა
Label lms-server
Address Droplet-ის IP
Username root (ცალკე user-ს შემდეგ ლექციაზე შევქმნით)
Key ის, რაც ახლა შემოვიტანეთ

3. Connect. პირველად Termius იტყვის, რომ სერვერის „თითის ანაბეჭდი“ (fingerprint) უცნობია: ამ სერვერს პირველად ვხედავთ — Continue. Termius მას იმახსოვრებს და თუ შემდეგში შეიცვლება, გაგაფრთხილებს (შეიძლება ვინმე შუაში ჩაჯდა).

⚠️

ფაილური სისტემა — ერთი ხე /-დან

სლაიდი 17

Windows-ში დისკები ასოებითაა (C:\, D:\). Linux-ში ერთი ხეა, რომელიც /-დან (root) იწყება — ყველაფერი, დისკებიც, მის შიგნითაა.

✅ შეამოწმე თავი დაფიქრდი, მერე გახსენი პასუხი
SSH-ის რომელი გასაღები რჩება შენთან და რომელი მიდის სერვერზე?
პირადი (id_ed25519) — მხოლოდ შენს კომპიუტერზე, არავის აჩვენო. საჯარო (id_ed25519.pub) — სერვერზე, ~/.ssh/authorized_keys-ში
რატომ ჯობია გასაღები პაროლს?
პაროლს ბოტები უწყვეტად არჩევენ (brute force); გასაღების გამოცნობა პრაქტიკულად შეუძლებელია და მისი „მოპარვა“ სერვერიდან არ შეიძლება — იქ მხოლოდ საჯარო ნაწილია
Droplet გამოვრთე (Power Off). ფული აღარ ჩამოგეჭრება?
ჩამოგეჭრება — გამორთული Droplet-იც ფასიანია, რადგან რესურსი შენთვისაა დაჯავშნილი. გადახდა მხოლოდ Destroy-ის შემდეგ ჩერდება
რას ნიშნავს /, ~ და ..? სად არის root-ის ~?
/ — ფაილური სისტემის ფესვი, ყველაფერი აქედან იწყება; ~ — შენი სახლის საქაღალდე (root-ისთვის /root, სხვებისთვის /home/<user>); .. — ერთი საქაღალდით ზემოთ
სად ინახება Linux-ზე პროგრამების კონფიგურაცია და ლოგები?
კონფიგურაცია — /etc (მაგ. /etc/ssh), ლოგები — /var/log (მაგ. /var/log/auth.log — შესვლის ცდები)
რატომ არის rm -r სახიფათო, განსაკუთრებით root-ით?
Linux-ში სანაგვე ყუთი არ არის: წაშლილი ფაილი სამუდამოდ ქრება, rm -r კი საქაღალდეს მთელი შიგთავსით შლის. root-ს ყველაფრის წაშლის უფლება აქვს — შეკითხვის გარეშე
