წინა ლექციის საშინაო: პროექტების გვერდი, ლინკი README-ში და მზადება სერვერისთვის. ქვემოთ არის ერთ-ერთი სწორი ამოხსნა. შენი კოდი შეიძლება სხვანაირად იყოს დაწერილი — მთავარია, მოთხოვნები სრულდებოდეს.

დღის თემა: საკუთარი სერვერი — არჩევა, ყიდვა და SSH

სლაიდი 4

API-ს სჭირდება კომპიუტერი, რომელიც 24/7 ჩართულია და ინტერნეტიდან მისაწვდომია. დღეს ასეთს ვარჩევთ და ვყიდულობთ: ვთვლით, რა გვჭირდება, ვქმნით DigitalOcean Droplet-ს, ვიგებთ, როგორ შევდივართ მასში პაროლის გარეშე — SSH გასაღებით — და ვუკავშირდებით ჯერ ტერმინალით, მერე Termius-ით. ბოლოს სერვერზე პირველ ბრძანებებს ვუშვებთ.

ლექციის ბოლოს შეძლებ:

  • სერვერის ზომის არჩევა იმის მიხედვით, რა იმუშავებს მასზე: RAM, CPU, დისკი, region
  • Droplet-ის შექმნა DigitalOcean-ზე: Ubuntu 24.04, ზომა, SSH Key
  • ახსნა, როგორ მუშაობს SSH გასაღები: საჯარო ნაწილი სერვერზე, პირადი შენთან
  • სერვერთან დაკავშირება ტერმინალით (ssh root@IP) და Termius-ით
  • პირველი ბრძანებები სერვერზე: whoami, pwd, ls, cd, cat, free -h, df -h

1 · არჩევა

ნაწილი 1 · სერვერის არჩევა

სლაიდი 5

რა სერვერი გვჭირდება, როგორ გამოვთვალოთ მისი ზომა და სად ვიყიდოთ.

პრობლემა: API-ს სჭირდება კომპიუტერი, რომელიც არასოდეს ითიშება

სლაიდი 6

წინა ლექციაზე ვნახეთ: GitHub Pages მხოლოდ ფაილებს აჩვენებს. API კი გაშვებული პროგრამაა — მას სჭირდება კომპიუტერი, რომელიც:

  • 24/7 ჩართულია — ლეპტოპს დახურავ და საიტი ქრება;
  • საჯარო, მუდმივი IP აქვს — სახლის ინტერნეტის IP ხშირად იცვლება და გარედან მიუწვდომელია;
  • სტაბილურ დენზე და ინტერნეტზეა.

საკუთარი სერვერის ყიდვა და მოვლა (რკინა, გაგრილება, ხაზი, შეკეთება) ცალკე ბიზნესია. ამიტომ სერვერს ვქირაობთ: VPS (Virtual Private Server) — მონაცემთა ცენტრის დიდი კომპიუტერის ვირტუალური „ნაჭერი“, რომელიც მხოლოდ შენ გეკუთვნის. პირველი ლექციის ანალოგიით — ნაქირავები ბინა.

შენობა ათასობით სერვერით, მუდმივი დენით და ინტერნეტით

როგორ მივხვდეთ, რა გვჭირდება

სლაიდი 7

სერვერს „თვალით“ არ ვარჩევთ. ჯერ ვწერთ, რა იმუშავებს მასზე, და ვთვლით, რამდენი რესურსი სჭირდება ყველას ერთად. ჩვენი LMS-ისთვის:

რა მუშაობს RAM (დაახლოებით)
Ubuntu (ოპერაციული სისტემა) ~300 MB
Nginx + frontend-ის ფაილები ~20 MB
LMS API (.NET) ~150–250 MB
PostgreSQL ~100–200 MB
ჯამში ~0.6–0.8 GB

სამი მთავარი პარამეტრი:

  • 🧠 RAM — ყველაზე მნიშვნელოვანი: ყველა პროგრამა ერთდროულად უნდა ჩაეტიოს. ჩვენთვის 1 GB საკმარისია.
  • ⚡ CPU (vCPU) — პროცესორის ბირთვები. სასწავლო პროექტს, რომელსაც ცოტა მომხმარებელი ჰყავს, 1 vCPU ჰყოფნის.
  • 💾 დისკი — სისტემა, პროგრამები, ბაზა, ლოგები. 25 GB საკმარისია.
👉

იწყებ პატარით. სერვერის ზომა მოგვიანებით იზრდება (DigitalOcean-ში — Resize). თავიდანვე დიდის ყიდვა უბრალოდ ზედმეტი ხარჯია. როცა დატვირთვა გაიზრდება, მონიტორინგი გეტყვის, რა გაზარდო.

2 · SSH

ნაწილი 2 · SSH

სლაიდი 10

სერვერთან ფიზიკურად ვერ მიხვალ. როგორ შეხვიდე მასში — და ისე, რომ სხვამ ვერ შეძლოს.

პრობლემა: Password? — ბოტები უკვე გელოდებიან

სლაიდი 11

სერვერი მონაცემთა ცენტრშია, სხვა ქვეყანაში — ფიზიკურად მასთან ვერ მიხვალ. SSH (Secure Shell) შენს ტერმინალს სერვერს აკავშირებს: შენ კრეფ, ბრძანება სერვერზე სრულდება, შედეგი შენთან ჩანს. მთელი კავშირი დაშიფრულია.

შესასვლელად სერვერმა უნდა იცოდეს, რომ ეს შენ ხარ. პირველი აზრი — პაროლი. მაგრამ ინტერნეტში ბოტები უწყვეტად ამოწმებენ ყველა IP მისამართს და SSH-ზე პაროლებს არჩევენ (admin/admin, root/123456...). ახალი სერვერის ლოგში ასეთი ცდები რამდენიმე წუთში ჩნდება:

სერვერის შესვლის ლოგი
Invalid user admin from 45.x.x.xInvalid user test from 103.x.x.xFailed password for root from 194.x.x.x

ამიტომ Authentication-ში ვირჩევთ SSH Key-ს — პაროლი საერთოდ არ იქნება, და ბოტებს გამოსაცნობი არაფერი დარჩებათ.

როგორ მუშაობს SSH გასაღები

სლაიდი 12

SSH გასაღები ორი ნაწილისგან შედგება, რომლებიც ერთმანეთს მათემატიკურად ემთხვევა — როგორც საკეტი და მისი გასაღები:

  • 🔒 საჯარო ნაწილი (საკეტი) — ინახება სერვერზე. სერვერმა იცის: „ვისაც ამ საკეტის გასაღები აქვს, ის შევუშვა“.
  • 🔑 პირადი ნაწილი (გასაღები) — ინახება მხოლოდ შენთან, შენს კომპიუტერზე.

როგორ ხდება შესვლა:

  1. შენ სერვერს ეუბნები: „შემიშვი“.
  2. სერვერი საჯარო ნაწილით ამზადებს ამოცანას, რომლის ამოხსნაც მხოლოდ შესაბამის პირად გასაღებს შეუძლია, და გიგზავნის.
  3. შენი კომპიუტერი ამოცანას პირადი გასაღებით ხსნის და პასუხს უბრუნებს. სწორია — შეხვედი.

მთავარი: პირადი გასაღები ქსელში არასოდეს მიდის — მიდის მხოლოდ ამოხსნა. ამიტომ მისი „მოსმენა“ ან სერვერიდან მოპარვა შეუძლებელია: სერვერზე მხოლოდ საკეტია.

საჯარო ნაწილის მოპარვა საშიში არ არის — საკეტით კარს ვერ გააღებ. ამიტომ ერთ საკეტს ბევრ კარზე კიდებ: ყველა შენს სერვერზე, GitHub-ზეც. პირადი კი პაროლზე მნიშვნელოვანია.

⚠️

პირადი გასაღები არ გაუგზავნო არავის, არ ჩასვა ჩატში და არ ატვირთო GitHub-ზე.

ნაბიჯი 2 · გასაღების გენერაცია, ჩასმა და ყიდვა

სლაიდი 13

1. გენერაცია — შენს კომპიუტერზე (Windows-ზე WSL-ში, macOS-ზე Terminal-ში). ერთხელ იქმნება — ყველა სერვერზე და GitHub-ზეც გამოგადგება:

WSL
$ ssh-keygen -t ed25519 -C "giorgi@mail.ge"Enter file in which to save the key (/home/giorgi/.ssh/id_ed25519):   ← EnterEnter passphrase (empty for no passphrase):                           ← სურვილისამებრYour identification has been saved in /home/giorgi/.ssh/id_ed25519
  • -t ed25519 — ალგორითმი: თანამედროვე, მოკლე და ძლიერი.
  • -C — კომენტარი, რომ იცოდე, ვისი გასაღებია.
  • passphrase — პირადი გასაღების პაროლი: თუ ლეპტოპი მოიპარეს, მის გარეშე გასაღები უსარგებლოა. სწავლისას შეგიძლია ცარიელი დატოვო.

შეიქმნა ორი ნაწილი: id_ed25519 — პირადი 🔑 (რჩება შენთან), id_ed25519.pub — საჯარო 🔒 (მიდის სერვერზე).

2. ჩასმა. საჯარო ნაწილის ტექსტი:

WSL
$ cat ~/.ssh/id_ed25519.pub

Droplet-ის ფორმაში: Authentication → SSH Key → New SSH Key → ჩასვი ეს ერთი ხაზი, დაარქვი სახელი (მაგ. laptop).

3. ყიდვა. Create Droplet → დაახლოებით ერთ წუთში Droplet-ის გვერდზე გამოჩნდება მისი IPv4 მისამართი, მაგ. 164.90.12.34. DigitalOcean-მა საკეტი უკვე დადო სერვერზე — და რადგან Password არ ავირჩიეთ, პაროლით შესვლა იქ საერთოდ გამორთულია.

👉

თუ ოდესმე SSH-ით ვეღარ შედიხარ, Droplet-ის გვერდზე არის Console — ტერმინალი პირდაპირ ბრაუზერში. ეს სათადარიგო კარია.

ჯერ ჩვეულებრივი ტერმინალით — რომ დავინახოთ, რა ხდება სინამდვილეში. მერე Termius-ით — რომ გავიგოთ, რატომ გვჭირდება ცალკე აპლიკაცია.

ნაბიჯი 3 · დაკავშირება ტერმინალით

სლაიდი 16
WSL
giorgi@laptop:~$ ssh root@164.90.12.34The authenticity of host '164.90.12.34' can't be established.ED25519 key fingerprint is SHA256:Xb9...Are you sure you want to continue connecting (yes/no)? yes Welcome to Ubuntu 24.04.3 LTS
  • ssh root@164.90.12.34 — ვინ შედის (root) @ სად (IP). ახალ სერვერზე ერთადერთი user root-ია — ადმინისტრატორი.
  • fingerprint — სერვერის „თითის ანაბეჭდი“. ამ სერვერს პირველად ვხედავთ, ამიტომ ვეკითხებით — yes. კომპიუტერი მას იმახსოვრებს და თუ შემდეგში შეიცვლება, გაგაფრთხილებს (შეიძლება ვინმე შუაში ჩაჯდა).
  • პაროლი არ უკითხავს: ssh-მა შენი პირადი გასაღები თვითონ იპოვა (~/.ssh/id_ed25519) და ამოცანა ამოხსნა.

ყურადღება prompt-ს: იყო giorgi@laptop, გახდა root@lms-server. ერთ ფანჯარაში ხარ, მაგრამ ბრძანებები უკვე სერვერზე სრულდება.

Droplet
root@lms-server:~# exitlogout

exit — კავშირის დახურვა, ისევ შენს კომპიუტერზე ხარ.

ნაბიჯი 4 · რატომ Termius

სლაიდი 17

ტერმინალით შესვლა მუშაობს, მაგრამ ყოველ ჯერზე უნდა გახსოვდეს IP, user და რომელი გასაღები. როცა სერვერი ხუთია — ხუთი IP. და ერთ ფანჯარაში ერთი სერვერია.

Termius — SSH კლიენტი, რომელიც ამას ალაგებს:

  • სერვერების სია — სახელით, ერთი დაჭერით შესვლა;
  • შენახული გასაღებები;
  • რამდენიმე tab ერთად (ერთში ლოგი, მეორეში ბრძანებები);
  • ჩაშენებული SFTP — სერვერის ფაილების დათვალიერება.

შიგნით ის ზუსტად იმას აკეთებს, რაც წინა სლაიდზე ტერმინალში — ssh root@164.90.12.34.

1. გასაღების შემოტანა. Termius-ს იგივე პირად გასაღებს ვაძლევთ — ახალს არ ვქმნით, რომ ტერმინალიდანაც და Termius-იდანაც ერთი გასაღებით შევიდეთ:

WSL
$ cat ~/.ssh/id_ed25519-----BEGIN OPENSSH PRIVATE KEY-----...

Termius → Keychain → Key → Import → მთელი ტექსტი, -----BEGIN-იდან -----END-ის ჩათვლით, ჩასვი Private key ველში.

2. Host. Hosts → New Host: Label lms-server, Address — Droplet-ის IP, Username root, Key — ის, რაც ახლა შემოვიტანეთ.

3. Connect — ორჯერ დააჭირე Host-ს. პირველად Termius-იც იკითხავს fingerprint-ს — Continue.

⚠️

პირადი გასაღების ტექსტი მხოლოდ Termius-ის ველში ჩასვი — არა ჩატში, არა სხვაგან.

💡

ამიერიდან სერვერზე ყველაფერს Termius-ში ვაკეთებთ. შენს კომპიუტერზე (git, ssh-keygen, მოგვიანებით rsync და docker) — WSL-ში.

სამი ღილაკი, რომელიც დროს დაგიზოგავს:

  • Tab — ფაილის ან ბრძანების სახელის ავტოშევსება.
  • ↑ / ↓ — წინა ბრძანებები.
  • Ctrl + C — გაშვებული ბრძანების გაჩერება (ტერმინალში ეს კოპირება არ არის!). Termius-ში კოპირება — მონიშვნა, ჩასმა — მარჯვენა ღილაკი.
⚠️

root-ს ყველაფრის უფლება აქვს — მათ შორის სისტემის გაფუჭების, შეკითხვის გარეშე. არ გაუშვა ბრძანება, რომლის მნიშვნელობაც არ იცი. სწორად როგორ ვიმუშაოთ root-ის გარეშე — შემდეგ ლექციაზე.

ფაილური სისტემის დანარჩენ ნაწილს და ფაილებთან მუშაობას შემდეგ ლექციაზე დეტალურად გავივლით.

ვწერთ, რა იმუშავებს მასზე (Ubuntu, Nginx, API, ბაზა) და ვთვლით მათ RAM-ს ერთად. ჩვენთვის ~0.7 GB → 1 GB RAM, 1 vCPU, 25 GB. ვიწყებთ პატარით — საჭიროებისას Resize
SSH გასაღების რომელი ნაწილი სად ინახება?
საჯარო (საკეტი, .pub) — სერვერზე; პირადი (გასაღები) — მხოლოდ შენს კომპიუტერზე. შესვლისას პირადი გასაღები ქსელში არ მიდის — მიდის მხოლოდ სერვერის ამოცანის ამოხსნა
რატომ ვირჩევთ SSH Key-ს და არა Password-ს?
ბოტები ინტერნეტის ყველა IP-ზე უწყვეტად არჩევენ პაროლებს. გასაღების გამოცნობა პრაქტიკულად შეუძლებელია, ხოლო SSH Key-ით შექმნილ Droplet-ზე პაროლით შესვლა საერთოდ გამორთულია
თუ ტერმინალით ssh root@IP მუშაობს, რისთვის გვჭირდება Termius?
Termius შიგნით იგივე SSH-ს აკეთებს, მაგრამ ინახავს სერვერების სიას, გასაღებებს, ხსნის რამდენიმე tab-ს და აქვს SFTP — IP-ს და პარამეტრებს ყოველ ჯერზე აღარ კრეფ
Droplet გამოვრთე (Power Off). ფული აღარ ჩამოგეჭრება?
ჩამოგეჭრება — გამორთული Droplet-იც ფასიანია, რადგან რესურსი შენთვისაა დაჯავშნილი. გადახდა მხოლოდ Destroy-ის შემდეგ ჩერდება
