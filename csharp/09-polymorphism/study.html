წინა ლექციის საშინაო: ⚽ ფეხბურთის კლუბი · ნაწილი 3 — პოზიციები. ქვემოთ არის ერთ-ერთი სწორი ამოხსნა. შენი კოდი შეიძლება სხვანაირად იყოს დაწერილი — მთავარია, მოთხოვნები სრულდებოდეს.

მოთხოვნები

  • Player — საერთო მშობელი: Name, Stamina, Price, Rest() და protected მეთოდები Roll(int min, int max) და Tire(int amount). Shot და Reflex აქედან გადის — ისინი პოზიციებს ეკუთვნის

სლაიდი 4

Character[]-ში მთელი გუნდი ეტევა, მაგრამ c.Attack() ყველასთვის ერთნაირია — მეომრის Smash() და ჯადოქრის Fireball() კი ციკლიდან არ ჩანს. ყოველ ტიპს თავისი მასივი და ციკლი? ახალი გმირი — ბრძოლის კოდის ხელახლა წერა. დღეს ვისწავლით პოლიმორფიზმს: virtual და override — ერთი გამოძახება, ყველა თავისებურად. ბოლოს სამი გმირი ერთი ციკლით დრაკონს შეებრძოლება.

ლექციის ბოლოს შეძლებ:

  • virtual და override: შვილის საკუთარი ვერსია მშობლის მეთოდისა
  • ცვლადის ტიპი vs ობიექტის ტიპი: რა შეიძლება და რა შესრულდება
  • base.Method() — მშობლის ვერსია + საკუთარი წესი
  • object და override ToString(); override vs overload

Character[]-ში ყველა ეტევა, მაგრამ c.Attack() ყველასთვის ერთნაირია (5–15), Smash() და Fireball() კი Character-მა არ იცის. გამოსავალი „შუბლით“:

სლაიდი 6

პოლიმორფიზმი (ბერძნულად „ბევრი ფორმა“) — ერთი და იგივე გამოძახება სხვადასხვა ობიექტზე სხვადასხვანაირად მუშაობს.

c.Attack(): მეომარი ხმლით ურტყამს (15–25), ჯადოქარი — ცეცხლით (25–35), მშვილდოსანი — ისრით, ზოგჯერ ორმაგად.

ცხოვრებიდან: მასწავლებელი ამბობს „წარადგინეთ თავი!“ — ბრძანება ერთია, ყველა თავისებურად პასუხობს.

// Character.cspublic virtual int Attack(){    return RollDamage(5, 15);} // Warrior.cs — Smash()-ის ნაცვლადpublic override int Attack(){    return RollDamage(15, 25);}

  • override შვილში — „ვცვლი“. სახელი, პარამეტრები და დასაბრუნებელი ტიპი ზუსტად იგივეა.

💡 override vs overload

სლაიდი 17
  • override (შეცვლა) — შვილი მშობლის virtual მეთოდს იგივე სახელითა და პარამეტრებით ცვლის. რომელი ვერსია შესრულდება — ობიექტი წყვეტს.
