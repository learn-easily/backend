საფინალო პროექტი

ლექტორი კლასში Shop-ს (ონლაინ მაღაზია) აწყობს. შენ იმავე დროს იწყებ შენს პროექტს და ყოველი ლექციის შემდეგ სახლში იმავეს ამატებ შენს სფეროში. 28-ე ლექციაზე წარადგენ იმას, რაც 14-იდან ააწყე — ცალკე „საფინალოს წერა“ ბოლოს აღარ გჭირდება.

როგორ მუშაობს

1 · ლექცია 14

აირჩიე სფერო

ქვემოთ მოცემულიდან ერთი (ან შენი — ლექტორთან შეთანხმებით) და დააჭირე „ეს ავირჩიე“. დავალებები შენს სფეროზე გამოჩნდება.
2 · კლასში

ლექტორთან ერთად

ახალი თემა Shop-ზე: პრობლემა → ახსნა → კოდი.
3 · სახლში — HW

შენს პროექტში

ლექციის ნომრის საშინაო (HW-15, HW-16, …) — ზუსტად შენი სფეროს კლასებით. ყოველი HW — ერთი commit მაინც.
4 · ლექცია 28

წარდგენა

დემო, კოდი, ტესტები და კითხვები.

⚠️ საშინაო = შენი პროექტის შემდეგი ნაბიჯი. ყოველი ლექცია წინაზე დგება — გამოტოვებული HW მომდევნო ლექციის საშინაოს ვერ გაგაკეთებინებს.

პროექტი C#-ით არ მთავრდება: SQL-ზე შენი სფეროსთვის ბაზას დააპროექტებ, EF Core-ზე კი იგივე კონსოლის აპი ამ ბაზას მიუერთდება.

სფეროები

ყველა სფერო Shop-ის ფორმისაა: კატალოგი, კლიენტი, „შეკვეთა“ ხაზებით, სტატუსით და თარიღით, შეზღუდვა, წესი (ფასდაკლება / ჯარიმა) და ორი როლი. დააჭირე — ნახავ დეტალებს და შენს დავალებებს.

💡 საკუთარი იდეა? შეიძლება — თუ მას აქვს კატალოგი, კლიენტი, „შეკვეთა“ სტატუსით და თარიღით, შეზღუდვა, მინიმუმ ერთი წესი და ორი როლი. 14-ე ლექციაზე შეუთანხმე ლექტორს და დავალებებს Shop-ის მიხედვით გაიყოლებ.

დავალებები —

ყოველი ლექციის შემდეგ — სახლში, შენს პროექტში. კლასში იგივეს Shop-ზე ვაკეთებთ, ასე რომ, ყოველთვის გაქვს ნიმუში.

მოთხოვნები — რა უნდა ჰქონდეს წარდგენისას

  • კონსოლის აპი და სტრუქტურა: საქაღალდეები Models · Enums · Services · Data · Exceptions; ბოლოს solution სამ პროექტად — Core / Console / Tests
  • მოდელები: სწორად დაგეგმილი — მინიმუმ 5 კლასი (კატალოგი, კლიენტი, „შეკვეთა“, მისი ხაზი, User), 2+ enum, ყველა ობიექტს Guid id; ერთი record
  • OOP და ინკაფსულაცია: მონაცემი private set-ით, ცვლილება მხოლოდ მეთოდებით; წესები ობიექტის შიგნით
  • ავტორიზაცია და როლები: რეგისტრაცია / შესვლა, მინიმუმ 2 როლი, მენიუ როლის მიხედვით; პაროლი მხოლოდ hash-ით (PBKDF2)
  • შეცდომები: მინიმუმ 2 საკუთარი exception; მენიუ არასწორ შეყვანაზე არ ვარდება
  • კოლექციები და generic: List, Dictionary; ერთი საკუთარი generic კლასი ან მეთოდი
  • დელეგატები და LINQ: ფილტრი Func-ით; მინიმუმ 5 ანგარიში LINQ-ით (მათ შორის GroupBy)
  • თარიღები: DateTime / TimeSpan — ვადა, ხანგრძლივობა ან თარიღების შედარება
  • JSON და async: ყველა მონაცემი JSON ფაილებში, ჩატვირთვა და შენახვა async-ით
  • ელფოსტა: მინიმუმ ერთი მეილი SMTP-ით (დადასტურება ან შეხსენება); პაროლი კოდში არ წერია
  • ტესტები: მინიმუმ 8 unit ტესტი — წესები და exception-ები
  • Git: GitHub რეპო, README; მინიმუმ ერთი commit ყოველი HW-ის შემდეგ

წარდგენა — ლექცია 28

თითოეულს ~8 წუთი: 3 წუთი დემო (შესვლა ორივე როლით, მთავარი სცენარი, შეცდომის სცენარი, ანგარიშები, მეილი) → 2 წუთი კოდი (სტრუქტურა, მოდელები, ერთი წესი, ერთი LINQ, ტესტები) → 3 წუთი კითხვები („რატომ ასე?“, „რა მოხდება, თუ…?“).
