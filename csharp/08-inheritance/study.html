წაიკითხე ლექციის შემდეგ, ან პრეზენტაციასთან ერთად: პრეზენტაციაში დააჭირე P და ეს გვერდი სლაიდებს გაჰყვება. კოდი და AI-ს პრომპტები კოპირდება ერთი დაჭერით.

გავიხსენოთ წინა ლექცია

სლაიდი 1

ლექცია 7 — ინკაფსულაცია. ახალ თემამდე ვამოწმებთ, რა დაგვამახსოვრდა. ჯერ თვითონ უპასუხე, მერე გახსენი პასუხი. თუ რომელიმე გაგიჭირდა, წინა ლექციის კონსპექტს გადახედე.

✅ შეამოწმე თავი დაფიქრდი, მერე გახსენი პასუხი
public და private — რა განსხვავებაა? და რა არის, თუ არაფერი წერია?
public — ყველგან ჩანს · private — მხოლოდ კლასის შიგნით · არაფერი → private
public int Health { get; private set; } — knight.Health = 99999; Program.cs-ში?
შეცდომა (CS0272): set private-ია. წაკითხვა შეიძლება, შეცვლა — მხოლოდ კლასის მეთოდებით
property-ის set-ში რა არის value?
მნიშვნელობა, რომელსაც წერენ: knight.Name = "" → value = ""
ველი და property — რა განსხვავებაა?
ველი — უბრალოდ ცვლადი კლასში (private) · property — „კარი“ get/set-ით, შეიძლება წესით
რატომ ამოწმებს TakeDamage უარყოფით დაზიანებას თავად — და არა Program.cs?
წესი ერთ ადგილას — კლასში. ვინც არ უნდა გამოიძახოს, წესი ყოველთვის მუშაობს (ინკაფსულაცია)

სლაიდი 3

წინა ლექციის საშინაო: ⚽ ფეხბურთის კლუბი · ნაწილი 2 — ტრანსფერები. ქვემოთ არის ერთ-ერთი სწორი ამოხსნა. შენი კოდი შეიძლება სხვანაირად იყოს დაწერილი — მთავარია, მოთხოვნები სრულდებოდეს.

მოთხოვნები

  • Player დაიცავი: Name — წესით (ცარიელი → „უცნობი“); Shot, Reflex, Stamina — { get; private set; } და ყოველთვის 0–100; ახალი Price { get; private set; } (კონსტრუქტორში)
  • Train() და Rest() — Player-ის მეთოდები: Train — Shot +5, Stamina −20 (Stamina 20-ზე ნაკლები → „დაღლილია“ და არაფერი იცვლება); Rest — Stamina +30
  • ახალი კლასი Club (Club.cs): Name, Budget { get; private set; }, private Player[] squad = new Player[5] (მინი-ფეხბურთი — 5 მოთამაშე), Count { get; private set; }
  • bool Buy(Player p) — გუნდი სავსეა ან ფული არ ჰყოფნის → false და არაფერი იცვლება; void PrintSquad()
  • Main-ში: კლუბი 100 000 ₾-ით; სცადე 6 მოთამაშის ყიდვა — ერთი ძვირია, მეექვსეს ადგილი აღარ აქვს

დღის თემა: მემკვიდრეობა

სლაიდი 4

არენას მეომარი, ჯადოქარი და დრაკონი სჭირდება — და თითოეულს Hero-ს მთელი კოდი. Copy-paste ნიშნავს: ერთი ბაგი — სამ ფაილში. დღეს ვისწავლით მემკვიდრეობას: საერთო კოდი ერთხელ იწერება Character-ში, შვილები კი მხოლოდ საკუთარს ამატებენ. მერე — protected და გუნდური ბრძოლა დრაკონთან.

ლექციის ბოლოს შეძლებ:

  • class Warrior : Character — მშობელი და შვილი, „არის“ კავშირი
  • : base(...) — მშობლის კონსტრუქტორი და გამოძახების რიგი
  • protected: public / protected / private — ვინ რას ხედავს
  • შვილი მშობლის ტიპის ცვლადში: Character[] — და მისი შეზღუდვა

🧩 პრობლემა: სამი კლასი — სამჯერ ერთი და იგივე

სლაიდი 5

არენას სამი ახალი პერსონაჟი სჭირდება: მეომარი (Smash()), ჯადოქარი (Mana, Fireball()) და დრაკონი (FireBreath()). თითოეულს ასევე სჭირდება ყველაფერი, რაც Hero-ს აქვს: Name, Health, MaxHealth, Potions, TakeDamage(), Heal(), UsePotion(), IsAlive().

  • Hero-ს ~70 ხაზი — სამჯერ copy-paste.
  • ბაგი TakeDamage-ში? სამ ფაილში უნდა გაასწორო.
  • ერთგან დაგავიწყდა — ახლა მხოლოდ ჯადოქარია ბაგიანი, და ძებნა იწყება.

💡 მემკვიდრეობა: მეომარი არის პერსონაჟი

სლაიდი 6

მემკვიდრეობა — ახალი კლასი არსებულზე შენდება: მშობლის ყველაფერი უკვე აქვს და თავისას ამატებს.

  • Character — მშობელი (base class): ყველაფერი საერთო, ერთხელ დაწერილი.
  • Warrior, Mage, Dragon — შვილები (derived class): მშობლის ყველაფერი + საკუთარი.

შემოწმება — „X არის Y?“: მეომარი არის პერსონაჟი ✓, დრაკონი არის პერსონაჟი ✓, ხმალი არის პერსონაჟი ✗ — ხმალი მემკვიდრე არ იქნება.
