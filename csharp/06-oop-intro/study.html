საშინაოს განხილვა

სლაიდი 3

წინა ლექციის საშინაო: სკოლის ჟურნალი. ქვემოთ არის ერთ-ერთი სწორი ამოხსნა. შენი კოდი შეიძლება სხვანაირად იყოს დაწერილი — მთავარია, მოთხოვნები სრულდებოდეს.

მოთხოვნები

  • Console App SchoolJournal, კლასი Student (Student.cs): Name და int[] Scores (property-ები)
  • ორი კონსტრუქტორი: Student(string name, int[] scores) და Student(string name) — მეორე: სამი ნული (new int[3])
  • მეთოდები: double Average(), string Grade() (switch expression: 9+ ფრიადი · 7+ კარგი · 5+ საშუალო · სხვა — არადამაკმაყოფილებელი) და void PrintReport()
  • Main-ში: 4 ცალკე ობიექტი (ორივე კონსტრუქტორით), ყველას რეპორტი, საუკეთესო და ფრიადოსნების რაოდენობა

Student.cs · namespace-ის შიგნით
internal class Student{    public string Name { get; set; }    public int[] Scores { get; set; }     public Student(string name, int[] scores)    {        Name = name;        Scores = scores;    }     public Student(string name)    {        Name = name;        Scores = new int[3];    }     public double Average()    {        int sum = 0;        foreach (int s in Scores)        {            sum += s;        }        return sum * 1.0 / Scores.Length;    }     public string Grade()    {        return Average() switch        {            >= 9 => "ფრიადი",            >= 7 => "კარგი",            >= 5 => "საშუალო",            _ => "არადამაკმაყოფილებელი"        };    }     public void PrintReport()    {        Console.Write($"{Name} — ქულები: ");        foreach (int s in Scores)        {            Console.Write(s + " ");        }        Console.WriteLine($"· საშუალო {Average():F1} · {Grade()}");    }}
💡

Grade() საკუთარ Average()-ს იძახებს — კლასის მეთოდებს ერთმანეთის გამოძახება შეუძლიათ. new int[] { 8, 9, 7 } — მასივი პირდაპირ კონსტრუქტორის პარამეტრად. new Student("მარიამი") მეორე კონსტრუქტორს იძახებს — მარიამს სამი ნული აქვს. Main-ში ერთი და იგივე ხაზი ოთხჯერ მეორდება — 30 მოსწავლეზე 30-ჯერ. შემდეგ ლექციაზე ვნახავთ, როგორ ხდება ეს ყველაფერი ერთი მასივით და ერთი foreach-ით.

დღის თემა: OOP: შესავალი და არენა

სლაიდი 4

წინა ლექციაზე საკუთარი კლასი — Student — დავწერეთ. დღეს დავინახავთ, რომ C#-ში ყველაფერი ობიექტია და რა ხდება, როცა ობიექტს სხვა ცვლადში ვწერთ. მერე — OOP-ის ოთხი პრინციპი და ჩვენი თამაში, არენა, რომელზეც მომდევნო ოთხ ლექციაში ოთხივე პრინციპს ვისწავლით.

ლექციის ბოლოს შეძლებ:

  • string, Random, მასივი — როგორც ობიექტები: property-ები და მეთოდები
  • value და reference: რატომ ცვლის b = a ერთსა და იმავე ობიექტს
  • OOP-ის ოთხი პრინციპი და რატომ ვიცავთ მათ; არენა: Hero კლასი და პირველი ბრძოლა

  • ToUpper() ქართულზეც მუშაობს: ქართულს „დიდი ასოები“ — მთავრული აქვს, ამიტომ "ანა".ToUpper() → ᲐᲜᲐ.

❓ რას დაბეჭდავს?

სლაიდი 8
int
int x = 5;int y = x;y = 10;Console.WriteLine(x);

პასუხი: 5. y = x რიცხვს აკოპირებს — y-ის შეცვლა x-ს არ ეხება.

Student
Student a = new Student("ანა", 15, 9.2);Student b = a;b.Name = "გიო";Console.WriteLine(a.Name);

პასუხი: გიო! b = a ობიექტს არ აკოპირებს — a და b ერთსა და იმავე მოსწავლეს უჩვენებს. რატომ — შემდეგ სლაიდზე.

💡 value და reference: ცვლადში ობიექტი კი არა, მისამართი წერია

სლაიდი 9
  • value type — int, double, bool: ცვლადში თვითონ მნიშვნელობა წერია. y = x მას აკოპირებს — ორი დამოუკიდებელი რიცხვი.
  • reference type — კლასის ობიექტი (Student, string, მასივი…): ობიექტი მეხსიერებაში ცალკე ცხოვრობს, ცვლადში კი მხოლოდ მისი მისამართი (reference) წერია. b = a ისარს აკოპირებს — ახლა ორი ისარი ერთ ობიექტზე მიუთითებს.
  • ახალი ობიექტი მხოლოდ new-ით იქმნება.

ცხოვრებიდან: მეგობარს სახლის მისამართი მიეცი. ორივეს ერთი მისამართი გაქვთ — მან სახლი რომ შეღებოს, შენც შეღებილს ნახავ.

OOP — Object-Oriented Programming, ობიექტზე ორიენტირებული დაპროგრამება.

🧩 პრობლემა: თამაში იზრდება — კოდი იშლება

სლაიდი 12

წარმოიდგინე თამაში 10 გმირით, 50 მონსტრით და 100 ნივთით — კლასების გარეშე:

  • ასობით ცვლადი და მეთოდი: knightName, mageHealth, orc1Health… ვინ რას ეკუთვნის — აღარ ჩანს.
  • ნებისმიერ ადგილას შეიძლება knightHealth = 99999 — არავინ იცავს.
  • ახალი გმირი — copy-paste. ბაგი? 10 ადგილას გასასწორებელი.

OOP-ში პროგრამა ობიექტების სამყაროა: ყოველ ობიექტს თავისი მონაცემი და ქცევა აქვს.

💡 OOP: ობიექტი = მონაცემი + ქცევა

სლაიდი 13
  • მონაცემი — რა აქვს ობიექტს: property-ები (სახელი, სიცოცხლე).
  • ქცევა — რა შეუძლია: მეთოდები (შეტევა, დაზიანება).
  • ობიექტები ერთმანეთს მეთოდებით „ელაპარაკებიან“: რაინდი უტევს → დრაკონი ზიანდება.

C# — OOP ენაა: ყველაფერი კლასებშია, Program-იც კი.

💡 OOP-ის ოთხი პრინციპი

სლაიდი 14
  1. 🛡️ ინკაფსულაცია — „დაიცავი“. ობიექტის მონაცემს გარედან ვერავინ გააფუჭებს: knight.Health = 99999 აღარ იმუშავებს.
  2. 🧬 მემკვიდრეობა — „გაიზიარე“. მეომარი და ჯადოქარი ერთი „პერსონაჟის“ შვილებია: საერთო კოდი ერთხელ იწერება.
  3. 🎭 პოლიმორფიზმი — „ერთი ბრძანება — სხვადასხვა ქცევა“. hero.Attack(): მეომარი ხმლით უტევს, ჯადოქარი — ცეცხლით.
  4. 🎨 აბსტრაქცია — „აჩვენე რა, დამალე როგორ“. მანქანას პედლით მართავ — ძრავის შიგნით რა ხდება, არ გჭირდება.

ყოველ პრინციპს თავისი ლექცია ეთმობა. ოთხივეს ერთ თამაშზე ვისწავლით — არენა.

  1. string, Random, მასივი — ობიექტებია. წერტილი = „შედი ობიექტში“.

  5. OOP-ის 4 პრინციპი: ინკაფსულაცია, მემკვიდრეობა, პოლიმორფიზმი, აბსტრაქცია.
