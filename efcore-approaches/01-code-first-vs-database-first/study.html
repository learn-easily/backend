Code First vs Database First

წაიკითხე ლექციის შემდეგ, ან პრეზენტაციასთან ერთად: პრეზენტაციაში დააჭირე P და ეს გვერდი სლაიდებს გაჰყვება. კოდი და AI-ს პრომპტები კოპირდება ერთი დაჭერით.

დღის თემა

დღის თემა: Code First vs Database First

სლაიდი 1

EF Core-ით უკვე მუშაობთ: კლასს წერთ და ბაზას EF Core ქმნის. ამ გზას სახელი აქვს — Code First. მაგრამ რა ხდება, როცა ბაზა უკვე არსებობს — 15 წლის, სხვისი? დღეს ორ მიდგომას ვადარებთ, ვსწავლობთ, როდის რომელი ავირჩიოთ, და ვხედავთ Code First-ის ნამდვილ ძალას: ბაზა იზრდება კოდთან ერთად, ისტორიით.

ლექციის ბოლოს შეძლებ:

  • ახსნა: ვინ არის ჭეშმარიტების წყარო Code First-ში და Database First-ში
  • სწორი მიდგომის არჩევა რეალურ სიტუაციაში
  • ახალი სვეტი და 1-N კავშირი მიგრაციით, FK-ის შეცდომის გამოსწორება
  • მიგრაციების ისტორია: Remove-Migration, Update-Database <სახელი>, Script-Migration

ლექციის გეგმა

სლაიდი 3

✓ EF Core და ✓ Entity-ები კავშირებით უკვე იცით. დღეს:

  1. ⚖️ ორი მიდგომა — ვინ არის მთავარი: კოდი თუ ბაზა?
  2. შედარება — როდის რომელი.
  3. Code First პრაქტიკაში — ბაზა იზრდება კოდთან ერთად.
  4. ⌨️ პრაქტიკა — მე → ერთად → თქვენ.

დღის თემა

რასაც უკვე აკეთებთ

სლაიდი 4

EF Core-ით ასე მუშაობდით:

  1. Entity — კლასები და კავშირები
  2. DbContext — DbSet-ები + connection string
  3. Add-Migration — მიგრაციის ფაილი
  4. Update-Database — ბაზა იქმნება

ჯერ კლასი → მერე EF Core ქმნის ბაზას. SSMS-ში CREATE TABLE არ გიწერიათ. ამ გზას სახელი აქვს: Code First — „ჯერ კოდი“.

მაგრამ რა ხდება, როცა ბაზა უკვე არსებობს?

1 · ორი მიდგომა

ნაწილი 1 · ორი მიდგომა, ორი მიმართულება

სლაიდი 5

ორივე ერთსა და იმავე პრობლემას ხსნის — C# და ბაზა ერთმანეთს უნდა შეესაბამებოდეს. განსხვავება მიმართულებაშია: კოდი → ბაზა თუ ბაზა → კოდი.

ვინ არის ჭეშმარიტების წყარო?

სლაიდი 6

ჭეშმარიტების წყარო — ადგილი, სადაც „ნამდვილი“ ვერსია ცხოვრობს; დანარჩენი მისი ასლია.

  • 🟢 Code First — 👑 C# კლასები → ბაზა. მთავარი კოდია; ბაზა კოდის ასლია, რომელსაც EF Core აშენებს.
  • 🟠 Database First — 👑 ბაზა → C# კლასები. მთავარი ბაზაა; კლასები ბაზის ასლია, რომელსაც EF Core აგენერირებს.
📘 ტერმინები
ჭეშმარიტების წყარო (source of truth)
ადგილი, საიდანაც ყველაფერი დანარჩენი იქმნება; ცვლილება აქ იწყება

Code First: კოდი წერს ბაზას

სლაიდი 7

✍️ C# კლასი (ჩვენ ვწერთ) → Add-Migration → 📐 მიგრაცია (ნახაზი, ფაილი) → Update-Database → 🗄️ ბაზა (EF Core აშენებს)

კოდი შეიცვალა? → ისევ თავიდან 🔁. ბაზას ხელით არ ვეხებით — SSMS-ში მხოლოდ ვამოწმებთ. ყოველი ცვლილება ახალი მიგრაციაა.

Database First: ბაზიდან იბადება კოდი

სლაიდი 8

🗄️ ბაზა უკვე არსებობს (SSMS-ში შექმნა ვიღაცამ — შეიძლება ჩვენ, DBA-მ, ან 10 წლის წინ) → Scaffold-DbContext → 📄 C# კლასები + DbContext (EF Core აგენერირებს)

Package Manager Console
Scaffold-DbContext "Server=...;Database=ShopDb;..." Microsoft.EntityFrameworkCore.SqlServer -OutputDir Models

EF Core უერთდება ბაზას, კითხულობს ყველა ცხრილს და თითოეულზე კლასს წერს. ბაზა შეიცვალა? → ისევ Scaffold (-Force) 🔁.

📘 ტერმინები
Scaffold-DbContext
ბრძანება, რომელიც არსებული ბაზიდან Entity კლასებს და DbContext-ს აგენერირებს

ერთი ცხრილი — ორი ავტორი

სლაიდი 9
Code First · ხელით დაწერილი
public class Product{    public int Id { get; set; }    public string Name { get; set; } = string.Empty;    public decimal Price { get; set; }} public class DataContext : DbContext{    public DbSet<Product> Products { get; set; }}
Database First · Scaffold-მა დაწერა
public partial class Product{    public int Id { get; set; }    public string Name { get; set; } = null!;    public decimal Price { get; set; }} public partial class ShopDbContext : DbContext{    public virtual DbSet<Product> Products { get; set; }     protected override void OnModelCreating(ModelBuilder modelBuilder)    {        modelBuilder.Entity<Product>(entity =>        {            entity.Property(e => e.Name).HasMaxLength(100);            entity.Property(e => e.Price).HasColumnType("decimal(18, 2)");        });    }}

თითქმის იგივეა! განსხვავებები:

  • partial — კლასი ნაწილებად იწერება: შენს დამატებებს ცალკე ფაილში წერ, რომ ხელახალმა Scaffold-მა არ წაშალოს.
  • OnModelCreating — ბაზის დეტალები (HasMaxLength(100), ტიპები) ცხადად წერია, რადგან ბაზაში ზუსტად ასეა.

შედეგი ერთი და იგივეა — Entity + DbContext. EF Core-ს არ აინტერესებს, ვინ დაწერა.

ახალი მოთხოვნა: „პროდუქტს მარაგი (Stock) უნდა ჰქონდეს“

სლაიდი 10
  • Code First ✍️ — Product.cs: + Stock → Add-Migration AddStock → Update-Database → ✓ ბაზაში ახალი სვეტი. (ამას დღეს პრაქტიკაში გავაკეთებთ.)
  • Database First 🗄️ — SSMS: ALTER TABLE Products ADD Stock … → Scaffold-DbContext … -Force → ✓ Product.cs თავიდან დაიწერა.
⚠️

-Force გენერირებულ ფაილებს თავიდან წერს — შიგ ხელით დამატებული კოდი იკარგება. ამიტომაა partial: შენი კოდი ცალკე ფაილში.

კრიტერიუმი 🟢 Code First 🟠 Database First
ჭეშმარიტების წყარო C# კლასები ბაზის სქემა
პირველი ნაბიჯი ვწერთ კლასს ბაზა უკვე არსებობს
ცვლილების გზა კლასი → Add-Migration → Update-Database SSMS-ში ALTER → Scaffold … -Force

ვინ წერს SQL-ს EF Core (მიგრაცია) ადამიანი (SSMS)

ძლიერი და სუსტი მხარეები

სლაიდი 13

🟢 Code First

  • ✓ ყველაფერი C#-შია, ერთ ადგილას
  • ✓ ბაზის ისტორია — მიგრაციები Git-ში
  • ✓ ბაზა ერთი ბრძანებით იქმნება ნებისმიერ კომპიუტერზე
  • ✗ მიგრაციებს დისციპლინა სჭირდება
  • ✗ ცუდი კლასი = ცუდი ცხრილი — SQL-ის ცოდნა მაინც საჭიროა

🟠 Database First

  • ✓ არსებულ, დიდ ბაზასთან წამებში იწყებ მუშაობას
  • ✓ ბაზას შეუძლია მართოს DBA-მ, SQL-ის სრული ძალით
  • ✗ ორ ადგილას მუშაობ: SSMS და კოდი
  • ✗ ცვლილებების ისტორია კოდში არ ჩანს

„საუკეთესო“ არ არსებობს — ორივეს თავისი ფასი აქვს.

✅ შეამოწმე თავი დაფიქრდი, მერე გახსენი პასუხი
🚀 სტარტაპი იწყებს ახალ აპლიკაციას, ბაზა ჯერ არ არსებობს
Code First — ბაზის მფლობელი ჩვენ ვართ და ახლა იქმნება
🏦 ბანკის ბაზა 15 წლისაა, 300 ცხრილით, და მას 5 სხვა პროგრამაც იყენებს
Database First — ბაზა უკვე არსებობს და მარტო ჩვენი არ არის
🧑‍💼 ბაზას DBA-ების გუნდი მართავს; დეველოპერს CREATE TABLE-ის უფლება არ აქვს

🎓 სასწავლო პროექტი, რომელსაც მარტო წერ და ხშირად ცვლი
Code First — კლასს ცვლი, მიგრაცია, და ისტორიაც გაქვს

მითები და ფაქტები

სლაიდი 15
მითი ფაქტი
Database First-ში ბაზას დიზაინერში „ვხატავთ“ ეს იყო ძველი EF6 (EDMX). EF Core-ში — ერთი ბრძანება: Scaffold-DbContext. („Model First“-იც EF6-ისაა.)
Code First-ში SQL აღარ მჭირდება SQL-ს EF წერს, მაგრამ ჩვენ ვკითხულობთ — მიგრაციის ფაილს და SSMS-ს ყოველთვის
ერთ პროექტში მხოლოდ ერთი მიდგომა შეიძლება Database First-ით დაიწყო და მერე მიგრაციებზე გადახვიდე
Database First — ძველია, Code First — თანამედროვე ორივე აქტუალურია; ირჩევ სიტუაციის მიხედვით, არა მოდით

ერთი წინადადებით

სლაიდი 16
  • 🏠 ბაზა შენია და ახლა იქმნება → Code First
  • 🏛️ ბაზა უკვე არსებობს ან სხვისია → Database First
