ასე რომ, მიმტანი არის API. ვნახოთ, რას აკეთებს.
API = მიმტანი

შეკვეთა მიდის — კერძი მოდის

სტუმარმა არ იცის, როგორ მზადდება კერძი — და არც სჭირდება.
სამზარეულო არ იცნობს სტუმარს — მხოლოდ შეკვეთას ხედავს.
⏱ 3 წთ
სტუმარს ხაჭაპური უნდა.
→ 1შეკვეთა მიდის
სტუმარი მიმტანს ეუბნება, მიმტანი შეკვეთას სამზარეულოში მიიტანს. ამას ჰქვია მოთხოვნა — Request.
→ 2კერძი ბრუნდება
სამზარეულო ამზადებს, მიმტანი კერძს უკან მოიტანს. ეს არის პასუხი — Response.
→ 3ორი ბლოკი ქვემოთ
სტუმარმა არ იცის, როგორ მზადდება კერძი — და არც სჭირდება. სამზარეულო სტუმარს არ იცნობს — მხოლოდ შეკვეთას ხედავს.
Frontend-საც არ აინტერესებს, რა ბაზაა ან რა ენაზეა Backend დაწერილი. მას მხოლოდ შეკვეთის გაგზავნა და პასუხის მიღება სჭირდება.
მიმტანმა იცის, ვის მიუტანოს

ყოველ შეკვეთას — თავისი მზარეული

მიმტანი თვითონ არ ამზადებს — ის სწორ ადგილას მიაქვს შეკვეთა. API-შიც ასეა: ყოველ მოთხოვნას თავისი ადგილი აქვს.
⏱ 3 წთ
მაგრამ სტუმარი ერთ რამეს არ უკვეთავს. და სამზარეულოში ყველაფერს ერთი მზარეული არ აკეთებს.
→ 1„ხაჭაპური“ → თონე
ხაჭაპურის შეკვეთა მიმტანს თონესთან მიაქვს.
→ 2„სალათი“ → ცივი კერძები
სალათი — ცივი კერძების მზარეულთან.
→ 3„ანგარიში“ → სალარო
ანგარიში — სალაროში, საერთოდ არა სამზარეულოში.
→ 4დასკვნა
მიმტანი თვითონ არაფერს ამზადებს. მან იცის: რომელი თხოვნა სად წაიღოს.
API-შიც ასეა — ყოველ მოთხოვნას თავისი ადგილი აქვს. ვნახოთ, როგორ გამოიყურება ეს რეალურად.
Endpoint

API შედგება Endpoint-ებისგან

Endpoint = მეთოდი + მისამართი ერთი კონკრეტული მიზნით. მოთხოვნა მოდის Endpoint-ზე → Endpoint Backend-ში შესაბამის ფუნქციას ააქტიურებს.
⏱ 4 წთ · ! ერთ-ერთი მთავარი სლაიდი, ნელა
აი, რეალური API. სამი სვეტი: მარცხნივ საიტი, შუაში API, მარჯვნივ Backend-ის კოდი.
შუა სვეტს დააკვირდით. API ერთი დიდი კარი არ არის — ეს ბევრი პატარა კარია. თითოეულ კარს ჰქვია Endpoint.
თითოეულ Endpoint-ს აქვს: მეთოდი (GET, POST) + მისამართი (/api/products) + ერთი კონკრეტული მიზანი.
პირველი — პროდუქტების სია. მეორე — ერთი პროდუქტი. მესამე — შეკვეთის გაკეთება. მეოთხე — ჩემი კალათა.
→ 1კავშირები („იძახებს“)
ყოველი Endpoint მიბმულია Backend-ში ერთ ფუნქციაზე. ეს ფუნქციები ჩვენ დავწერთ C#-ში.
→ 2მოთხოვნა #1
საიტს პროდუქტების სია სჭირდება. აგზავნის მოთხოვნას GET /api/products-ზე. ეს Endpoint ანთდება და Backend-ში იძახებს ფუნქციას GetAllProducts().
→ 3მოთხოვნა #2
მომხმარებელმა „შეკვეთა“ დააჭირა. საიტი აგზავნის POST /api/orders-ს — ეს უკვე სხვა კარია, და ის სხვა ფუნქციას იძახებს: CreateOrder().
→ 4განმარტება
