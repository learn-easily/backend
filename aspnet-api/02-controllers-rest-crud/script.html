7Minimal API და Controller — გვერდიგვერდ

⏱ 0:13 · 5 წთ
ერთი და იგივე endpoint ორივე გზით. მარცხნივ — Minimal API, მარჯვნივ — Controller.
❓ ერთი შეხედვით, რომელშია მეტი კოდი? (Controller-ში.) კარგი, ვნახოთ, რატომ.
→ 1მისამართი და მეთოდი
ორივეს ერთი და იგივე ორი რამ სჭირდება: მისამართი და HTTP მეთოდი. Minimal-ში ორივე ერთ ხაზშია: MapGet + მისამართი. Controller-ში ცალ-ცალკეა: მისამართი — კლასის თავზე [Route]-ში, მეთოდი — [HttpGet]-ში.
→ 2რას ვაბრუნებთ
ლოგიკაც ერთია. Minimal-ში ფუნქციაა — lambda. Controller-ში — კლასის ჩვეულებრივი მეთოდი, რომელიც პასუხს Ok-ში ახვევს.
→ 3შედეგი
და შედეგი? ზუსტად ერთი და იგივე: GET /api/products → 200 და JSON. ბრაუზერმა, Angular-მა, მობილურმა აპლიკაციამ არ იცის და არც აინტერესებს, რომელი გზით დავწერეთ.

8Controller-ი — ნაწილ-ნაწილ

⏱ 0:18 · 5 წთ
Controller-ში ყველაფერს თავისი ადგილი აქვს. ხუთი ნაწილი — თითოეულს ცალკე ავხსნი.
→ 1[ApiController]
პირველი: [ApiController]. ეს ატრიბუტია — კვადრატულ ფრჩხილებში წერია და კლასს „ნიშანს“ ადებს: ეს კლასი API-ს ემსახურება. მაგალითად, თუ კლიენტი არასწორ მონაცემს გამოგზავნის, თავისით დააბრუნებს 400-ს.
→ 2[Route]
მეორე: [Route] — მისამართი. [controller] სპეციალური სიტყვაა: მის ადგილას ჩაჯდება კლასის სახელი Controller-ის გარეშე. ProductsController → api/products.
❓ CategoriesController-ის მისამართი რა იქნება? (api/categories.)
→ 3ControllerBase
მესამე: ვაშენებთ ControllerBase-ზე. აქედან ვიღებთ მზა მეთოდებს — Ok, NotFound, NoContent. ! და სახელი აუცილებლად Controller-ით უნდა მთავრდებოდეს — ASP.NET Core ასე პოულობს.
→ 4[HttpGet]
მეოთხე: [HttpGet] — ეს მეთოდი GET მოთხოვნას პასუხობს. იქნება [HttpPost], [HttpPut], [HttpDelete] — დღესვე ყველას დავწერთ.
→ 5Action
მეხუთე: თავად მეთოდი. Controller-ის მეთოდს Action ჰქვია. IActionResult ნიშნავს: ვაბრუნებთ პასუხს სტატუს კოდით. Ok — ეს 200-ია.

9Controller-ებს Program.cs-ში ორი ხაზი სჭირდება

⏱ 0:23 · 3 წთ
Minimal API-ში endpoint-ს პირდაპირ Program.cs-ში ვწერდით. Controller-ებს კი Program.cs-ში მხოლოდ ორი ხაზი სჭირდება — დანარჩენი ცალკე ფაილებშია.
→ 1AddControllers
პირველი: AddControllers — „ჩემს პროექტში Controller-ები გამოიყენება“. ამით ვარეგისტრირებთ.
→ 2MapControllers
მეორე: MapControllers — ASP.NET Core პროექტში ყველა Controller-ს პოულობს, თითოეულის [Route]-ს კითხულობს და მისამართებს აბამს.
Controllers შაბლონით შექმნილ პროექტში ეს ორი ხაზი უკვე წერია — ხელით არაფერი გვიწერია.
→ 3დაგავიწყდა?
თუ ოდესმე ხელით დაამატებთ Controller-ებს Minimal API პროექტში და ეს ხაზები დაგავიწყდებათ — ყველაფერზე 404 მიიღებთ.

11Minimal API vs Controller

⏱ 0:29 · 4 წთ
შევაჯამოთ განსხვავებები ერთ ცხრილში.
→ 1სად წერია
Minimal — Program.cs-ში ან იქ, სადაც შენ გადაწყვეტ. Controller — ცალკე კლასებში, Controllers ფოლდერში.
→ 2როგორ იწერება
Minimal — ფუნქციით. Controller — კლასით, მეთოდებით და ატრიბუტებით.
→ 3სტრუქტურა
ეს მთავარი განსხვავებაა: Controller-ს მზა წესი აქვს. ნებისმიერ კომპანიაში გახსნით პროექტს და იცით, სად რა იქნება.
→ 4კოდი
Minimal-ში კოდი ნაკლებია.
→ 5სიჩქარე
Minimal ოდნავ უფრო მსუბუქია. მაგრამ ჩვენი პროექტებისთვის განსხვავებას ვერ იგრძნობთ.
→ 6სად შეხვდებით
Microsoft ახალ პროექტებში Minimal API-ს უფრო ხშირად გვთავაზობს. მაგრამ არსებული პროექტების დიდი ნაწილი Controller-ებითაა — სამსახურში ორივეს შეხვდებით.
→ 7დასკვნა
ორივე ერთი ASP.NET Core-ია, შეიძლება ერთ პროექტშიც კი იყოს. „რომელია უკეთესი?“ — არასწორი კითხვაა. სწორი კითხვაა: „ამ პროექტს რომელი უფრო შეეფერება?“
