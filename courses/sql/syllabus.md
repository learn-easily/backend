## საფუძვლები (2 ლექცია)

### 01. რატომ ბაზა — PostgreSQL და პირველი ცხრილი

**პრობლემა:** C#-ის პროექტში ყველაფერი ერთ `database.json`-შია: ძებნა მთელი ფაილის წაკითხვას ითხოვს, ორი ერთდროული ცვლილება ერთმანეთს შლის, ფაილი იზრდება. **თემები:** რა არის ბაზა და DBMS; რელაციური მოდელი — ცხრილი, სტრიქონი, სვეტი; SQL და მისი ნაწილები (DDL, DML); PostgreSQL vs სხვა ბაზები; Docker მოკლედ — რატომ და როგორ ვუშვებთ PostgreSQL-ს კონტეინერში; pgAdmin / DBeaver; ტიპები (`integer`, `bigint`, `numeric`, `text`, `varchar`, `boolean`, `date`, `timestamptz`, `uuid`); `CREATE TABLE` — `PRIMARY KEY`, `NOT NULL`, `DEFAULT`, `UNIQUE`, `CHECK` სვეტთან ერთად; `ALTER TABLE`, `DROP TABLE`. **საშინაო:** შენი სფეროს ბაზა — კატალოგის ცხრილი C#-ის კატალოგის კლასიდან: `uuid` id, სწორი ტიპები, `NOT NULL` / `CHECK`.

📚 აუხსნის, რატომ არ კმარა ფაილი და რას გვაძლევს ბაზა
📚 გაუშვებს PostgreSQL-ს Docker-ში და დაუკავშირდება კლიენტით
📚 შექმნის ცხრილს სწორი ტიპებით და შეზღუდვებით
🛠 ლიგა | ბაზა `league` · ცხრილები `clubs` (სახელი, ქალაქი, დაარსების წელი), `players` (სახელი, პოზიცია, დაბადების თარიღი, ნომერი)

### 02. CRUD — SELECT, INSERT, UPDATE, DELETE

**თემები:** `INSERT` (რამდენიმე სტრიქონი ერთად, `RETURNING`); `SELECT` — `WHERE`, `ORDER BY`, `LIMIT` / `OFFSET`; `IN`, `BETWEEN`, `LIKE` / `ILIKE`, `IS NULL`; `UPDATE` და `DELETE` — და რატომ არის საშიში `WHERE`-ის გარეშე. **საშინაო:** კატალოგი შევსებული (15+ ჩანაწერი) და 5 მოთხოვნა — ფილტრი, დალაგება, ძებნა, გვერდები, განახლება.

📚 ჩაწერს, წაიკითხავს, შეცვლის და წაშლის მონაცემს
📚 გაფილტრავს და დაალაგებს შედეგს
📚 დაწერს გვერდებად ჩვენებას `LIMIT` / `OFFSET`-ით
🛠 ლიგა | კლუბების და მოთამაშეების შევსება · თავდამსხმელები 25 წლამდე · ძებნა სახელით · ნომრის შეცვლა

## ცხრილების დაპროექტება (2 ლექცია)

### 03. რელაციები — Foreign Key

**პრობლემა:** მოთამაშის ცხრილში კლუბის სახელი ტექსტად წერია — კლუბმა სახელი შეიცვალა და 25 სტრიქონი გასასწორებელია. **თემები:** `REFERENCES` (FK); 1–1, 1–N, N–N და შუალედური ცხრილი; `ON DELETE CASCADE` / `RESTRICT` / `SET NULL`; მონაცემის მთლიანობა; ER დიაგრამა. **საშინაო:** `users` (email, password_hash, role) და „შეკვეთა“ ხაზებით (`orders` → `order_items`) — FK-ებით და წაშლის სწორი ქცევით.

📚 დააკავშირებს ცხრილებს foreign key-ით
📚 გაარჩევს 1–1, 1–N და N–N კავშირებს და ააწყობს თითოეულს
📚 აირჩევს წაშლის სწორ ქცევას
🛠 ლიგა | `players.club_id` (1–N) · `stadiums` (1–1 კლუბთან) · `matches` — მასპინძელი და სტუმარი: ორი FK ერთ ცხრილზე · `goals` (მატჩი ↔ მოთამაშე)

### 04. ნორმალიზაცია

**პრობლემა:** ერთი დიდი ცხრილი „მატჩები და გოლები“ — განახლების, ჩასმის და წაშლის ანომალიები. **თემები:** ანომალიები; 1NF, 2NF, 3NF მაგალითებით; როდის ვარღვევთ ნორმალიზაციას შეგნებულად (ფასის „ფოტო“ შეკვეთაში); **enum → ცხრილი:** C#-ში კატეგორია enum იყო — კოდის შეცვლის გარეშე ახალს ვერ დაამატებ; როცა ადმინს მისი დამატება სჭირდება, ის ცხრილი ხდება, სტატუსი და როლი კი მნიშვნელობად რჩება; C#-ის კლასები → ცხრილები (`Entity.Id` → `uuid`, სია → FK). **საშინაო:** შენი სფეროს სრული სქემა 3NF-ში — კატეგორია ცხრილად, სტატუსი და როლი მნიშვნელობად — და ER დიაგრამა.

📚 იპოვის ანომალიებს ცუდად დაპროექტებულ ცხრილში
📚 დაშლის ცხრილს 3NF-მდე
📚 გაარჩევს, როდის რჩება მნიშვნელობა enum-ად და როდის ხდება ცხრილი
📚 გადაიყვანს C#-ის მოდელებს ცხრილებად
🛠 ლიგა | `positions` და `seasons` ცხრილები · `transfers` (მოთამაშე, საიდან, სად, თანხა, თარიღი)

## მოთხოვნები (2 ლექცია)

### 05. JOIN და UNION

**თემები:** რატომ JOIN; `INNER`, `LEFT`, `RIGHT`, `FULL JOIN`; რამდენიმე ცხრილის შეერთება; alias-ები; ერთი ცხრილის ორჯერ შეერთება (მასპინძელი და სტუმარი); `UNION` / `UNION ALL`. **საშინაო:** 4 მოთხოვნა JOIN-ით — „შეკვეთა“ მომხმარებლით და ხაზებით, ერთი `LEFT JOIN` („რაც არავის უყიდია / წაუღია“).

📚 გააერთიანებს რამდენიმე ცხრილის მონაცემს ერთ შედეგში
📚 გაარჩევს `INNER` და `LEFT JOIN`-ს და იცის, რომელი როდის
🛠 ლიგა | მატჩების სია ორივე კლუბის სახელით · გოლები მოთამაშით და კლუბით · მოთამაშეები, რომლებსაც გოლი არ გაუტანიათ

### 06. აგრეგაცია და subquery

**თემები:** `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`; `GROUP BY` და `HAVING` (vs `WHERE`); subquery `WHERE`-ში და `FROM`-ში; `EXISTS`, `IN`; CTE (`WITH`). **საშინაო:** C#-ის 5 LINQ ანგარიში — ახლა SQL-ით (`GROUP BY`, `HAVING`, subquery).

📚 დაითვლის ჯამებს და საშუალოებს ჯგუფების მიხედვით
📚 დაწერს subquery-ს და CTE-ს
🛠 ლიგა | **ტურნირის ცხრილი** (მოგება 3, ფრე 1, გოლების სხვაობა) · ბომბარდირები · კლუბები 10+ გოლით

## ბაზა Production-ში (1 ლექცია)

### 07. ინდექსები, ტრანზაქციები, View და window functions

**პრობლემა:** ძებნა 100 000 მოთამაშეში ნელია; ტრანსფერი ჩაიწერა, მოთამაშე კი ძველ კლუბში დარჩა. **თემები:** ინდექსი — რატომ, როდის და რა ფასი აქვს (`EXPLAIN` მოკლედ); ტრანზაქცია (`BEGIN` / `COMMIT` / `ROLLBACK`) და ACID; `VIEW`; window functions (`ROW_NUMBER`, `RANK`, `SUM() OVER`); `jsonb` მოკლედ; ფუნქცია, procedure და trigger — მიმოხილვა: რა არის და რატომ ვიყენებთ იშვიათად backend-ში. **საშინაო:** ინდექსი საძიებო სვეტზე, „შეკვეთის“ განთავსება ტრანზაქციით (შეკვეთა + ხაზები + მარაგი / ადგილი) და ერთი view ანგარიშისთვის.

📚 დაამატებს ინდექსს და დაინახავს განსხვავებას
📚 შეასრულებს რამდენიმე ცვლილებას ერთ ტრანზაქციაში
📚 გამოიყენებს view-ს და window function-ს ანგარიშისთვის
