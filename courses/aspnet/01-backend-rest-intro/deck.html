## ნაწილი 2 · რა არის API? მიმტანი, რომელიც Frontend-სა და Backend-ს აკავშირებს — ეს არის **API**.
API = მიმტანი

შეკვეთა მიდის — კერძი მოდის

სტუმარმა არ იცის, როგორ მზადდება კერძი — და არც სჭირდება.
სამზარეულო არ იცნობს სტუმარს — მხოლოდ შეკვეთას ხედავს.
### API = მიმტანი სტუმარს ხაჭაპური უნდა: 1. სტუმარი მიმტანს ეუბნება, მიმტანი შეკვეთას სამზარეულოში მიაქვს — ეს **მოთხოვნაა (Request)**. 2. სამზარეულო ამზადებს, მიმტანი კერძს უკან მოიტანს — ეს **პასუხია (Response)**. სტუმარმა არ იცის, როგორ მზადდება კერძი — და არც სჭირდება. სამზარეულო სტუმარს არ იცნობს — მხოლოდ შეკვეთას ხედავს.
მიმტანმა იცის, ვის მიუტანოს

ყოველ შეკვეთას — თავისი მზარეული

მიმტანი თვითონ არ ამზადებს — ის სწორ ადგილას მიაქვს შეკვეთა. API-შიც ასეა: ყოველ მოთხოვნას თავისი ადგილი აქვს.
### მიმტანმა იცის, ვის მიუტანოს სამზარეულოში ყველაფერს ერთი მზარეული არ აკეთებს: - „ხაჭაპური“ → თონე - „სალათი“ → ცივი კერძები - „ანგარიში“ → სალარო მიმტანი თვითონ არაფერს ამზადებს — მან იცის, რომელი თხოვნა სად წაიღოს. **API-შიც ასეა: ყოველ მოთხოვნას თავისი ადგილი აქვს.**
Endpoint

API შედგება Endpoint-ებისგან

Endpoint = მეთოდი + მისამართი ერთი კონკრეტული მიზნით. მოთხოვნა მოდის Endpoint-ზე → Endpoint Backend-ში შესაბამის ფუნქციას ააქტიურებს.
### API შედგება Endpoint-ებისგან API ერთი დიდი კარი არ არის — ეს ბევრი პატარა კარია. თითოეულს **Endpoint** ჰქვია: | Endpoint | რას აკეთებს | |---|---| | `GET /api/products` | პროდუქტების სია | | `GET /api/products/5` | ერთი პროდუქტი | | `POST /api/products` | ახალი პროდუქტი | **Endpoint = მეთოდი + მისამართი, ერთი კონკრეტული მიზნით.** მოთხოვნა მოდის Endpoint-ზე → Endpoint Backend-ში შესაბამის ფუნქციას ააქტიურებს. ```terms Endpoint — მეთოდი (GET, POST…) + მისამართი (/api/products), რომელიც Backend-ში ერთ კონკრეტულ ფუნქციას იძახებს ```

### რატომ არსებობს API? ერთი Backend — ბევრი კლიენტი ერთსა და იმავე API-ს იყენებს ვებ საიტიც, მობილური აპიც, სმარტ საათიც და სხვა კომპანიის სისტემაც. **ლოგიკა იწერება ერთხელ — და ყველა კლიენტი ერთსა და იმავე API-ს იყენებს.** ამიტომაა შენი ბალანსი ბანკის საიტზეც და აპლიკაციაშიც ერთნაირი: ორივე ერთ API-ს ეკითხება.

### ნაბიჯი 3 · პირველი endpoint Program.cs-ის შიგთავსს ვშლით და ვწერთ: ```csharp Program.cs var builder = WebApplication.CreateBuilder(args); var app = builder.Build(); var products = new List { new(1, "ლეპტოპი", 2400), new(2, "მაუსი", 45), }; app.MapGet("/api/products", () => products); app.Run(); record Product(int Id, string Name, decimal Price); ``` - **ხაზები 1–2** — აპლიკაციის შექმნა. ასე ყოველთვის იწყება. - **მონაცემი** — ბაზა ჯერ არ გვაქვს, ამიტომ უბრალო სიას ვიყენებთ. `record Product` — მოკლე ჩანაწერი: Id, Name, Price. - **`app.MapGet`** — ჩვენი პირველი endpoint: GET მოთხოვნა ამ მისამართზე → დააბრუნე სია. - **`app.Run()`** — სერვერი იწყებს მოთხოვნების მიღებას.
