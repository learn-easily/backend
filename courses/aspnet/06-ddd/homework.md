# ჩემი LMS: პირველი საუბრისთვის მზადება

საშინაო · შენი LMS

## მოთხოვნები

- **ხედვა** 3–5 წინადადებით: ვინ იყენებს LMS-ს, რა პრობლემას ხსნის და რა **არ** შედის მასში
- **ლექსიკონი**: 10 ტერმინი. თითოს ერთი წინადადებით განმარტება ბიზნესის ენაზე და ინგლისური სახელი, რომელიც კოდში იქნება
- ლექსიკონში მინიმუმ **2 სიტყვა**, რომელიც LB-ზე ან აკადემიაში ორი მნიშვნელობით გამოიყენება, და შენი გადაწყვეტილება: რომელ სიტყვას რა ჰქვია
- **12 კითხვა** დირექტორისთვის, დაჯგუფებული ტექნიკის მიხედვით (მაგალითი · მერე? · ყოველთვის? · ვინ? · რატომ?)

## ✓ მზადაა, როცა

ლექსიკონში არც ერთი განმარტება ტექნიკურ სიტყვას არ შეიცავს (ცხრილი, Controller, ბაზა), და ყოველ კითხვაზე დირექტორს შეუძლია კონკრეტული მაგალითით უპასუხოს

## ⭐ ბონუსი

- 3 user story, თითოს 2–3 მიღების კრიტერიუმით
- ერთ user story-ს მიუწერე, კოდში რა გახდება: class, endpoint, შემოწმება

## ამოხსნა

ეს ერთ-ერთი შესაძლო ვარიანტია: შენი ლექსიკონი და კითხვები შეიძლება სხვანაირი იყოს. მთავარია, ყოველ სიტყვას ერთი მნიშვნელობა ჰქონდეს.

```markdown ლექსიკონი (ნაწილი) !
კურსი (Course) — სასწავლო პროგრამა: რას ვასწავლით (მაგ. „ASP.NET Web API“)
ჯგუფი (Group) — კონკრეტული სტუდენტები, რომლებიც კურსს ერთად გადიან
ჩარიცხვა (Enrollment) — სტუდენტის მიღება კონკრეტულ ჯგუფში
ლექცია (Lecture) — ჯგუფის ერთი შეხვედრა განრიგში, თარიღით
დასწრება (Attendance) — სტუდენტი ლექციაზე იყო, დააგვიანა თუ გააცდინა
გაცდენა (Absence) — არ მოვიდა ან 15 წუთზე მეტი დააგვიანა
დავალება (Assignment) — ამოცანა, რომელსაც ლექტორი ჯგუფს აძლევს დედლაინით
ნამუშევარი (Submission) — სტუდენტის ჩაბარებული ფაილი კონკრეტულ დავალებაზე
შეფასება (Grade) — ლექტორის ქულა ნამუშევარზე, მთელი რიცხვი 1-დან 12-მდე
დედლაინი (Deadline) — თარიღი, რომლის შემდეგაც ნამუშევარი აღარ მიიღება
```

**ხედვა (მაგალითი):** LMS აკადემიის სასწავლო ცხოვრებას ერთ ადგილას აგროვებს. მენეჯერი ქმნის კურსებს და ჯგუფებს და რიცხავს სტუდენტებს. ლექტორი ატარებს ლექციებს, აღრიცხავს დასწრებას და აფასებს ნამუშევრებს. სტუდენტი ხედავს განრიგს, აბარებს დავალებებს და ხედავს თავის შეფასებებს. გადახდები და ხელშეკრულებები LMS-ში **არ** შედის.

**ორმნიშვნელოვანი სიტყვები:** „დავალება“ ორად გაიყო: **Assignment** (ამოცანა) და **Submission** (ნამუშევარი). „კურსი“ და „ჯგუფი“ ცალ-ცალკე ცნებებია: „კურსზე ჩარიცხვა“ სინამდვილეში **ჯგუფში** ჩარიცხვაა.

**კითხვები (ნაწილი):**

- *მაგალითი:* ბოლოს როდის ჩააბარა ვინმემ დავალება დედლაინის შემდეგ? რა ქენით?
- *მერე?* ლექტორმა ნამუშევარი შეაფასა. მერე რა ხდება? სტუდენტი რას ხედავს?
- *ყოველთვის?* ჯგუფში ყოველთვის ერთი ლექტორია?
- *ვინ?* ვინ რიცხავს სტუდენტს ჯგუფში? ვინ რიცხავს მას ჯგუფიდან?
- *რატომ?* რატომ უნდა ჩანდეს ჯგუფის საშუალო ქულა? ვინ უყურებს მას?

```check

? რატომ გავყავით „დავალება“ ორ ტერმინად?
= ამოცანა (ერთი ჯგუფისთვის, დედლაინით) და ნამუშევარი (ერთი სტუდენტის ფაილი, შეფასებით) სხვადასხვა რამაა: ერთ დავალებას ბევრი ნამუშევარი აქვს
```
