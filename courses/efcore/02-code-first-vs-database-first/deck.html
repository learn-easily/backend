### Code First vs Database First | კრიტერიუმი | 🟢 Code First | 🟠 Database First | |---|---|---| | ჭეშმარიტების წყარო | C# კლასები | ბაზის სქემა | | პირველი ნაბიჯი | ვწერთ კლასს | ბაზა უკვე არსებობს | | ცვლილების გზა | კლასი → `Add-Migration` → `Update-Database` | SSMS-ში `ALTER` → `Scaffold … -Force` | | ცვლილებების ისტორია | მიგრაციები, Git-ში | ბაზაში / DBA-სთან | | ვინ წერს SQL-ს | EF Core (მიგრაცია) | ადამიანი (SSMS) |
ძლიერი და სუსტი მხარეები

ყველას თავისი ფასი აქვს

🟢Code First

  • ყველაფერი C#-შია, ერთ ადგილას
  • ბაზის ისტორია — მიგრაციები Git-ში
  • ბაზა ერთი ბრძანებით იქმნება ნებისმიერ კომპიუტერზე
  • მიგრაციებს დისციპლინა სჭირდება
  • ცუდი კლასი = ცუდი ცხრილი — SQL-ის ცოდნა მაინც საჭიროა

🟠Database First

  • არსებულ ბაზაზე მუშაობა — წამებში
  • ბაზის სრული კონტროლი: DBA, index, trigger, procedure
  • კლასებს ხელით არ ვწერთ
  • ცვლილება ორ ადგილას: ბაზაში + ხელახალი Scaffold
  • ხელახალი Scaffold შლის ხელით ჩამატებულ კოდს
### ძლიერი და სუსტი მხარეები 🟢 **Code First** - ✓ ყველაფერი C#-შია, ერთ ადგილას - ✓ ბაზის ისტორია — მიგრაციები Git-ში - ✓ ბაზა ერთი ბრძანებით იქმნება ნებისმიერ კომპიუტერზე - ✗ მიგრაციებს დისციპლინა სჭირდება - ✗ ცუდი კლასი = ცუდი ცხრილი — SQL-ის ცოდნა მაინც საჭიროა 🟠 **Database First** - ✓ არსებულ, დიდ ბაზასთან წამებში იწყებ მუშაობას - ✓ ბაზას შეუძლია მართოს DBA-მ, SQL-ის სრული ძალით - ✗ ორ ადგილას მუშაობ: SSMS და კოდი - ✗ ცვლილებების ისტორია კოდში არ ჩანს „საუკეთესო“ არ არსებობს — ორივეს თავისი ფასი აქვს.
