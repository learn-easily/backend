### null — ჩანაწერი არ არსებობს `Find` და `FirstOrDefault` აბრუნებს `TodoItem?`-ს — კითხვის ნიშანი ნიშნავს: **შეიძლება `null` იყოს**. თუ ასეთი Id არ არსებობს, ობიექტი არ გვაქვს. ```csharp 💥 ასე — არა var item = db.TodoItems.Find(99); Console.WriteLine(item.Title); // NullReferenceException ``` Id = 99 ბაზაში არ არის → `item` არის `null` → `null`-ის `.Title`-ს ვერ წაიკითხავ და პროგრამა ვარდება. Visual Studio ამას წინასწარ გეუბნება: `item`-ს ყვითელი ტალღა უჩნდება (*Dereference of a possibly null reference*). ```csharp ✅ ასე — კი var item = db.TodoItems.Find(99); if (item is null) { Console.WriteLine("ვერ მოიძებნა"); return; } Console.WriteLine(item.Title); // აქ item უკვე null ვერ იქნება ``` **წესი:** `Find` / `FirstOrDefault`-ის შემდეგ ჯერ `null`-ს ამოწმებ, მერე იყენებ. | მეთოდი | ვერ იპოვა → | |---|---| | `First(…)` | **შეცდომა**: `InvalidOperationException: Sequence contains no elements` | | `FirstOrDefault(…)` | `null` | `First`-ს მხოლოდ მაშინ იყენებენ, როცა ჩანაწერი **აუცილებლად** უნდა არსებობდეს. მომხმარებელი Id-ს ხელით წერს — შეიძლება შეეშალოს, ამიტომ ჩვენ `FirstOrDefault` / `Find` + `null`-ის შემოწმება გვჭირდება.

## ნაწილი 3 · იპოვე, შეცვალე, შეინახე წაკითხვა ვიცით. ახლა — განახლება და წაშლა. ორივე ერთნაირად იწყება: **ჯერ ჩანაწერს ვპოულობთ**.
U · Update

განახლება — Update() არ გვჭირდება

using var db = new DataContext(); var item = db.TodoItems.Find(2); if (item is null) return; item.IsDone = true; db.SaveChanges();
1. იპოვე — SELECT … WHERE Id = 2
2. შეცვალე — ჩვეულებრივი C#, ბაზას ჯერ არ ეხება
3. SaveChanges — ახლა მიდის:
UPDATE TodoItems SET IsDone = 1 WHERE Id = 2
მხოლოდ IsDone! Title-ს არ ეხება. Update() არსად დაგვიწერია — საიდან გაიგო? 🤔
### განახლება: იპოვე → შეცვალე → SaveChanges ```csharp Program.cs using var db = new DataContext(); var item = db.TodoItems.Find(2); if (item is null) return; item.IsDone = true; db.SaveChanges(); ``` 1. **იპოვე** — `Find(2)` → `SELECT … WHERE Id = 2`. (`null`-ის შემოწმება აქაც აუცილებელია.) 2. **შეცვალე** — `item.IsDone = true` ჩვეულებრივი C#-ია. ბაზას ჯერ არ ეხება. 3. **`SaveChanges()`** — ახლა მიდის: ```sql UPDATE TodoItems SET IsDone = 1 WHERE Id = 2 ``` ორ რამეს დააკვირდი: - `Update()` მეთოდი **არსად** დაგვიწერია. - SQL-ში მხოლოდ **`IsDone`** წერია — `Title`-ს და `CreatedAt`-ს არ ეხება, რადგან ისინი არ შეცვლილა. საიდან გაიგო EF Core-მა, რომ სწორედ `IsDone` შევცვალეთ? ამაზეა შემდეგი სლაიდი. ```note `db.TodoItems.Update(item)` მეთოდი არსებობს, მაგრამ აქ საჭირო არ არის: ის ყველა სვეტს „შეცვლილად“ მონიშნავს და `UPDATE` ყველა სვეტზე წავა. გვჭირდება მაშინ, როცა ობიექტი EF Core-ს **არ წაუკითხავს** (მაგალითად, სხვაგან შეიქმნა). ჩვენ ჯერ ვპოულობთ — ამიტომ საკმარისია შეცვლა და `SaveChanges`. ```

### Change Tracker — EF Core-ის მეხსიერება DataContext-ს შიგნით აქვს **Change Tracker** („ცვლილებების მეთვალყურე“). ის ასე მუშაობს: 1. **`Find(2)`** — ჩანაწერი მოვიდა ბაზიდან. ობიექტს რომ გვაძლევს, EF Core თავისთვის იმახსოვრებს მის **„ფოტოს“**: `Title = "საშინაოს დაწერა"`, `IsDone = false`. 2. **`item.IsDone = true`** — ჩვენ ობიექტს ვცვლით. ფოტო იგივე რჩება. 3. **`SaveChanges()`** — EF Core ყველა ობიექტს თავის ფოტოს ადარებს: `Title` იგივეა, `IsDone` შეიცვალა → წერს `UPDATE … SET IsDone = 1 WHERE Id = 2`. ამიტომ არ გვჭირდება `Update()`: EF Core-მა თვითონ იცის, რა შეიცვალა. და ამიტომაა SQL-ში მხოლოდ ერთი სვეტი. ```terms Change Tracker — DataContext-ის ნაწილი, რომელიც წაკითხულ და დამატებულ ობიექტებს თვალს ადევნებს და SaveChanges-ის დროს ითვლის, რა უნდა გაიგზავნოს ბაზაში Snapshot („ფოტო“) — ობიექტის მნიშვნელობების ასლი წაკითხვის მომენტში ``` ```prompt Change Tracker-ის ახსნა ვსწავლობ EF Core-ს. ამიხსენი Change Tracker მარტივად, მაგალითით: რა ხდება Find-ის, property-ს შეცვლის და SaveChanges-ის დროს? რას ნიშნავს Entity State (Added, Unchanged, Modified, Deleted)? და რა არის AsNoTracking — როდის იყენებენ? ქართულად. ```
