### DTO — Data Transfer Object **DTO** არის კლასი, რომელიც მხოლოდ მონაცემის გადასატანად არსებობს. მასში ლოგიკა არ არის — მხოლოდ ველები. წესი მარტივია: **Entity შიგნით რჩება, გარეთ DTO გადის**. ბანკის მაგალითი: - 📝 **Request DTO** — ანგარიშის გასახსნელი განაცხადი. მხოლოდ ის ველები, რაც შენ უნდა შეავსო: სახელი, პირადი ნომერი, ტელეფონი. ანგარიშის ნომერს არ წერ — ბანკი გაძლევს. - 🗄️ **Entity** — ბანკის შიდა ბაზა: ყველაფერი, რაც ბანკმა იცის. რისკის შეფასება, ვინ გახსნა, როდის. გარედან ამას არავინ ხედავს. - 🧾 **Response DTO** — ამონაწერი, რომელსაც ბანკი გაძლევს: მხოლოდ ის, რაც შენ გჭირდება. ერთი ანგარიში — სამი ფორმა. ზუსტად იგივეს ვაკეთებთ პროდუქტისთვის: `CreateProductRequest` → `Product` → `ProductResponse`. ```terms DTO — Data Transfer Object: კლასი მხოლოდ მონაცემის გადასატანად, ლოგიკის გარეშე Request DTO — რასაც კლიენტი გვიგზავნის (კლიენტი → სერვერი) Response DTO — რასაც კლიენტს ვაჩვენებთ (სერვერი → კლიენტი) ``` ```prompt DTO-ს სხვა მაგალითით ახსნა მე ვსწავლობ ASP.NET Core Web API-ს. ვიცი Controller, IActionResult და CRUD, მაგრამ DTO ახალია ჩემთვის. ამიხსენი, რა არის DTO და რატომ არ უნდა დავაბრუნო Entity პირდაპირ. გამოიყენე ცხოვრებისეული მაგალითი (არა ბანკის) და მერე C#-ის პატარა მაგალითი Product-ზე: CreateProductRequest, Product, ProductResponse. ახსნა ქართულად, მარტივად. ```

### DTO-ები კოდში — `record` პროექტში ვქმნით ფოლდერს `Dtos` და მასში სამ DTO-ს (რეალურად — თითო ფაილი თითოზე): ```csharp Dtos/ public record CreateProductRequest( string Name, decimal Price, decimal CostPrice); public record UpdateProductRequest( string Name, decimal Price, decimal CostPrice); public record ProductResponse( int Id, string Name, decimal Price); ``` - **CreateProductRequest** — შექმნისას: `Id`-ს და `CreatedAt`-ის გარეშე. - **UpdateProductRequest** — განახლებისას: `Id`-ს გარეშე, რადგან `Id` მისამართიდან მოდის. - **ProductResponse** — პასუხში: `CostPrice`-ის და `CreatedAt`-ის გარეშე. **რატომ `record`?** DTO-სთვის `class`-იც გამოდგება, მაგრამ `record` ერთ ხაზში აკეთებს ყველაფერს: ფრჩხილებში ჩამოწერილი პარამეტრები ავტომატურად ხდება property-ები და constructor. JSON-ში `Name` ისევ `"name"`-ად გადაიქცევა, როგორც ადრე. **სახელები:** `…Request` — რაც შემოდის, `…Response` — რაც გადის. ასე ფაილის სახელიდანვე ჩანს, რისთვის არის კლასი. ```note `CreateProductRequest` და `UpdateProductRequest` ახლა ერთნაირია — მაშ, რატომ ცალკე? იმიტომ, რომ ხვალ შეიძლება განსხვავდებოდეს: მაგალითად, განახლებისას შესყიდვის ფასის შეცვლა აიკრძალოს. ცალკე კლასით ერთის შეცვლა მეორეს არ დააზიანებს. ``` ```prompt record vs class ამიხსენი C#-ში record-ის და class-ის განსხვავება მარტივად. მაგალითად აიღე: public record ProductResponse(int Id, string Name, decimal Price); რა იქმნება ავტომატურად ამ ერთი ხაზით? რატომ ჯობია record DTO-სთვის? ახსნა ქართულად, დამწყებისთვის. ```

### ProductMapper — mapping ერთ ადგილას ვქმნით ფოლდერს `Mappers` და მასში კლასს `ProductMapper`: ```csharp Mappers/ProductMapper.cs public static class ProductMapper { public static ProductResponse ToResponse(this Product product) { return new ProductResponse(product.Id, product.Name, product.Price); } public static Product ToEntity(this CreateProductRequest request) { return new Product { Name = request.Name, Price = request.Price, CostPrice = request.CostPrice }; } public static void UpdateFrom(this Product product, UpdateProductRequest request) { product.Name = request.Name; product.Price = request.Price; product.CostPrice = request.CostPrice; } } ``` - **`static class`** — მისი ობიექტის შექმნა არ გვჭირდება, მხოლოდ მეთოდები. - **`ToResponse`** — `Product` → `ProductResponse`. ზუსტად ის ხაზი, რომელიც სამ ადგილას გვქონდა. - **`ToEntity`** — Request → ახალი `Product`. `Id`-ს და `CreatedAt`-ს აქ **არ** ვავსებთ — ეს სერვერის გადაწყვეტილებაა და Controller-ში რჩება. - **`UpdateFrom`** — ახალს არ ქმნის, **არსებულ** `Product`-ს ცვლის. ამიტომ `void`-ია. #### `this` პარამეტრის წინ — extension method `this` საშუალებას გვაძლევს მეთოდი ისე გამოვიძახოთ, თითქოს ის `Product`-ს ეკუთვნის: ```csharp product.ToResponse(); // extension method — ასე ვწერთ ProductMapper.ToResponse(product); // იგივეა, უბრალოდ ნაკლებად იკითხება ``` ორივე ხაზი ზუსტად ერთსა და იმავეს აკეთებს. extension method-ისთვის კლასიც და მეთოდიც `static` უნდა იყოს. LINQ-ის `Select` და `Where` ზუსტად ასეთი extension method-ებია. ```terms Extension method — static მეთოდი, რომლის პირველ პარამეტრს this უწერია; იძახება ისე, თითქოს იმ ტიპს ეკუთვნის: product.ToResponse() ``` ```prompt extension method-ის გაგება ამიხსენი C#-ის extension method მარტივად. მაგალითი: public static ProductResponse ToResponse(this Product product) { ... } რატომ შეიძლება product.ToResponse() დავწერო, თუ ეს მეთოდი Product კლასში არ არის? რატომ უნდა იყოს კლასი static? მომიყევი, რომელი ცნობილი extension method-ები მაქვს უკვე გამოყენებული (LINQ). ახსნა ქართულად. ```
