## ნაწილი 1 · virtual და override მშობელი ნებას რთავს — შვილი ცვლის.
⌨️ ერთად ვწერთ · Character.cs · Warrior.cs

მშობელი ნებას რთავს, შვილი ცვლის

// Character.cs public virtual int Attack() { return RollDamage(5, 15); } // Warrior.cs — Smash()-ის ნაცვლად public override int Attack() { return RollDamage(15, 25); }
virtual — „შვილს შეუძლია ეს მეთოდი შეცვალოს“
override — „ვცვლი“. სახელი, პარამეტრები, ტიპი — ზუსტად იგივე
Smash() აღარ გვჭირდება — მეომრის შეტევა ახლა Attack()-ია
Mage-იც იგივენაირად: Fireball() → override Attack()
### ⌨️ virtual და override: მშობელი ნებას რთავს, შვილი ცვლის ```csharp Character.cs + Warrior.cs // Character.cs public virtual int Attack() { return RollDamage(5, 15); } // Warrior.cs — Smash()-ის ნაცვლად public override int Attack() { return RollDamage(15, 25); } ``` - `virtual` მშობელში — „შვილს შეუძლია ეს მეთოდი შეცვალოს“. - `override` შვილში — „ვცვლი“. სახელი, პარამეტრები და დასაბრუნებელი ტიპი ზუსტად იგივეა. - `Smash()` აღარ გვჭირდება — მეომრის შეტევა ახლა `Attack()`-ია. Mage-იც იგივენაირად: `Fireball()` → `override Attack()` (შემდეგ ნაწილში). ```terms virtual — მშობლის მეთოდი, რომლის შეცვლაც შვილს შეუძლია override — შვილის საკუთარი ვერსია virtual მეთოდისა ```

📚overload — გადატვირთვა

ერთ კლასში, ერთი სახელი, სხვადასხვა პარამეტრები: Student(), Student(string) · Console.WriteLine(5), WriteLine("ა")

overload-ს უკვე იცნობთ — რამდენიმე კონსტრუქტორი 05 ლექციიდან
### 💡 override vs overload - **override** (შეცვლა) — შვილი მშობლის `virtual` მეთოდს იგივე სახელითა და პარამეტრებით ცვლის. რომელი ვერსია შესრულდება — ობიექტი წყვეტს. - **overload** (გადატვირთვა) — ერთ კლასში ერთი სახელი, სხვადასხვა პარამეტრები. ამას უკვე იცნობთ: რამდენიმე კონსტრუქტორი — `Student()`, `Student(string)`. `Console.WriteLine`-საც ბევრი ვერსია აქვს — `WriteLine(5)`, `WriteLine("ა")`. ```terms override — შვილის ვერსია მშობლის virtual მეთოდისა (იგივე პარამეტრები) overload — ერთი სახელი, სხვადასხვა პარამეტრები ერთ კლასში object — C#-ის ყველა კლასის საერთო წინაპარი ```

## შეჯამება · ერთი ბრძანება — ბევრი ქცევა **დაიმახსოვრე:** 1. **პოლიმორფიზმი** — ერთი გამოძახება სხვადასხვა ობიექტზე სხვადასხვანაირად მუშაობს. 2. `virtual` მშობელში — ნებართვა; `override` შვილში — საკუთარი ვერსია. ყოველთვის წყვილად. 3. რისი გამოძახება შეიძლება — ცვლადის ტიპი წყვეტს; რომელი ვერსია შესრულდება — ობიექტის ტიპი. 4. `base.Method()` — მშობლის ვერსია შვილის შიგნიდან. 5. ყველა კლასი `object`-ის შვილია; `override ToString()` — ობიექტი ტექსტად. 6. override (შეცვლა, იგივე პარამეტრები) ≠ overload (ერთი სახელი, სხვა პარამეტრები). ### ⏭️ შემდეგ 🎨 აბსტრაქცია: `abstract` კლასი და `interface` — მკურნალები, ოქრო და საბოლოო ბრძოლა.
