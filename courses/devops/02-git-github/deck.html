Git შენს კომპიუტერზე მუშაობს — ინტერნეტი არ სჭირდება

🐧 2005 წლიდან

შექმნა ლინუს ტორვალდსმა Linux-ის ბირთვისთვის. დღეს — სტანდარტი

### Git = Save Point-ები შენი პროექტისთვის თამაშში „Save Point“ გახსოვს? სანამ ბოსს შეებრძოლები, ინახავ. თუ წააგე — იქიდან აგრძელებ, თავიდან არ იწყებ. **Git ზუსტად ამას აკეთებს კოდისთვის:** - 📸 შენს ბრძანებაზე ინახავს მთელი პროექტის „ფოტოს“ — და იმახსოვრებს, **ვინ, როდის და რა** შეცვალა. - ↩ თუ რაღაც გატეხე, ნებისმიერ წინა „ფოტოზე“ დაბრუნდები. - 💻 მუშაობს **შენს კომპიუტერზე**, ინტერნეტის გარეშეც. - 🐧 შექმნა **ლინუს ტორვალდსმა** 2005 წელს Linux-ის ბირთვის განვითარებისთვის. დღეს პრაქტიკულად ყველა პროექტი Git-ს იყენებს. ```terms Version Control System (VCS) — ვერსიების კონტროლის სისტემა: პროგრამა, რომელიც ფაილების ცვლილებების ისტორიას ინახავს ```

### ცნება 1 · რეპოზიტორია **რეპოზიტორია (repository, „რეპო“)** — ჩვეულებრივი საქაღალდე, რომელშიც Git-მა ისტორიის შენახვა დაიწყო. ```console Git Bash $ git init Initialized empty Git repository in ~/my-portfolio/.git/ ``` `git init` საქაღალდეში ქმნის დამალულ `.git` საქაღალდეს. მასში ინახება **მთელი ისტორია**: ყველა „ფოტო“, ყველა branch, პარამეტრები. ```plain 📁 my-portfolio ├ 📁 .git ← ისტორია აქ ცხოვრობს ├ 📄 index.html └ 📄 style.css ``` ```warn `.git` საქაღალდეს ხელით არ ვეხებით. თუ წაშლი — საქაღალდე ჩვეულებრივ საქაღალდედ იქცევა და მთელი ისტორია ქრება. ```
ცნება 2 · როგორ ვინახავთ

სამი ზონა: რედაქტირება → მზადება → ისტორია

📮 ანალოგია: add = ნივთს ყუთში დებ. commit = ყუთს ლუქავ, აწერ წარწერას და აგზავნი.
### ცნება 2 · სამი ზონა Git-ში ფაილი სამ „ზონას“ გადის: | ზონა | რა არის | როგორ ხვდება აქ | |---|---|---| | 📝 **Working Directory** | შენი საქაღალდე, სადაც ფაილებს არედაქტირებ | უბრალოდ ცვლი ფაილს | | 📦 **Staging Area** | „რა შევინახო ამჯერად“ — მომზადებული ცვლილებები | `git add` | | 🗃️ **Repository** | ისტორია `.git`-ში | `git commit` | რატომ გვჭირდება შუალედური ზონა? შეიძლება 5 ფაილი შეცვალე, მაგრამ ერთ „ფოტოში“ მხოლოდ 2 გინდა — ის, რაც ერთ ამოცანას ეხება. Staging-ით შენ წყვეტ, რა მოხვდეს შენახვაში. 📮 **ანალოგია — ამანათი:** `git add` = ნივთს ყუთში დებ (ჯერ კიდევ შეგიძლია ამოიღო). `git commit` = ყუთს ლუქავ, აწერ წარწერას და აგზავნი — ის უკვე ისტორიაშია. ```bash git add index.html # ერთი ფაილი staging-ში git add . # ყველა შეცვლილი ფაილი git commit -m "Add home page" ```

### ცნება 3 · Commit — ისტორიის ერთი ფოტო **Commit** — პროექტის შენახული მდგომარეობა. ყოველ commit-ს აქვს: - **hash** — უნიკალური იდენტიფიკატორი, მაგ. `a3f9c21` (სრულად 40 სიმბოლოა, ჩვეულებრივ პირველ 7-ს ვიყენებთ); - **ავტორი** და **თარიღი**; - **მესიჯი** — რა გაკეთდა; - **მშობელი** — წინა commit-ის hash. ასე იქმნება ისტორიის ჯაჭვი. **კარგი მესიჯი** მომავალი შენთვის იწერება — ექვსი თვის შემდეგ უნდა მიხვდე, რა გააკეთე: | ✓ კარგი | ✗ ცუდი | |---|---| | `Add contact section` | `fix` | | `Fix broken link on projects page` | `asdfgh` | | `Update profile photo` | `ცვლილებები` | წესი: **რა გააკეთე**, ბრძანებითი ფორმით, მოკლედ: „Add…“, „Fix…“, „Update…“, „Remove…“. ```tip ერთი commit = ერთი აზრი. „დავამატე კონტაქტები და შევცვალე ფერები და გავასწორე ბმული“ — ეს სამი commit-ია. ```
