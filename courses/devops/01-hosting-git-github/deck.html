## რა არის DevOps? ### რატომ არსებობს DevOps წარმოიდგინე ორი გუნდი: - 👩‍💻 **Dev (Development)** — დეველოპერები. წერენ კოდს და მათ ლეპტოპზე ყველაფერი მუშაობს. - 🛠️ **Ops (Operations)** — ადმინისტრატორები. მართავენ სერვერებს, სადაც საიტი რეალურად ცხოვრობს. ძველად მათ შორის **კედელი** იდგა: დეველოპერი კოდს „კედელს იქით გადააგდებდა“, ადმინისტრატორი კი ცდილობდა, ის სერვერზე როგორმე გაეშვა. შედეგი: - 🐢 ახალი ვერსია თვეში ერთხელ გამოდიოდა — ხელით და შიშით. - 🔥 რამე თუ გაფუჭდა, იწყებოდა: „ჩემთან მუშაობს!“ — „სერვერზე არ მუშაობს!“ - 🌙 სერვერი ღამით ჩავარდებოდა და დილამდე ამას ვერავინ ამჩნევდა. **DevOps = Dev + Ops.** კედელი ქრება: კოდი დეველოპერის ლეპტოპიდან მომხმარებლამდე **ერთი, ავტომატური გზით** მიდის, და ამ გზას ერთი გუნდი აკონტროლებს.
DevOps ციკლი

DevOps = კოდის უწყვეტი გზა ♾️

DevOps — ერთი პროგრამა კი არა, მიდგომაა: ყველაფერი, რაც კოდს მომხმარებლამდე მიიყვანს, ავტომატური, სწრაფი და კონტროლირებადია. და ციკლი არ მთავრდება.
### DevOps ციკლი — კოდის უწყვეტი გზა ♾️ DevOps ხშირად უსასრულობის ნიშნით (♾️) იხატება: მარცხენა ნახევარი **Dev**-ია, მარჯვენა — **Ops**. ციკლი არასოდეს მთავრდება — მონიტორინგში დანახული პრობლემა შემდეგი გეგმის ნაწილი ხდება. | ეტაპი | რა ხდება | ამ კურსში | |---|---|---| | 📝 Plan | ვწყვეტთ, რას ვაკეთებთ | — | | 💻 Code | ვწერთ კოდს და ვინახავთ Git-ში | Git/GitHub — **დღეს** | | ⚙️ Build | კოდიდან გასაშვებ ვერსიას ვაწყობთ | GitHub Actions | | 🧪 Test | ავტომატურად ვამოწმებთ, ხომ არაფერი გატყდა | GitHub Actions | | 📦 Release | ვამზადებთ ვერსიას გასაშვებად | სრული CI/CD | | 🚀 Deploy | ვერსია სერვერზე მიდის | GitHub Pages, Droplet | | 🖥️ Operate | სერვერი მუშაობს და ვუვლით | Linux + SSH | | 📈 Monitor | ვაკვირდებით: სწრაფია? ჩავარდა? | მონიტორინგი | **DevOps ერთი პროგრამა არ არის** — ეს მიდგომაა: ყველაფერი, რაც კოდს მომხმარებლამდე მიიყვანს, ავტომატური, სწრაფი და კონტროლირებადი უნდა იყოს. Git, GitHub Actions, Linux, Nginx, Docker — ეს ის ინსტრუმენტებია, რომლითაც ამას ვაკეთებთ. ```terms DevOps — Development + Operations: მიდგომა, რომლითაც კოდი დეველოპერიდან მომხმარებლამდე სწრაფად, ავტომატურად და კონტროლირებადად მიდის Deploy (დეპლოი) — ახალი ვერსიის სერვერზე გაშვება, რომ მომხმარებელმა დაინახოს CI/CD — ავტომატური აწყობა, ტესტი და დეპლოი ყოველ ცვლილებაზე ```

### პრობლემა: „გახსენი, ჩემი საიტია!“ Angular-ის პროექტი გაუშვი (`ng serve`), ბრაუზერში `localhost:4200` ლამაზად იხსნება. ლინკი მეგობარს მესენჯერით გაუგზავნე — მასთან კი: **This site can't be reached**. რატომ? **`localhost` ნიშნავს „ეს კომპიუტერი“.** შენთან ეს შენი ლეპტოპია, მეგობართან — მისი ტელეფონი. მისი ტელეფონი შენს საიტს საკუთარ თავში ეძებს, და, ბუნებრივია, ვერ პოულობს. ```terms localhost — მისამართი, რომელიც ყოველთვის იმავე მოწყობილობას ნიშნავს, რომელზეც ბრაუზერი მუშაობს (IP: 127.0.0.1) ```

### სერვერი · დატა-ცენტრი · ჰოსტინგი - 🖥️ **სერვერი** — ჩვეულებრივი კომპიუტერი: პროცესორი, მეხსიერება, დისკი. ოღონდ ეკრანი და კლავიატურა არ აქვს, უფრო მძლავრია და არასოდეს ითიშება. სერვერების აბსოლუტური უმრავლესობა **Linux**-ზე მუშაობს — ამიტომ კურსში Linux-ს ვსწავლობთ. - 🏢 **დატა-ცენტრი** — შენობა ათასობით სერვერით: სარეზერვო ელექტროენერგია, გაგრილება, ძალიან სწრაფი ინტერნეტი, ფიზიკური დაცვა. - 🏠 **ჰოსტინგი** — სერვისი: კომპანია გაქირავებს სერვერს ან მის ნაწილს, სადაც შენი საიტი „იცხოვრებს“. ჰოსტინგის პროვაიდერები: **DigitalOcean** (ამ კურსის მთავარი), AWS, Azure, Google Cloud, Hetzner; სტატიკური საიტებისთვის — **GitHub Pages**, Cloudflare.

### DNS — სახელების და მისამართების საცავი ინტერნეტში კომპიუტერები ერთმანეთს **IP მისამართით** პოულობენ — მაგალითად `164.90.12.34`. ადამიანისთვის ციფრების დამახსოვრება რთულია, ამიტომ გვაქვს **დომენის სახელები**: `google.com`, `myportfolio.ge`. **DNS (Domain Name System)** — ინტერნეტის „კონტაქტების წიგნი“: საცავი, სადაც ყოველ **სახელს** მისი სერვერის **მისამართი** (IP) უწერია. | სახელი (დომენი) | მისამართი (IP) | |---|---| | `google.com` | `142.250.185.78` | | `facebook.com` | `157.240.1.35` | | `myportfolio.ge` | `164.90.12.34` | **როგორ მუშაობს:** 1. ① ბრაუზერი DNS-ს ეკითხება: „`myportfolio.ge` სად არის?“ 2. ② DNS წიგნში პოულობს და პასუხობს: „`164.90.12.34`“. 3. ③ ბრაუზერი ამ მისამართზე მიდის — სერვერთან. 📱 **ანალოგია — ტელეფონის კონტაქტები:** შენ ეძებ „დედა“-ს, ტელეფონი კი ნომერზე რეკავს. სახელს იმახსოვრებ შენ, ნომერს — ტელეფონი. ```note ეს „წიგნი“ თვითონ არ ივსება: როცა დომენს იყიდი, DNS-ში შენ ჩაწერ, რომ `myportfolio.ge` → შენი სერვერის IP. ამას კურსში თვითონ გავაკეთებთ. (ცხრილის IP-ები მაგალითისთვისაა.) ``` ```terms დომენი — საიტის სახელი, რომელსაც ადამიანი კრეფს: myportfolio.ge IP მისამართი — სერვერის ნომერი ინტერნეტში: 164.90.12.34 DNS — საცავი, სადაც დომენის სახელს მისი სერვერის IP უწერია ```
მოთხოვნის გზა — სრულად

რა ხდება, როცა აკრეფ myportfolio.ge?

### რა ხდება, როცა აკრეფ `myportfolio.ge`? 1. **DNS** — ბრაუზერმა სახელი იცის, მაგრამ ინტერნეტში კომპიუტრები **IP მისამართით** პოულობენ ერთმანეთს. DNS „სატელეფონო წიგნია“: `myportfolio.ge` → `164.90.12.34`. 2. **მოთხოვნა** — ბრაუზერი ამ IP-ზე აგზავნის HTTP მოთხოვნას: `GET /`. 3. **სერვერი** — იღებს მოთხოვნას და პოულობს შესაბამის ფაილს. 4. **პასუხი** — `200 OK` და HTML-ის შიგთავსი. 5. **დამატებითი მოთხოვნები** — ბრაუზერი HTML-ში ხედავს `style.css`-ს, `app.js`-ს, სურათებს და თითოეულს ცალკე ითხოვს. ერთი გვერდი = ათობით მოთხოვნა. ```note DNS-ს და დომენებს კურსში დეტალურად გავივლით. დღეს მთავარია სურათი: **სახელი → IP → სერვერი → ფაილი → პასუხი**. ``` ```terms IP მისამართი — მოწყობილობის ნომერი ინტერნეტში, მაგ. 164.90.12.34 DNS — სისტემა, რომელიც დომენის სახელს IP მისამართად თარგმნის ```

### ცნება 1 · რეპოზიტორია **რეპოზიტორია (repository, „რეპო“)** — ჩვეულებრივი საქაღალდე, რომელშიც Git-მა ისტორიის შენახვა დაიწყო. ```console Git Bash $ git init Initialized empty Git repository in ~/my-portfolio/.git/ ``` `git init` საქაღალდეში ქმნის დამალულ `.git` საქაღალდეს. მასში ინახება **მთელი ისტორია**: ყველა „ფოტო“, ყველა branch, პარამეტრები. ```plain 📁 my-portfolio ├ 📁 .git ← ისტორია აქ ცხოვრობს ├ 📄 index.html └ 📄 style.css ``` ```warn `.git` საქაღალდეს ხელით არ ვეხებით. თუ წაშლი — საქაღალდე ჩვეულებრივ საქაღალდედ იქცევა და მთელი ისტორია ქრება. ```
ცნება 2 · როგორ ვინახავთ

სამი ზონა: რედაქტირება → მზადება → ისტორია

📮 ანალოგია: add = ნივთს ყუთში დებ. commit = ყუთს ლუქავ, აწერ წარწერას და აგზავნი.
### ცნება 2 · სამი ზონა Git-ში ფაილი სამ „ზონას“ გადის: | ზონა | რა არის | როგორ ხვდება აქ | |---|---|---| | 📝 **Working Directory** | შენი საქაღალდე, სადაც ფაილებს არედაქტირებ | უბრალოდ ცვლი ფაილს | | 📦 **Staging Area** | „რა შევინახო ამჯერად“ — მომზადებული ცვლილებები | `git add` | | 🗃️ **Repository** | ისტორია `.git`-ში | `git commit` | რატომ გვჭირდება შუალედური ზონა? შეიძლება 5 ფაილი შეცვალე, მაგრამ ერთ „ფოტოში“ მხოლოდ 2 გინდა — ის, რაც ერთ ამოცანას ეხება. Staging-ით შენ წყვეტ, რა მოხვდეს შენახვაში. 📮 **ანალოგია — ამანათი:** `git add` = ნივთს ყუთში დებ (ჯერ კიდევ შეგიძლია ამოიღო). `git commit` = ყუთს ლუქავ, აწერ წარწერას და აგზავნი — ის უკვე ისტორიაშია. ```bash git add index.html # ერთი ფაილი staging-ში git add . # ყველა შეცვლილი ფაილი git commit -m "Add home page" ```

### ცნება 3 · Commit — ისტორიის ერთი ფოტო **Commit** — პროექტის შენახული მდგომარეობა. ყოველ commit-ს აქვს: - **hash** — უნიკალური იდენტიფიკატორი, მაგ. `a3f9c21` (სრულად 40 სიმბოლოა, ჩვეულებრივ პირველ 7-ს ვიყენებთ); - **ავტორი** და **თარიღი**; - **მესიჯი** — რა გაკეთდა; - **მშობელი** — წინა commit-ის hash. ასე იქმნება ისტორიის ჯაჭვი. **კარგი მესიჯი** მომავალი შენთვის იწერება — ექვსი თვის შემდეგ უნდა მიხვდე, რა გააკეთე: | ✓ კარგი | ✗ ცუდი | |---|---| | `Add contact section` | `fix` | | `Fix broken link on projects page` | `asdfgh` | | `Update profile photo` | `ცვლილებები` | წესი: **რა გააკეთე**, ბრძანებითი ფორმით, მოკლედ: „Add…“, „Fix…“, „Update…“, „Remove…“. ```tip ერთი commit = ერთი აზრი. „დავამატე კონტაქტები და შევცვალე ფერები და გავასწორე ბმული“ — ეს სამი commit-ია. ```

### ნაბიჯი 2 · status → add → commit ```console Git Bash $ git status On branch main Untracked files: index.html style.css $ git add . $ git status Changes to be committed: new file: index.html new file: style.css $ git commit -m "Add home page" [main (root-commit) 7b2e0d4] Add home page 2 files changed, 14 insertions(+) ``` აქ სამივე ზონა ჩანს: 1. **Untracked files** (ტერმინალში წითლად) — Git ფაილებს ხედავს, მაგრამ ჯერ არ ინახავს. 📝 Working Directory. 2. **Changes to be committed** (მწვანედ) — `git add`-ის შემდეგ ფაილები staging-შია. 📦 Staging Area. 3. **`[main (root-commit) 7b2e0d4]`** — პირველი commit ისტორიაშია. 🗃️ Repository. ```tip VS Code-ის მარცხენა პანელში **Source Control** (Ctrl+Shift+G) იგივეს ღილაკებით აკეთებს: `+` = add, ✓ = commit. ჯერ ბრძანებებით ისწავლე — მერე ღილაკებს ადვილად გაიგებ. ```
