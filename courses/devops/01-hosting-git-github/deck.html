## რა არის DevOps? ### რატომ არსებობს DevOps წარმოიდგინე ორი გუნდი: - 👩‍💻 **Dev (Development)** — დეველოპერები. წერენ კოდს და მათ ლეპტოპზე ყველაფერი მუშაობს. - 🛠️ **Ops (Operations)** — ადმინისტრატორები. მართავენ სერვერებს, სადაც საიტი რეალურად ცხოვრობს. ძველად მათ შორის **კედელი** იდგა: დეველოპერი კოდს „კედელს იქით გადააგდებდა“, ადმინისტრატორი კი ცდილობდა, ის სერვერზე როგორმე გაეშვა. შედეგი: - 🐢 ახალი ვერსია თვეში ერთხელ გამოდიოდა — ხელით და შიშით. - 🔥 რამე თუ გაფუჭდა, იწყებოდა: „ჩემთან მუშაობს!“ — „სერვერზე არ მუშაობს!“ - 🌙 სერვერი ღამით ჩავარდებოდა და დილამდე ამას ვერავინ ამჩნევდა. **DevOps = Dev + Ops.** კედელი ქრება: კოდი დეველოპერის ლეპტოპიდან მომხმარებლამდე **ერთი, ავტომატური გზით** მიდის, და ამ გზას ერთი გუნდი აკონტროლებს.

### DNS — სახელების და მისამართების საცავი ინტერნეტში კომპიუტერები ერთმანეთს **IP მისამართით** პოულობენ — მაგალითად `164.90.12.34`. ადამიანისთვის ციფრების დამახსოვრება რთულია, ამიტომ გვაქვს **დომენის სახელები**: `google.com`, `myportfolio.ge`. **DNS (Domain Name System)** — ინტერნეტის „კონტაქტების წიგნი“: საცავი, სადაც ყოველ **სახელს** მისი სერვერის **მისამართი** (IP) უწერია. | სახელი (დომენი) | მისამართი (IP) | |---|---| | `google.com` | `142.250.185.78` | | `facebook.com` | `157.240.1.35` | | `myportfolio.ge` | `164.90.12.34` | **როგორ მუშაობს:** 1. ① ბრაუზერი DNS-ს ეკითხება: „`myportfolio.ge` სად არის?“ 2. ② DNS წიგნში პოულობს და პასუხობს: „`164.90.12.34`“. 3. ③ ბრაუზერი ამ მისამართზე მიდის — სერვერთან. 📱 **ანალოგია — ტელეფონის კონტაქტები:** შენ ეძებ „დედა“-ს, ტელეფონი კი ნომერზე რეკავს. სახელს იმახსოვრებ შენ, ნომერს — ტელეფონი. ```note ეს „წიგნი“ თვითონ არ ივსება: როცა დომენს იყიდი, DNS-ში შენ ჩაწერ, რომ `myportfolio.ge` → შენი სერვერის IP. დომენს მე-2 ლექციაზე დავაკავშირებთ, DNS ჩანაწერებს — მე-5-ზე. ### ცნება 4 · Branch (შტო) **პრობლემა:** საიტი მუშაობს და სერვერზე დევს. გინდა ახალი სექცია დაამატო, მაგრამ ამას 2 დღე სჭირდება — ამ ხნის განმავლობაში `main` ნახევრად დაწერილი კოდით უნდა იყოს? და თუ ამასობაში `main`-ზე სასწრაფო შესწორება დაგჭირდა? **Branch** — ისტორიის პარალელური ხაზი. ის მიმდინარე commit-იდან იწყება და `main`-ს არ ეხება. - 🌿 **იზოლაცია** — `main` სტაბილური რჩება, ახალ ფიჩაზე branch-ში მუშაობ. - 🧪 **ექსპერიმენტი** — არ გამოვიდა? branch-ს წაშლი, `main`-ს არაფერი მოსვლია. - 👥 **გუნდი** — ყველა თავის branch-ზე მუშაობს და ერთმანეთს ხელს არ უშლის. ```bash git branch # რა branch-ები მაქვს git switch -c feature/contacts # ახალი branch + გადასვლა git switch main # main-ზე დაბრუნება ``` ```tip სახელი — `feature/...` ახალი ფუნქციონალისთვის, `fix/...` შესწორებისთვის. ასე ერთი შეხედვით ჩანს, რას ეხება branch-ი. ```

### ცნება 5 · Merge (შერწყმა) ფიჩა მზადაა — ახლა branch-ის ცვლილებები `main`-ში უნდა დაბრუნდეს: ```console Git Bash $ git switch main $ git merge feature/contacts Merge made by the 'ort' strategy. index.html | 12 ++++++++++++ $ git branch -d feature/contacts ``` 1. **გადადი იმ branch-ზე, რომელშიც უნდა შეერწყას** — ჩვეულებრივ `main`. 2. **`git merge `** — მითითებული branch-ის ცვლილებები მიმდინარეში გადმოდის. 3. branch აღარ გვჭირდება — **ვშლით** (`-d`). commit-ები არ იკარგება, ისინი უკვე `main`-შია. **ორი შემთხვევა:** - თუ `main` branch-ის შექმნის შემდეგ **არ შეცვლილა**, Git უბრალოდ `main`-ს წინ გადაწევს — **fast-forward**. ახალი commit არ იქმნება. - თუ `main`-ზეც იყო ცვლილებები (როგორც სურათზე), Git ქმნის **merge commit**-ს, რომელსაც ორი მშობელი ჰყავს. ორივე შემთხვევაში შედეგი ერთია: `main`-ში ორივე ხაზის ცვლილებებია.
