### GitHub Pages — რეპო → საიტი **GitHub Pages** — GitHub-ის უფასო ჰოსტინგი. ის რეპოს ერთი branch-იდან ფაილებს იღებს და აქვეყნებს მისამართზე: ```plain https://.github.io/<რეპოს-სახელი>/ ``` | რას იძლევა | რა პირობით | |---|---| | საჯარო მისამართი და HTTPS | უფასოდ, **public** რეპოსთვის | | ავტომატური განახლება ყოველ `git push`-ზე | ფაილები ერთი branch-იდან (ჩვენთან `main`) | | HTML, CSS, JS, სურათები | **მხოლოდ ფაილები** | პირველი ლექციის ტერმინებით: ეს **სტატიკური ჰოსტინგია** — სერვერს შენ არ მართავ, GitHub ყველაფერს თვითონ აკეთებს. შენ მხოლოდ ფაილებს აწვდი. ```terms deploy — კოდის გაგზავნა იქ, სადაც მომხმარებელი მას დაინახავს ჰოსტინგი — სერვისი, რომელიც საიტს ინტერნეტში 24/7 აჩვენებს ```

⚙️ workflow

GitHub-მა თვითონ შექმნა: build (ფაილების მომზადება) → deploy (გამოქვეყნება)

ეს pipeline-ია: push ავტომატურად იქცევა deploy-ად. კურსის ბოლოს ასეთს თვითონ დავწერთ — შენი API-სთვის
### ნაბიჯი 2 · Actions ჩანართი — პირველი pipeline Save-ზე დაჭერის შემდეგ GitHub-მა **workflow** გაუშვა — სახელით **pages build and deployment**. მას ნახავ რეპოს **Actions** ჩანართში. ის ორი ნაბიჯისგან შედგება: - **build** — ფაილების მომზადება გამოსაქვეყნებლად; - **deploy** — მათი გამოქვეყნება `github.io`-ზე. სტატუსი: 🟡 მიმდინარეობს · ✅ წარმატებით დასრულდა · ❌ შეცდომა (დააჭირე — ნახავ, რომელ ნაბიჯზე და რატომ). ```terms workflow — ავტომატური ნაბიჯების თანმიმდევრობა, რომელსაც GitHub რაღაც მოვლენაზე (მაგ. push) უშვებს pipeline — გზა კოდიდან გამოქვეყნებამდე, ნაბიჯებად დაყოფილი: build → deploy ``` ```tip ეს workflow GitHub-მა **თვითონ** შექმნა. კურსის ბოლო ლექციაზე ასეთს ჩვენ თვითონ დავწერთ — ოღონდ არა სტატიკური საიტისთვის, არამედ შენი API-სთვის, რომელიც საკუთარ სერვერზე გაეშვება. ```

### შპარგალკა: GitHub Pages **ჩართვა (ერთხელ):** Settings → Pages → Source: `Deploy from a branch` → `main` / `(root)` → Save → Actions-ში ✅ → `https://.github.io//`. **განახლება (ყოველთვის):** ```console Git Bash $ git switch -c feature/… $ git add . && git commit -m "…" $ git switch main $ git merge feature/… $ git push # → Actions: pages build and deployment ✅ ``` **თუ არ მუშაობს:** Actions მწვანეა? → `index.html` root-შია, პატარა ასოებით? → გზები ფარდობითია (`style.css`, არა `/style.css`)? → ფაილის სახელის ასოები ემთხვევა? → `Ctrl + F5`.

## შეჯამება · დღეს ვისწავლეთ - 📄 **GitHub Pages** — რეპოს ფაილებს აქვეყნებს `username.github.io/repo`-ზე: უფასოდ, public რეპოსთვის, HTTPS-ით. - 🚀 **deploy** — ჩართვა ერთხელ ხდება, მერე ყოველი `git push` `main`-ში ახალ ვერსიას აქვეყნებს. სტატუსი — **Actions** ჩანართში (`pages build and deployment`). - 🐧 **ტიპური შეცდომები** — `index.html` root-ში და პატარა ასოებით; ფარდობითი გზები; სერვერი Linux-ია და `Style.css` ≠ `style.css`. - ⚙️ **API ვერ გაეშვება Pages-ზე** — ის გაშვებული პროგრამაა, რომელიც კოდს ასრულებს და ბაზას მიმართავს. სჭირდება საკუთარი სერვერი (VPS), რომელზეც Linux მუშაობს. **შემდეგ ლექციაზე:** Linux — სერვერის ენა. საშინაოში დააყენე WSL და Ubuntu — ლექციაზე უკვე დაგჭირდება. ```prompt გამოცდა მეოთხე ლექციაზე ვსწავლობ DevOps-ს. მეოთხე ლექციაზე გავიარეთ: GitHub Pages (ჩართვა, მისამართი username.github.io/repo, განახლება git push-ით, Actions ჩანართი), ტიპური შეცდომები (404, CSS არ იტვირთება, /style.css vs style.css, დიდი და პატარა ასოები Linux-ზე, cache) და რატომ ვერ გაეშვება API GitHub Pages-ზე. დამისვი 7 კითხვა სათითაოდ, მარტივიდან რთულისკენ — ნაწილი პრაქტიკული სიტუაციები იყოს („საიტი გაიხსნა, მაგრამ…“). ყოველ პასუხზე შემიფასე და ამიხსენი. ბოლოს მითხარი, რა გავიმეორო. ქართულად. ``` ```prompt საიტი Pages-ზე არ მუშაობს ჩემი სტატიკური საიტი GitHub Pages-ზე არ მუშაობს სწორად. დამეხმარე პრობლემის პოვნაში ნაბიჯ-ნაბიჯ, მარტივად და ქართულად — ჯერ დამისვი კითხვები, მერე მირჩიე გამოსავალი. რას ვხედავ: [აქ აღწერე — მაგ. 404, CSS არ ჩანს, ძველი ვერსია]. ჩემი ფაილების სია: [აქ ჩაწერე] ```
