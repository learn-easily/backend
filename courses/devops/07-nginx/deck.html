### ნაბიჯი 1 · Nginx-ის დაყენება **Nginx** („ენჯინ-ექს“) — ერთ-ერთი ყველაზე პოპულარული ვებ-სერვერი: სწრაფი, მსუბუქი, ათასობით მომხმარებელს ერთდროულად უძლებს. ის ფაილებს (HTML, CSS, JS, სურათები) აძლევს ბრაუზერს — და შემდეგ ლექციაზე API-ს წინაც დადგება, როგორც **reverse proxy**. ```console lms-server $ sudo apt install -y nginx $ systemctl status nginx ● nginx.service - A high performance web server and a reverse proxy server Active: active (running) $ sudo ufw allow 'Nginx HTTP' # port 80 $ sudo ufw status OpenSSH ALLOW Anywhere Nginx HTTP ALLOW Anywhere ``` ბრაუზერში `http://` — **Welcome to nginx!** 🎉 სერვერმა ინტერნეტს პირველად უპასუხა. ```note `'Nginx HTTP'` — ufw-ის მზა პროფილი (port 80). არის `'Nginx HTTPS'` (443) და `'Nginx Full'` (ორივე) — HTTPS-ს მე-11 ლექციაზე ჩავრთავთ. ```

### ნაბიჯი 2 · ფაილები სერვერზე — rsync ჯერ სერვერზე საქაღალდე, რომელიც შენს user-ს ეკუთვნის (რომ ატვირთვას `sudo` არ სჭირდებოდეს): ```console lms-server $ sudo mkdir -p /var/www/portfolio $ sudo chown -R $USER:$USER /var/www/portfolio ``` მერე **შენს კომპიუტერზე** (WSL), my-portfolio-ს საქაღალდეში: ```console WSL · ~/my-portfolio $ rsync -avz --delete --exclude .git ./ lms:/var/www/portfolio/ sending incremental file list ./ index.html projects.html style.css ``` | ოფცია | რას ნიშნავს | |---|---| | `-a` | archive: ყველა ფაილი და საქაღალდე, უფლებებით | | `-v` / `-z` | აჩვენე რა მიდის / შეკუმშე გზაში | | `--delete` | რაც შენთან წაშალე, სერვერზეც წაიშალოს | | `--exclude .git` | Git-ის ისტორია სერვერზე არ გვჭირდება | | `./` → `lms:/var/www/portfolio/` | საიდან → სად (`lms` — `~/.ssh/config`-იდან) | **rsync** SSH-ით მუშაობს და ჭკვიანია: მეორედ მხოლოდ **შეცვლილ** ფაილებს აგზავნის. ```warn `./`-ის ბოლოს `/` მნიშვნელოვანია: `./` = საქაღალდის **შიგთავსი**. `--delete`-ით ფრთხილად: თუ დანიშნულება შეგეშალა, იქ არსებულ ფაილებს წაშლის. ```

### ნაბიჯი 3 · server block ```console lms-server $ sudo nano /etc/nginx/sites-available/portfolio ``` ```nginx sites-available/portfolio server { listen 80 default_server; server_name _; root /var/www/portfolio; index index.html; location / { try_files $uri $uri/ =404; } } ``` | დირექტივა | რას ნიშნავს | |---|---| | `listen 80 default_server` | port 80-ს უსმინე; ეს არის ნაგულისხმევი საიტი ამ port-ზე | | `server_name _` | რომელ დომენზე პასუხობს; `_` = ნებისმიერი (დომენი მე-11 ლექციაზე გვექნება) | | `root` | სად დევს საიტის ფაილები | | `index` | რა გაიხსნას, როცა მისამართი `/`-ით მთავრდება | | `location / { … }` | წესები ყველა მისამართისთვის | | `try_files $uri $uri/ =404` | მოძებნე ასეთი ფაილი → ასეთი საქაღალდე → თუ არ არის, 404 | `$uri` — მოთხოვნილი გზა: `/projects.html`-ზე Nginx ეძებს `/var/www/portfolio/projects.html`-ს. ```warn Nginx-ის კონფიგში ყოველი ხაზი `;`-ით მთავრდება, ბლოკები `{ }`-შია. გამოტოვებული `;` — ყველაზე ხშირი შეცდომა. ამიტომ ყოველი ცვლილების შემდეგ — `nginx -t`. ```

### ნაბიჯი 4 · ჩართვა: symlink → test → reload ```console lms-server $ sudo ln -s /etc/nginx/sites-available/portfolio /etc/nginx/sites-enabled/ $ sudo rm /etc/nginx/sites-enabled/default # „Welcome to nginx“ აღარ გვჭირდება $ sudo nginx -t nginx: the configuration file /etc/nginx/nginx.conf syntax is ok nginx: configuration file /etc/nginx/nginx.conf test is successful $ sudo systemctl reload nginx ``` 1. `ln -s` — symlink `sites-enabled`-ში: საიტი ჩართულია. 2. `default`-ის **symlink**-ს ვშლით (ფაილი `sites-available`-ში რჩება) — ორი `default_server` 80-ზე ერთად ვერ იქნება. 3. `nginx -t` — კონფიგის შემოწმება **ამოქმედებამდე**. 4. `reload` — ახალი კონფიგი, გათიშვის გარეშე. ბრაუზერში `http://` — შენი portfolio, შენს სერვერზე. 🎉 ```warn **ყოველთვის** `sudo nginx -t` reload/restart-მდე. თუ კონფიგში შეცდომაა და `restart` გაუშვი, Nginx ვეღარ ჩაირთვება — და ერთ სერვერზე მყოფი **ყველა** საიტი გაჩერდება. `nginx -t` გეტყვის ფაილს და ხაზს, სადაც შეცდომაა. ```
