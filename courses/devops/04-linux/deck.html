### root-ის ნაცვლად — საკუთარი user წინა ლექციაზე ყველაფერს **root**-ით ვაკეთებდით. root-ს ყველაფრის უფლება აქვს — შეცდომით გაშვებული ერთი ბრძანებაც სისტემას აფუჭებს, და მის სახელს ყველა ბოტი იცის. ამიტომ ვქმნით ჩვეულებრივ user-ს, რომელიც root-ის უფლებას მხოლოდ საჭიროებისას, `sudo`-თი იღებს: ```console Termius · root@lms-server # adduser giorgi # ახალი user — ითხოვს პაროლს, დანარჩენზე Enter # usermod -aG sudo giorgi # -aG: დაამატე ჯგუფში sudo # rsync --archive --chown=giorgi:giorgi ~/.ssh /home/giorgi ``` ბოლო ბრძანება root-ის `~/.ssh` საქაღალდეს (შენი საჯარო გასაღებით) ახალ user-ს უკოპირებს და მფლობელად მას ნიშნავს — ასე `giorgi`-თიც გასაღებით შეხვალ. Termius-ში შექმენი **მეორე Host** — იგივე IP და გასაღები, ოღონდ Username: `giorgi` (Label: `lms-server`). ძველი, root-ის Host შეგიძლია წაშალო, როცა ყველაფერი შემოწმდება. ახალი Host → Connect: ```console Termius · giorgi@lms-server giorgi@lms-server:~$ sudo whoami [sudo] password for giorgi: root ``` `adduser`-ში მითითებული პაროლი **შესვლისთვის არ გამოიყენება** — ის მხოლოდ `sudo`-სთვისაა. შესვლა ისევ გასაღებით ხდება.

### user-ები, root და sudo Linux-ში ყველა მოქმედებას რომელიმე **user** აკეთებს (`whoami` — ვინ ვარ). განსაკუთრებული user-ია **root** — ადმინისტრატორი, რომელსაც ყველაფრის უფლება აქვს, მათ შორის სისტემის გაფუჭების. ამიტომ ჩვეულებრივ user-ით ვმუშაობთ, და მხოლოდ საჭირო ბრძანებას ვუშვებთ root-ის უფლებით — **`sudo`**-თი (super user do). პირველად ის **შენს** პაროლს ითხოვს (რამდენიმე წუთი იმახსოვრებს). პაროლის აკრეფისას ეკრანზე არაფერი ჩანს — ეს ნორმალურია. ```console Termius · giorgi@lms-server $ apt install tree E: Could not open lock file ... Permission denied E: Unable to acquire the dpkg frontend lock, are you root? $ sudo apt update # პაკეტების სიის განახლება $ sudo apt install -y tree htop # დაყენება (-y = ყველა კითხვაზე „კი“) ``` **apt** — Ubuntu-ს პროგრამების „მაღაზია“. `apt update` პაკეტების **სიას** აახლებს, `apt install` — აყენებს, `apt upgrade` — დაყენებულებს აახლებს, `apt remove` — შლის. სერვერზე Nginx-ს, .NET-ს და Docker-ს სწორედ ასე დავაყენებთ. ```warn ბრძანება „Permission denied“-ით ჩავარდა? ჯერ იფიქრე, **რატომ** სჭირდება root — და მხოლოდ მერე დაუმატე `sudo`. ყველაფრის sudo-თი გაშვება ცუდი ჩვევაა. ```

### ფაილური სისტემა — ერთი ხე `/`-დან Windows-ში დისკები ასოებითაა (`C:\`, `D:\`). Linux-ში **ერთი ხეა**, რომელიც `/`-დან (root) იწყება — ყველაფერი, დისკებიც, მის შიგნითაა. ```plain tree / ← root, ყველაფრის დასაწყისი ├── home/ │ └── giorgi/ ← ~ (შენი სახლი) ├── etc/ ← კონფიგურაცია │ └── nginx/ ├── var/ │ ├── log/ ← ლოგები │ └── www/ ← საიტები ├── usr/bin/ ← პროგრამები ├── tmp/ ← დროებითი ``` | საქაღალდე | რა არის | როდის დაგჭირდება | |---|---|---| | `/home/` = `~` | შენი ფაილები | ყოველთვის | | `/etc` | პროგრამების კონფიგურაცია | Nginx, SSH-ის პარამეტრები | | `/var/log` | ლოგები | „რა გაფუჭდა?“ | | `/var/www` | საიტების ფაილები | portfolio სერვერზე | | `/usr/bin` | დაყენებული პროგრამები | — | ```warn Linux-ში **დიდი და პატარა ასოები განსხვავდება**: `Index.html` და `index.html` ორი სხვადასხვა ფაილია. წინა ლექციაზე GitHub Pages-ზე სწორედ ამის გამო „ქრებოდა“ CSS. ```

### ნავიგაცია: pwd · ls · cd ```console Termius · giorgi@lms-server $ pwd /home/giorgi $ ls my-portfolio notes.txt $ ls -la drwxr-x--- 4 giorgi giorgi 4096 . drwxr-xr-x 3 root root 4096 .. -rw-r--r-- 1 giorgi giorgi 220 .bashrc drwxr-xr-x 3 giorgi giorgi 4096 my-portfolio ``` - `pwd` (print working directory) — სად ვარ. - `ls` — რა არის მიმდინარე საქაღალდეში. `-l` — დეტალურად (უფლებები, მფლობელი, ზომა), `-a` — **ფარული** ფაილებიც (რომელთა სახელი `.`-ით იწყება, მაგ. `.bashrc`, `.git`, `.env`). - `cd <გზა>` — გადასვლა. ```console Termius · giorgi@lms-server $ cd /var/log # აბსოლუტური გზა — ფესვიდან $ cd .. # ერთით ზემოთ → /var $ cd www # ფარდობითი — აქედან → /var/www $ cd ~ # სახლში (ან უბრალოდ: cd) $ cd - # წინა საქაღალდეში ``` **გზის ორი სახე:** `/`-ით დაწყებული — **აბსოლუტური**, ფესვიდან ითვლება და ყველგან ერთნაირად მუშაობს. დანარჩენი — **ფარდობითი**, მიმდინარე საქაღალდიდან. `.` — მიმდინარე საქაღალდე, `..` — ერთით ზემოთ.

### შექმნა · კოპირება · წაშლა ```console Termius · giorgi@lms-server $ mkdir backups $ mkdir -p site/css/img # მთელი გზა ერთად (-p = parents) $ touch notes.txt # ცარიელი ფაილი $ cp notes.txt backups/ # ფაილის კოპირება $ cp -r site backups/ # საქაღალდის კოპირება: -r $ mv notes.txt todo.txt # სახელის შეცვლა $ mv todo.txt backups/ # გადატანა $ rm backups/todo.txt # ფაილის წაშლა $ rm -r backups # საქაღალდე — მთელი შიგთავსით ``` | ბრძანება | რას აკეთებს | |---|---| | `mkdir ` | საქაღალდე; `-p` — საჭირო შუალედურებიც | | `touch ` | ცარიელი ფაილი | | `cp ` | კოპირება; `-r` — საქაღალდე | | `mv ` | გადატანა **ან** სახელის შეცვლა | | `rm ` | წაშლა; `-r` — საქაღალდე | ```warn Linux-ში **სანაგვე ყუთი არ არის**: `rm` ფაილს სამუდამოდ შლის, შეკითხვის გარეშე. `-f` (force) კიდევ უფრო „ჩუმად“ შლის. ინტერნეტში ნანახი `sudo rm -rf /` მთელ სისტემას შლის — არასოდეს გაუშვა ბრძანება, რომლის მნიშვნელობაც არ იცი. ```

### პროცესები და port-ები: რა მუშაობს ახლა? **პროცესი** — გაშვებული პროგრამა. ყველას აქვს უნიკალური ნომერი — **PID**. ```console Termius · giorgi@lms-server $ ps aux | grep dotnet # ყველა პროცესიდან — მხოლოდ dotnet giorgi 2481 3.1 2.4 ... dotnet run $ htop # „Task Manager“ ტერმინალში: CPU, RAM; q — გასვლა $ kill 2481 # PID 2481-ის გაჩერება $ kill -9 2481 # თუ არ ჩერდება — ძალით ``` **port** — „კარი“, რომელსაც პროგრამა ქსელიდან მოთხოვნებისთვის უსმენს. API-ს `dotnet run` რომ გაუშვი, ის port `5080`-ს უსმენდა. სტანდარტული port-ები: **22** — SSH, **80** — HTTP, **443** — HTTPS, **5432** — PostgreSQL. ```console Termius · giorgi@lms-server $ sudo ss -tlnp State Local Address:Port Process LISTEN 0.0.0.0:22 sshd LISTEN 127.0.0.1:5080 dotnet LISTEN 0.0.0.0:80 nginx ``` `ss -tlnp` — ვინ რომელ port-ს უსმენს (`t` TCP, `l` listening, `n` რიცხვებით, `p` პროცესი). `0.0.0.0` — ყველასთვის ღიაა; `127.0.0.1` — მხოლოდ ამავე კომპიუტერიდან. **`|` (pipe)** — ერთი ბრძანების შედეგი მეორეს გადაეცემა: `ps aux | grep dotnet` — ყველა პროცესიდან `grep` მხოლოდ `dotnet`-იან ხაზებს ტოვებს. `grep` ლოგებშიც გამოგადგება: `grep ERROR app.log`. ```tip „საიტი არ იხსნება“ — DevOps-ის პირველი კითხვა: პროცესი **გაშვებულია**? (`ps`) და port-ს **უსმენს**? (`ss -tlnp`). ეს ორი ბრძანება პრობლემების ნახევარს პოულობს. ```

რატომ ახლა: .NET-ის build და ბაზა 1 GB-ში ვიწროდ ეტევა
### სერვერის მომზადება · 2 **განახლებები** — ახალ სერვერზე პირველივე დღეს ვაყენებთ (უსაფრთხოების პატჩები): ```console Termius · giorgi@lms-server $ sudo apt update && sudo apt upgrade -y ``` `&&` — მეორე ბრძანება მხოლოდ მაშინ სრულდება, თუ პირველი წარმატებით დასრულდა. **swap** — დისკზე გამოყოფილი ადგილი, რომელსაც სისტემა RAM-ად იყენებს, როცა ნამდვილი RAM ივსება. დისკი RAM-ზე ბევრად ნელია, მაგრამ swap-ის გარეშე მეხსიერების ამოწურვისას Linux პროცესებს **კლავს** (OOM killer). ჩვენს 1 GB-იან სერვერზე მოგვიანებით .NET-ის build-იც მოგვიწევს და ბაზაც — swap დაგვაზღვევს. ```console Termius · giorgi@lms-server $ sudo fallocate -l 2G /swapfile # 2 GB ფაილი $ sudo chmod 600 /swapfile # მხოლოდ root $ sudo mkswap /swapfile # swap-ად მომზადება $ sudo swapon /swapfile # ჩართვა $ echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab # reboot-ის შემდეგაც $ free -h total used free Mem: 961Mi 320Mi 410Mi Swap: 2.0Gi 0B 2.0Gi ``` `/etc/fstab` — ფაილი, რომელსაც სისტემა ჩართვისას კითხულობს. `tee -a` ფაილის ბოლოს ამატებს ხაზს root-ის უფლებით (`sudo echo ... >> file` არ იმუშავებს — გადამისამართებას შენი user აკეთებს და არა sudo).

### `~/.ssh/config` — WSL-ის ბრძანებებისთვის სერვერზე ჩვენ Termius-ით ვმუშაობთ. მაგრამ შემდეგ ლექციებზე **შენი კომპიუტერიდან** (WSL) გავუშვებთ ბრძანებებს, რომლებიც სერვერს თვითონ უკავშირდება: `rsync` (ფაილების ატვირთვა), `scp`, `ssh-copy-id`, `deploy.sh`. Termius-ის Host-ებს ისინი ვერ ხედავენ — მათ WSL-ის „მისამართების წიგნი“ სჭირდებათ, `~/.ssh/config`: ```plain ~/.ssh/config Host lms HostName 164.90.12.34 User giorgi IdentityFile ~/.ssh/id_ed25519 ``` შემოწმება — WSL-იდან: ```console WSL $ ssh lms giorgi@lms-server:~$ ``` `lms` — შენ მიერ მოფიქრებული მოკლე სახელი. ის იმუშავებს ყველა SSH-ზე დაფუძნებულ ბრძანებაში — შემდეგ ლექციაზე ფაილებს ასე ავტვირთავთ: `rsync -avz ./ lms:/var/www/portfolio/`.
