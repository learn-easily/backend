## ნაწილი 1 · ვინ და რისი უფლებით წინა ლექციაზე ყველაფერს root-ით ვაკეთებდით. დღეს ვქმნით საკუთარ user-ს, ვსწავლობთ `sudo`-ს, `apt`-ს და ფაილების უფლებებს.
პრობლემა → ვაკეთებთ ერთად

root-ის ნაცვლად — giorgi + sudo

# adduser giorgi New password: ******** Full Name []: ← Enter-ებით Is the information correct? [Y/n] y # usermod -aG sudo giorgi ← sudo ჯგუფში # rsync --archive --chown=giorgi:giorgi \ ~/.ssh /home/giorgi ← გასაღები მასაც

👑 root

ყველაფრის უფლება — მათ შორის ყველაფრის გაფუჭების. მის სახელს ყველა ბოტი იცის

giorgi@lms-server:~$ sudo whoami [sudo] password for giorgi: root
🎫 sudo — „ეს ერთი ბრძანება root-ის უფლებით“. პაროლი მხოლოდ sudo-სთვისაა, შესვლა — ისევ გასაღებით
### root-ის ნაცვლად — ცალკე user და sudo Linux-ში ყველა მოქმედებას რომელიმე **user** აკეთებს (`whoami` — ვინ ვარ). წინა ლექციაზე ვიყავით **root** — ადმინისტრატორი, რომელსაც ყველაფრის უფლება აქვს, მათ შორის სისტემის გაფუჭების. root-ის სახელს ყველა ბოტიც იცის. ამიტომ ვქმნით ჩვეულებრივ user-ს და მხოლოდ საჭირო ბრძანებას ვუშვებთ root-ის უფლებით — **`sudo`**-თი (super user do): ```console Termius · root@lms-server # adduser giorgi # ახალი user — ითხოვს პაროლს, დანარჩენზე Enter # usermod -aG sudo giorgi # -aG: დაამატე ჯგუფში sudo # rsync --archive --chown=giorgi:giorgi ~/.ssh /home/giorgi ``` ბოლო ბრძანება root-ის `~/.ssh` საქაღალდეს (შენი საჯარო გასაღებით) ახალი user-ის სახლში — `/home/giorgi`-ში — აკოპირებს და მფლობელად მას ნიშნავს. ასე `giorgi`-თიც გასაღებით შეხვალ. Termius-ში შექმენი **მეორე Host** — იგივე IP და გასაღები, ოღონდ Username: `giorgi`. ახალი Host → Connect: ```console Termius · giorgi@lms-server giorgi@lms-server:~$ whoami giorgi giorgi@lms-server:~$ sudo whoami [sudo] password for giorgi: root ``` prompt-ში ახლა `$` წერია — ჩვეულებრივი user. `sudo` პირველად **შენს** პაროლს ითხოვს (რამდენიმე წუთი იმახსოვრებს). პაროლის აკრეფისას ეკრანზე არაფერი ჩანს — ეს ნორმალურია. `adduser`-ში მითითებული პაროლი **შესვლისთვის არ გამოიყენება** — ის მხოლოდ `sudo`-სთვისაა. ```note ამიერიდან სერვერზე `giorgi`-ს Host-ით ვმუშაობთ. root-ის Host-ს ნაწილ 3-ში ვამოწმებთ — როცა root-ით შესვლას საერთოდ ავკრძალავთ. ```
პროგრამების დაყენება

apt — და რატომ სჭირდება sudo

$ apt install tree E: Could not open lock file ... Permission denied E: Unable to acquire the dpkg frontend lock, are you root? $ sudo apt update # პაკეტების სია $ sudo apt upgrade -y # განახლებები $ sudo apt install -y tree htop $ tree --version tree v2.1.1

📦 apt

პროგრამების „მაღაზია“: update → install · upgrade · remove

🔄 apt upgrade

უსაფრთხოების განახლებები — ახალ სერვერზე პირველივე დღეს

Nginx-ს, .NET-ს და Docker-ს სწორედ apt-ით დავაყენებთ
### apt — და რატომ სჭირდება sudo **apt** — Ubuntu-ს პროგრამების „მაღაზია“. პროგრამის დაყენება სისტემას ცვლის, ამიტომ ჩვეულებრივ user-ს ამის უფლება არ აქვს: ```console Termius · giorgi@lms-server $ apt install tree E: Could not open lock file ... Permission denied E: Unable to acquire the dpkg frontend lock, are you root? $ sudo apt update # პაკეტების სიის განახლება $ sudo apt upgrade -y # დაყენებული პროგრამების განახლება $ sudo apt install -y tree htop # დაყენება (-y = ყველა კითხვაზე „კი“) ``` | ბრძანება | რას აკეთებს | |---|---| | `apt update` | პაკეტების **სიას** აახლებს (რა ვერსიები არსებობს) | | `apt upgrade` | დაყენებულ პროგრამებს აახლებს — ახალ სერვერზე პირველივე დღეს (უსაფრთხოების პატჩები) | | `apt install` | აყენებს | | `apt remove` | შლის | სერვერზე Nginx-ს, .NET-ს და Docker-ს სწორედ ასე დავაყენებთ. `&&`-ით ორი ბრძანება ერთად: `sudo apt update && sudo apt upgrade -y` — მეორე მხოლოდ მაშინ სრულდება, თუ პირველი წარმატებით დასრულდა. ```warn ბრძანება „Permission denied“-ით ჩავარდა? ჯერ იფიქრე, **რატომ** სჭირდება root — და მხოლოდ მერე დაუმატე `sudo`. ყველაფრის sudo-თი გაშვება ცუდი ჩვევაა. ```

### უფლებები: ვის რისი უფლება აქვს `ls -l` ყოველ ფაილზე აჩვენებს 10 სიმბოლოს: ```console Termius · giorgi@lms-server $ ls -l index.html -rw-r--r-- 1 giorgi giorgi 1520 Nov 28 10:15 index.html ``` - პირველი სიმბოლო — ტიპი: `-` ფაილი, `d` საქაღალდე. - შემდეგ სამ-სამად: **მფლობელი** (`rw-`), **ჯგუფი** (`r--`), **სხვები** (`r--`). - მერე — მფლობელი user და ჯგუფი (`giorgi giorgi`). | ასო | რიცხვი | ფაილზე | საქაღალდეზე | |---|---|---|---| | `r` | 4 | წაკითხვა | შიგთავსის სიის ნახვა | | `w` | 2 | ჩაწერა | შიგნით შექმნა/წაშლა | | `x` | 1 | გაშვება | შესვლა (`cd`) | რიცხვი = ჯამი: `rw-` = 4+2 = **6**, `r--` = **4**, `rwx` = **7**. ასე `-rw-r--r--` = **644**. | რიცხვი | ვისთვის | მაგალითი | |---|---|---| | `644` | მე ვწერ, ყველა კითხულობს | HTML, CSS, კონფიგი | | `755` | მე ვწერ, ყველა შედის/უშვებს | საქაღალდე, სკრიპტი | | `600` | მხოლოდ მე | **SSH-ის პირადი გასაღები**, `.env` | ნამდვილი მაგალითი სერვერზე — შენი გასაღებების საქაღალდე: ```console Termius · giorgi@lms-server $ ls -la ~/.ssh drwx------ 2 giorgi giorgi 4096 . ← 700: მხოლოდ giorgi -rw------- 1 giorgi giorgi 98 authorized_keys ← 600: მხოლოდ giorgi ``` SSH ამას ამოწმებს: თუ `authorized_keys` ან პირადი გასაღები სხვებისთვისაც ღიაა, ის მის გამოყენებაზე **უარს** იტყვის. ```console Termius · giorgi@lms-server $ chmod 600 secret.txt # უფლებები რიცხვით $ chmod +x deploy.sh # გაშვების უფლება დაამატე $ sudo chown -R giorgi:giorgi /var/www/portfolio # მფლობელის შეცვლა ``` ```tip როცა Nginx საიტს ვერ აჩვენებს (403 Forbidden), ხშირად მიზეზი სწორედ უფლებებია — ამას შემდეგ ლექციაზე ვნახავთ. ```

## ნაწილი 2 · რა მუშაობს სერვერზე გაშვებული პროგრამები (პროცესები) და port-ები, რომლებსაც ისინი უსმენენ.

$ ps aux | grep sshd root 812 0.0 0.9 ... sshd: /usr/sbin/sshd $ htop # ცოცხლად: CPU, RAM (q) $ sleep 1000 & # სატესტო პროცესი [1] 2481 $ kill 2481 # გაჩერება PID-ით $ kill -9 2481 # თუ არ ჩერდება — ძალით $ sudo ss -tlnp State Local Address:Port Process LISTEN 0.0.0.0:22 sshd

⚙️ პროცესი

გაშვებული პროგრამა. ყველას აქვს ნომერი — PID

🚪 port

„კარი“, რომელსაც პროგრამა უსმენს: 22 — SSH, 80 — HTTP, 443 — HTTPS

„საიტი არ იხსნება“ → ss -tlnp: უსმენს კი ვინმე port-ს?
### პროცესები და port-ები: რა მუშაობს ახლა? **პროცესი** — გაშვებული პროგრამა. ყველას აქვს უნიკალური ნომერი — **PID**. ```console Termius · giorgi@lms-server $ ps aux | grep sshd # ყველა პროცესიდან — მხოლოდ sshd root 812 0.0 0.9 ... sshd: /usr/sbin/sshd $ htop # „Task Manager“ ტერმინალში: CPU, RAM; q — გასვლა $ sleep 1000 & # სატესტო პროცესი ფონზე (& — ტერმინალი თავისუფალი რჩება) [1] 2481 $ kill 2481 # PID 2481-ის გაჩერება $ kill -9 2481 # თუ არ ჩერდება — ძალით ``` **`|` (pipe)** — ერთი ბრძანების შედეგი მეორეს გადაეცემა: `ps aux | grep sshd` — ყველა პროცესიდან `grep` მხოლოდ `sshd`-იან ხაზებს ტოვებს. **port** — „კარი“, რომელსაც პროგრამა ქსელიდან მოთხოვნებისთვის უსმენს. API-ს `dotnet run` რომ გაუშვი, ის port `5080`-ს უსმენდა. სტანდარტული port-ები: **22** — SSH, **80** — HTTP, **443** — HTTPS, **5432** — PostgreSQL. ```console Termius · giorgi@lms-server $ sudo ss -tlnp State Local Address:Port Process LISTEN 0.0.0.0:22 sshd ``` `ss -tlnp` — ვინ რომელ port-ს უსმენს (`t` TCP, `l` listening, `n` რიცხვებით, `p` პროცესი). `0.0.0.0` — ყველასთვის ღიაა; `127.0.0.1` — მხოლოდ ამავე კომპიუტერიდან. ახლა სერვერზე მხოლოდ SSH-ია; მომდევნო ლექციებზე აქ გამოჩნდება `nginx` (80) და `dotnet` (5080). ```tip „საიტი არ იხსნება“ — DevOps-ის პირველი კითხვა: პროცესი **გაშვებულია**? (`ps`) და port-ს **უსმენს**? (`ss -tlnp`). ეს ორი ბრძანება პრობლემების ნახევარს პოულობს. ```

რატომ 00-? SSH ერთ პარამეტრზე პირველ მნიშვნელობას იღებს, ფაილებს კი ანბანით კითხულობს

### ნაბიჯი 1 · SSH-ის კონფიგი: root-ით და პაროლით — აკრძალულია SSH სერვერის (`sshd`) პარამეტრები `/etc/ssh/`-შია (წინა ლექციის საშინაოში ეს საქაღალდე ნახეთ). მთავარ ფაილს არ ვეხებით — ვქმნით საკუთარს `sshd_config.d` საქაღალდეში. `/etc` root-ისაა, ამიტომ — `sudo`: ```console Termius · giorgi@lms-server $ sudo nano /etc/ssh/sshd_config.d/00-hardening.conf ``` ```ini 00-hardening.conf PermitRootLogin no PasswordAuthentication no ``` - `PermitRootLogin no` — root-ით შესვლა აკრძალულია (მის სახელს ყველა ბოტი იცის). - `PasswordAuthentication no` — პაროლით შესვლა აკრძალულია, მხოლოდ გასაღებით (DigitalOcean-მა ეს უკვე გააკეთა, მაგრამ ჩვენ ამას ცხადად ვწერთ — ყველა სერვერზე იგივე წესი იქნება). ```console Termius · giorgi@lms-server $ sudo sshd -t # სინტაქსის შემოწმება: ცარიელი პასუხი = OK $ sudo systemctl restart ssh # ცვლილების ამოქმედება $ sudo sshd -T | grep -E "permitrootlogin|passwordauthentication" permitrootlogin no passwordauthentication no ``` `sshd -T` აჩვენებს **საბოლოო** პარამეტრებს, რომლითაც SSH რეალურად მუშაობს. `systemctl restart` — სერვისის გადატვირთვა; `systemctl`-ს Nginx-ის ლექციაზე დეტალურად ვნახავთ. **რატომ `00-`?** SSH ერთ პარამეტრზე **პირველ** ნანახ მნიშვნელობას იღებს, `sshd_config.d`-ის ფაილებს კი ანბანის მიხედვით კითხულობს. DigitalOcean-ს იქ შეიძლება უკვე ედოს `50-cloud-init.conf` — `00` მასზე ადრე იკითხება. ```warn **მიმდინარე Termius-ის tab არ დახურო**, სანამ **ახალ** tab-ში არ შეამოწმებ, რომ `giorgi`-ს Host-ით შესვლა მუშაობს. თუ რამე შეგეშალა, ძველი სესიით გაასწორებ. თუ მაინც ჩაიკეტე — Droplet-ის **Console** ბრაუზერში. ``` root-ის Host-ით Connect ახლა უნდა დასრულდეს `Permission denied (publickey)`-ით — ასეც უნდა იყოს. ეს Host Termius-იდან შეგიძლია წაშალო.

$ sudo ufw allow OpenSSH # ჯერ ეს! Rules updated $ sudo ufw enable Command may disrupt existing ssh connections. Proceed with operation (y|n)? y Firewall is active and enabled on system startup $ sudo ufw status Status: active To Action From OpenSSH ALLOW Anywhere
⚠ enable-მდე აუცილებლად allow OpenSSH — თორემ საკუთარ თავს ჩაკეტავ
### ნაბიჯი 2 · firewall: ufw **firewall** — „დაცვა კარებთან“: წყვეტს, რომელ port-ზე შეიძლება ინტერნეტიდან შემოსვლა. Ubuntu-ში მისი მარტივი ინტერფეისია **ufw** (uncomplicated firewall). ჩართვის შემდეგ **ყველა** შემოსული კავშირი იბლოკება, გარდა იმისა, რაც ცალკე დაუშვი. ```console Termius · giorgi@lms-server $ sudo ufw allow OpenSSH # port 22 — ჯერ ეს! $ sudo ufw enable Command may disrupt existing ssh connections. Proceed with operation (y|n)? y Firewall is active and enabled on system startup $ sudo ufw status Status: active To Action From OpenSSH ALLOW Anywhere ``` შემდეგ ლექციაზე, Nginx-ის დაყენებისას, დავამატებთ port 80-ს (HTTP), მოგვიანებით — 443-ს (HTTPS). ბაზის port (5432) კი **არასოდეს** გაიხსნება ინტერნეტისთვის. ```warn `ufw enable`-მდე **აუცილებლად** `ufw allow OpenSSH` — სხვა შემთხვევაში firewall შენს SSH კავშირსაც დაბლოკავს და სერვერზე ვეღარ შეხვალ (დაგრჩება მხოლოდ Droplet Console). ```
ნაბიჯი 3 · swap

1 GB RAM — და სათადარიგო 2 GB

$ sudo fallocate -l 2G /swapfile $ sudo chmod 600 /swapfile $ sudo mkswap /swapfile $ sudo swapon /swapfile $ echo '/swapfile none swap sw 0 0' \ | sudo tee -a /etc/fstab ← reboot-ის შემდეგაც $ free -h total used free Mem: 961Mi 320Mi 410Mi Swap: 2.0Gi 0B 2.0Gi

💾 swap

როცა RAM ივსება, დისკის ნაწილი RAM-ად გამოიყენება. ნელია — მაგრამ პროგრამა არ კვდება

🔐 chmod 600

swap-ში RAM-ის შიგთავსი ხვდება — მხოლოდ root-მა უნდა წაიკითხოს

რატომ ახლა: .NET-ის build და ბაზა 1 GB-ში ვიწროდ ეტევა
### ნაბიჯი 3 · swap **swap** — დისკზე გამოყოფილი ადგილი, რომელსაც სისტემა RAM-ად იყენებს, როცა ნამდვილი RAM ივსება. დისკი RAM-ზე ბევრად ნელია, მაგრამ swap-ის გარეშე მეხსიერების ამოწურვისას Linux პროცესებს **კლავს** (OOM killer). ჩვენს 1 GB-იან სერვერზე მოგვიანებით .NET-ის build-იც მოგვიწევს და ბაზაც — swap დაგვაზღვევს. ```console Termius · giorgi@lms-server $ sudo fallocate -l 2G /swapfile # 2 GB ფაილი $ sudo chmod 600 /swapfile # მხოლოდ root $ sudo mkswap /swapfile # swap-ად მომზადება $ sudo swapon /swapfile # ჩართვა $ echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab # reboot-ის შემდეგაც $ free -h total used free Mem: 961Mi 320Mi 410Mi Swap: 2.0Gi 0B 2.0Gi ``` `chmod 600` — ის, რაც პირველ ნაწილში ვისწავლეთ: swap-ში RAM-ის შიგთავსი (შეიძლება პაროლებიც) ხვდება, ამიტომ მხოლოდ root-მა უნდა წაიკითხოს. `/etc/fstab` — ფაილი, რომელსაც სისტემა ჩართვისას კითხულობს. `echo` ტექსტს ბეჭდავს, `|` მას `tee`-ს გადასცემს, `tee -a` კი ფაილის ბოლოს ამატებს root-ის უფლებით (`sudo echo ... >> file` არ იმუშავებს — გადამისამართებას შენი user აკეთებს და არა sudo).

$ nano ~/.ssh/config Host lms HostName 164.90.12.34 User giorgi IdentityFile ~/.ssh/id_ed25519
$ ssh lms giorgi@lms-server:~$ ▊
🖥️ Termius — შენთვის, სერვერზე მუშაობისას. 🐧 config — WSL-ის ბრძანებებისთვის: rsync … lms:/var/www/, სკრიპტები
### ნაბიჯი 4 · `~/.ssh/config` — WSL-ის ბრძანებებისთვის სერვერზე ჩვენ Termius-ით ვმუშაობთ. მაგრამ შემდეგ ლექციებზე **შენი კომპიუტერიდან** (WSL) გავუშვებთ ბრძანებებს, რომლებიც სერვერს თვითონ უკავშირდება: `rsync` (ფაილების ატვირთვა), `scp`, `ssh-copy-id`, `deploy.sh`. Termius-ის Host-ებს ისინი ვერ ხედავენ — მათ WSL-ის „მისამართების წიგნი“ სჭირდებათ, `~/.ssh/config`. WSL-იც Ubuntu-ა — იგივე `nano`, რაც სერვერზე: ```plain ~/.ssh/config Host lms HostName 164.90.12.34 User giorgi IdentityFile ~/.ssh/id_ed25519 ``` შემოწმება — WSL-იდან: ```console WSL $ ssh lms giorgi@lms-server:~$ ``` `lms` — შენ მიერ მოფიქრებული მოკლე სახელი. ის იმუშავებს ყველა SSH-ზე დაფუძნებულ ბრძანებაში — შემდეგ ლექციაზე ფაილებს ასე ავტვირთავთ: `rsync -avz ./ lms:/var/www/portfolio/`.
