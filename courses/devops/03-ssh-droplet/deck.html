## ნაწილი 1 · სერვერის არჩევა რა სერვერი გვჭირდება, როგორ გამოვთვალოთ მისი ზომა და სად ვიყიდოთ.
პრობლემა

API-ს სჭირდება კომპიუტერი, რომელიც არასოდეს ითიშება

💻 ჩემი ლეპტოპი?

დახურავ — საიტი ქრება. სახლის ინტერნეტს მუდმივი IP არ აქვს, დენი ითიშება

🏢 საკუთარი სერვერი?

ძვირი რკინა, გაგრილება, ინტერნეტის ხაზი, შეკეთება — ეს ცალკე ბიზნესია

☁️ ნაქირავები — VPS

კომპიუტერის „ნაჭერი“ მონაცემთა ცენტრში: 24/7, საჯარო IP, თვეში რამდენიმე დოლარი

პირველი ლექციის ანალოგიით: VPS = ნაქირავები ბინა. შენია, შიგნით რასაც გინდა აკეთებ — შენობას კი სხვა უვლის.
### პრობლემა: API-ს სჭირდება კომპიუტერი, რომელიც არასოდეს ითიშება წინა ლექციაზე ვნახეთ: GitHub Pages მხოლოდ ფაილებს აჩვენებს. API კი **გაშვებული პროგრამაა** — მას სჭირდება კომპიუტერი, რომელიც: - **24/7 ჩართულია** — ლეპტოპს დახურავ და საიტი ქრება; - **საჯარო, მუდმივი IP** აქვს — სახლის ინტერნეტის IP ხშირად იცვლება და გარედან მიუწვდომელია; - **სტაბილურ დენზე და ინტერნეტზეა**. საკუთარი სერვერის ყიდვა და მოვლა (რკინა, გაგრილება, ხაზი, შეკეთება) ცალკე ბიზნესია. ამიტომ სერვერს **ვქირაობთ**: **VPS** (Virtual Private Server) — მონაცემთა ცენტრის დიდი კომპიუტერის ვირტუალური „ნაჭერი“, რომელიც მხოლოდ შენ გეკუთვნის. პირველი ლექციის ანალოგიით — ნაქირავები ბინა. ```terms VPS — Virtual Private Server: ნაქირავები ვირტუალური სერვერი მონაცემთა ცენტრი — შენობა ათასობით სერვერით, მუდმივი დენით და ინტერნეტით ```

### როგორ მივხვდეთ, რა გვჭირდება სერვერს „თვალით“ არ ვარჩევთ. ჯერ ვწერთ, **რა იმუშავებს** მასზე, და ვთვლით, რამდენი რესურსი სჭირდება ყველას ერთად. ჩვენი LMS-ისთვის: | რა მუშაობს | RAM (დაახლოებით) | |---|---| | Ubuntu (ოპერაციული სისტემა) | ~300 MB | | Nginx + frontend-ის ფაილები | ~20 MB | | LMS API (.NET) | ~150–250 MB | | PostgreSQL | ~100–200 MB | | **ჯამში** | **~0.6–0.8 GB** | სამი მთავარი პარამეტრი: - 🧠 **RAM** — ყველაზე მნიშვნელოვანი: ყველა პროგრამა ერთდროულად უნდა ჩაეტიოს. ჩვენთვის **1 GB** საკმარისია. - ⚡ **CPU (vCPU)** — პროცესორის ბირთვები. სასწავლო პროექტს, რომელსაც ცოტა მომხმარებელი ჰყავს, **1 vCPU** ჰყოფნის. - 💾 **დისკი** — სისტემა, პროგრამები, ბაზა, ლოგები. **25 GB** საკმარისია. ```tip **იწყებ პატარით.** სერვერის ზომა მოგვიანებით იზრდება (DigitalOcean-ში — **Resize**). თავიდანვე დიდის ყიდვა უბრალოდ ზედმეტი ხარჯია. როცა დატვირთვა გაიზრდება, მონიტორინგი გეტყვის, რა გაზარდო. ```

## ნაწილი 2 · SSH სერვერთან ფიზიკურად ვერ მიხვალ. როგორ შეხვიდე მასში — და ისე, რომ სხვამ ვერ შეძლოს.
პრობლემა

Password? — ბოტები უკვე გელოდებიან

🔐 SSH — Secure Shell

შენს კომპიუტერში კრეფ ბრძანებას — ის სერვერზე სრულდება, შედეგი შენთან ჩანს. კავშირი დაშიფრულია.

🤖 პაროლით შესვლა

Invalid user admin from 45.x.x.x
Invalid user test from 103.x.x.x
Failed password for root from 194.x.x.x
…ათასობით, ყოველდღე

ბოტები ინტერნეტის ყველა IP-ს უწყვეტად ამოწმებენ და პაროლებს არჩევენ

გამოსავალი: პაროლის ნაცვლად — SSH გასაღები. მისი გამოცნობა პრაქტიკულად შეუძლებელია.
### პრობლემა: Password? — ბოტები უკვე გელოდებიან სერვერი მონაცემთა ცენტრშია, სხვა ქვეყანაში — ფიზიკურად მასთან ვერ მიხვალ. **SSH** (Secure Shell) შენს ტერმინალს სერვერს აკავშირებს: შენ კრეფ, ბრძანება **სერვერზე** სრულდება, შედეგი შენთან ჩანს. მთელი კავშირი **დაშიფრულია**. შესასვლელად სერვერმა უნდა იცოდეს, რომ ეს **შენ** ხარ. პირველი აზრი — პაროლი. მაგრამ ინტერნეტში ბოტები უწყვეტად ამოწმებენ ყველა IP მისამართს და SSH-ზე პაროლებს არჩევენ (`admin/admin`, `root/123456`...). ახალი სერვერის ლოგში ასეთი ცდები **რამდენიმე წუთში** ჩნდება: ```plain სერვერის შესვლის ლოგი Invalid user admin from 45.x.x.x Invalid user test from 103.x.x.x Failed password for root from 194.x.x.x ``` ამიტომ Authentication-ში ვირჩევთ **SSH Key**-ს — პაროლი საერთოდ არ იქნება, და ბოტებს გამოსაცნობი არაფერი დარჩებათ.
როგორ მუშაობს

ერთი ნაწილი — სერვერზე, მეორე — შენთან

🔒 საჯარო — საკეტი

სერვერზე ინახება. შეგიძლია ბევრ კარზე დაკიდო. მოპარვა საშიში არ არის — საკეტით კარს ვერ გააღებ

🔑 პირადი — გასაღები

მხოლოდ შენთანაა. ვისაც ის აქვს, ის შედის. არავის აჩვენო, არ ატვირთო GitHub-ზე

### როგორ მუშაობს SSH გასაღები SSH გასაღები **ორი ნაწილისგან** შედგება, რომლებიც ერთმანეთს მათემატიკურად ემთხვევა — როგორც საკეტი და მისი გასაღები: - 🔒 **საჯარო ნაწილი (საკეტი)** — ინახება **სერვერზე**. სერვერმა იცის: „ვისაც ამ საკეტის გასაღები აქვს, ის შევუშვა“. - 🔑 **პირადი ნაწილი (გასაღები)** — ინახება **მხოლოდ შენთან**, შენს კომპიუტერზე. **როგორ ხდება შესვლა:** 1. შენ სერვერს ეუბნები: „შემიშვი“. 2. სერვერი საჯარო ნაწილით ამზადებს ამოცანას, რომლის ამოხსნაც **მხოლოდ** შესაბამის პირად გასაღებს შეუძლია, და გიგზავნის. 3. შენი კომპიუტერი ამოცანას პირადი გასაღებით ხსნის და პასუხს უბრუნებს. სწორია — შეხვედი. მთავარი: **პირადი გასაღები ქსელში არასოდეს მიდის** — მიდის მხოლოდ ამოხსნა. ამიტომ მისი „მოსმენა“ ან სერვერიდან მოპარვა შეუძლებელია: სერვერზე მხოლოდ საკეტია. საჯარო ნაწილის მოპარვა საშიში არ არის — საკეტით კარს ვერ გააღებ. ამიტომ ერთ საკეტს ბევრ კარზე კიდებ: ყველა შენს სერვერზე, GitHub-ზეც. პირადი კი პაროლზე მნიშვნელოვანია. ```warn პირადი გასაღები **არ** გაუგზავნო არავის, **არ** ჩასვა ჩატში და **არ** ატვირთო GitHub-ზე. ```
