## ნაწილი 1 · SSH ტერმინალი სხვა ქვეყანაში მდგარ კომპიუტერზე — დაშიფრული და პაროლის გარეშე.
პრობლემა

სერვერი ფრანკფურტშია — როგორ „დავჯდე“ მასთან?

🔐 SSH — Secure Shell

შენი ტერმინალი, ოღონდ ბრძანებები სერვერზე სრულდება. ყველაფერი დაშიფრულია.

$ ssh root@164.90.12.34
root@lms-server:~# ▊

🤖 პაროლით შესვლა?

Invalid user admin from 45.x.x.x
Invalid user test from 103.x.x.x
Failed password for root from 194.x.x.x
…ათასობით, ყოველდღე

ბოტები ინტერნეტის ყველა IP-ს უწყვეტად ამოწმებენ და პაროლებს არჩევენ

გამოსავალი: პაროლის ნაცვლად — გასაღები. მისი გამოცნობა პრაქტიკულად შეუძლებელია.
### პრობლემა: სერვერი ფრანკფურტშია — როგორ „დავჯდე“ მასთან? წინა ლექციაზე ვნახეთ, რომ API GitHub Pages-ზე ვერ გაეშვება — მას საკუთარი სერვერი სჭირდება. სერვერი მონაცემთა ცენტრშია, სხვა ქვეყანაში. ფიზიკურად მასთან ვერ მიხვალ — და არც გჭირდება. **SSH** (Secure Shell) შენს ტერმინალს სერვერს აკავშირებს: შენ კრეფ, ბრძანება **სერვერზე** სრულდება, შედეგი შენთან ჩანს. მთელი კავშირი **დაშიფრულია**. ```console შენი კომპიუტერი $ ssh root@164.90.12.34 root@lms-server:~# ``` **პაროლის პრობლემა.** ინტერნეტში ბოტები უწყვეტად ამოწმებენ ყველა IP მისამართს და SSH-ზე პაროლებს არჩევენ (`admin/admin`, `root/123456`...). ახალი სერვერის ლოგში ასეთი ხაზები **რამდენიმე წუთში** ჩნდება: ```plain /var/log/auth.log Invalid user admin from 45.x.x.x Invalid user test from 103.x.x.x Failed password for root from 194.x.x.x ``` გამოსავალი — პაროლის ნაცვლად **SSH გასაღები**.
SSH გასაღები

🔒 საკეტი და 🔑 გასაღები

🔒 საჯარო — .pub

საკეტი: შეგიძლია ბევრ კარზე დაკიდო — სერვერზე, GitHub-ზე. მოპარვა საშიში არ არის

🔑 პირადი

მხოლოდ შენს კომპიუტერზე. არ გააგზავნო, არ ატვირთო GitHub-ზე

### SSH გასაღები: საკეტი და გასაღები SSH გასაღები **წყვილია** — ორი ფაილი, რომლებიც მათემატიკურად ერთმანეთს ემთხვევა: | ფაილი | ანალოგია | სად ცხოვრობს | |---|---|---| | `~/.ssh/id_ed25519.pub` — **საჯარო** | 🔒 საკეტი | სერვერზე (`~/.ssh/authorized_keys`), GitHub-ზე — ნებისმიერ ადგილას, სადაც შესვლა გინდა | | `~/.ssh/id_ed25519` — **პირადი** | 🔑 გასაღები | **მხოლოდ** შენს კომპიუტერზე | შესვლისას სერვერი გამოწვევას აგზავნის, რომლის სწორად „გახსნაც“ მხოლოდ შესაბამის პირად გასაღებს შეუძლია. თავად პირადი გასაღები ქსელში **არასოდეს** მიდის. საჯარო ნაწილის მოპარვა საშიში არ არის — საკეტით კარს ვერ გააღებ. პირადი კი პაროლზე მნიშვნელოვანია: ვისაც ის აქვს, ის შედის შენს ყველა სერვერზე. ```warn პირადი გასაღები **არ** გაუგზავნო არავის, **არ** ჩასვა ჩატში და **არ** ატვირთო GitHub-ზე. ```

### ნაბიჯი 1 · გასაღების შექმნა გასაღებს **შენს კომპიუტერზე** ვქმნით — WSL-ში (macOS-ზე — Terminal-ში). ეს ორი ბრძანებაა; Linux-ს დღესვე ნამდვილ სერვერზე ვისწავლით. გასაღები ერთხელ იქმნება — ყველა სერვერზე და GitHub-ზეც გამოგადგება: ```console WSL $ ssh-keygen -t ed25519 -C "giorgi@mail.ge" Generating public/private ed25519 key pair. Enter file in which to save the key (/home/giorgi/.ssh/id_ed25519): ← Enter Enter passphrase (empty for no passphrase): ← სურვილისამებრ Your identification has been saved in /home/giorgi/.ssh/id_ed25519 Your public key has been saved in /home/giorgi/.ssh/id_ed25519.pub ``` - `-t ed25519` — ალგორითმი: თანამედროვე, მოკლე და ძლიერი (ძველი ალტერნატივაა RSA). - `-C` — კომენტარი, რომ მოგვიანებით იცოდე, ვისი გასაღებია. - **passphrase** — პირადი გასაღების პაროლი. თუ ლეპტოპი მოიპარეს, მის გარეშე გასაღები უსარგებლოა. სწავლისას შეგიძლია ცარიელი დატოვო. ```console WSL $ cat ~/.ssh/id_ed25519.pub # cat — ფაილის შიგთავსის ჩვენება ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI...x9 giorgi@mail.ge ``` `.pub`-ის ეს ერთი ხაზი არის ის, რასაც სერვერს მივცემთ.

### ნაბიჯი 2 · Droplet-ის შექმნა DigitalOcean-ის panel-ში: **Create → Droplets**. | პარამეტრი | რას ვირჩევთ | რატომ | |---|---|---| | **Region** | Frankfurt | საქართველოსთან ახლოს — სწრაფი პასუხი | | **Image** | Ubuntu 24.04 (LTS) x64 | სერვერების ყველაზე პოპულარული Linux; LTS — წლების განმავლობაში განახლებები | | **Size** | Basic → Regular → უმცირესი (1 vCPU, 1 GB RAM) | საკმარისია API-სთვის და ბაზისთვის | | **Authentication** | **SSH Key** → New SSH Key → ჩასვი `.pub`-ის ხაზი | პაროლი არ გვინდა | | **Hostname** | `lms-server` | სერვერის სახელი prompt-ში | **Create Droplet** → დაახლოებით ერთ წუთში Droplet-ის გვერდზე გამოჩნდება მისი **IPv4 მისამართი**, მაგ. `164.90.12.34`. SSH Key-ით შექმნილ Droplet-ზე პაროლით შესვლა საერთოდ გამორთულია — ბოტები პაროლს ვერ გამოიცნობენ, რადგან ის არ არსებობს. ```warn **ფასი საათობრივად ითვლება**, თვეში რამდენიმე დოლარამდე. Termius — სერვერთან კავშირი

1️⃣ Keychain → Key → Import

WSL-ში შექმნილი პირადი გასაღები: cat ~/.ssh/id_ed25519 → ჩასვი Private key ველში

2️⃣ Hosts → New Host

Label: lms-server · Address: 164.90.12.34 · Username: root · Key: ეს გასაღები

3️⃣ Connect

„Unknown host fingerprint“ → Continue: სერვერს პირველად ვხედავთ

🖥️ რა არის Termius

SSH კლიენტი: სერვერების სია, გასაღებები, tab-ები, SFTP. შიგნით — ზუსტად იგივე ssh root@164.90.12.34

ამიერიდან სერვერზე ყველაფერს Termius-ში ვაკეთებთ. შენს კომპიუტერზე (git, docker, rsync) — WSL-ში
### ნაბიჯი 3 · Termius — სერვერთან კავშირი **Termius** — SSH კლიენტი: სერვერების სია, შენახული გასაღებები, რამდენიმე tab ერთად და ჩაშენებული SFTP (ფაილების დათვალიერება). შიგნით ის ზუსტად იმას აკეთებს, რასაც ტერმინალში `ssh root@164.90.12.34` — უბრალოდ IP-ს და პარამეტრებს ყოველ ჯერზე აღარ კრეფ. **1. გასაღების შემოტანა.** გასაღები უკვე შევქმენით WSL-ში (ნაბიჯი 1). Termius-ს იგივე გასაღებს ვაძლევთ — ახალს არ ვქმნით, რომ WSL-იდანაც და Termius-იდანაც ერთი გასაღებით შევიდეთ: ```console WSL $ cat ~/.ssh/id_ed25519 -----BEGIN OPENSSH PRIVATE KEY----- ... -----END OPENSSH PRIVATE KEY----- ``` Termius → **Keychain** → **Key** → **Import** (ან New Key) → მთელი ტექსტი, `-----BEGIN`-იდან `-----END`-ის ჩათვლით, ჩასვი **Private key** ველში. **2. Host.** **Hosts → New Host**: | ველი | მნიშვნელობა | |---|---| | Label | `lms-server` | | Address | Droplet-ის IP | | Username | `root` (ცალკე user-ს შემდეგ ლექციაზე შევქმნით) | | Key | ის, რაც ახლა შემოვიტანეთ | **3. Connect.** პირველად Termius იტყვის, რომ სერვერის „თითის ანაბეჭდი“ (fingerprint) უცნობია: ამ სერვერს პირველად ვხედავთ — **Continue**. Termius მას იმახსოვრებს და თუ შემდეგში შეიცვლება, გაგაფრთხილებს (შეიძლება ვინმე შუაში ჩაჯდა). ```warn გასაღების ტექსტი მხოლოდ Termius-ის ველში ჩასვი — **არა** ჩატში, არა სხვაგან. ის პაროლზე მნიშვნელოვანია. ``` ```note გასაღებს Termius-ში **არ** ვქმნით: მაშინ ის მხოლოდ Termius-ში იცხოვრებდა, WSL-ის ბრძანებები კი (`rsync`, `scp`, `ssh-copy-id`, `deploy.sh`) — მომდევნო ლექციებზე — ვერ შევიდოდნენ. ```

### ფაილური სისტემა — ერთი ხე `/`-დან Windows-ში დისკები ასოებითაა (`C:\`, `D:\`). ### ნავიგაცია: pwd · ls · cd ```console Termius · root@lms-server # pwd /root # ls ← არაფერი ჩანს? # ls -la drwx------ 4 root root 4096 . drwxr-xr-x 19 root root 4096 .. -rw-r--r-- 1 root root 3106 .bashrc drwx------ 2 root root 4096 .ssh ``` - `pwd` (print working directory) — სად ვარ. root-ის სახლი `/root`-ია. - `ls` — რა არის მიმდინარე საქაღალდეში. `-l` — დეტალურად (უფლებები, მფლობელი, ზომა), `-a` — **ფარული** ფაილებიც (რომელთა სახელი `.`-ით იწყება, მაგ. `.bashrc`, `.ssh`, `.git`, `.env`). `ls` ცარიელს აჩვენებს, `ls -la` კი — ფარულ `.ssh`-ს: სწორედ იქაა შენი საჯარო გასაღები (`authorized_keys`), რომელიც DigitalOcean-მა ჩადო. - `cd <გზა>` — გადასვლა. ```console Termius · root@lms-server # cd /etc # აბსოლუტური გზა — ფესვიდან # cd .. # ერთით ზემოთ → / # cd var/log # ფარდობითი — აქედან → /var/log # cd ~ # სახლში (ან უბრალოდ: cd) # cd - # წინა საქაღალდეში ``` **გზის ორი სახე:** `/`-ით დაწყებული — **აბსოლუტური**, ფესვიდან ითვლება და ყველგან ერთნაირად მუშაობს. დანარჩენი — **ფარდობითი**, მიმდინარე საქაღალდიდან. `.` — მიმდინარე საქაღალდე, `..` — ერთით ზემოთ.
