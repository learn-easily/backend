## ნაწილი 1 · compose.yaml ჯერ ყველაფერს შენს კომპიუტერზე ვაწყობთ — და მხოლოდ მერე სერვერზე, უცვლელად.
პრობლემა

ორი კონტეინერი — ორი გრძელი ბრძანება

$ docker run -d --name lms-db \ -e POSTGRES_USER=lms -e POSTGRES_PASSWORD=dev \ -e POSTGRES_DB=lms -p 5432:5432 \ -v lms-data:/var/lib/postgresql/data postgres:17 $ docker build -t lms-api . $ docker run -d --name lms-api -p 8080:8080 \ -e ASPNETCORE_ENVIRONMENT=Development \ -e ConnectionStrings__Default="Host=host.docker.internal;…" \ lms-api
📝 ზეპირად? README-ში? — ერთი შეცდომა და არ მუშაობს
🔗 host.docker.internal — „შემოვლითი გზა“

Docker Compose: მთელი სისტემა — ფაილში, რომელიც Git-ში ინახება
### პრობლემა: ორი კონტეინერი — ორი გრძელი ბრძანება წინა ლექციის ბოლოს LMS ორი კონტეინერით მუშაობდა — მაგრამ: - 📝 ორი გრძელი `docker run` — ზეპირად ან README-დან კოპირებით; ერთი შეცდომა და არ მუშაობს; - 🔗 API ბაზას `host.docker.internal`-ით პოულობს — „შემოვლით“, შენი კომპიუტერის გავლით; - ⏱️ თუ API ბაზაზე ადრე ჩაირთო — ვარდება. **Docker Compose** მთელ სისტემას — ყველა კონტეინერს, მათ პარამეტრებს და კავშირებს — **ერთ ფაილში** აღწერს: `compose.yaml`. ფაილი Git-ში ინახება, და ნებისმიერ კომპიუტერზე ერთი ბრძანებით ეშვება.
ვაკეთებთ ერთად · ნაბიჯი 1

compose.yaml — LMS-ის რეპოს root-ში

services: db: image: postgres:17 environment: POSTGRES_USER: lms POSTGRES_PASSWORD: ${DB_PASSWORD} POSTGRES_DB: lms volumes: - lms-data:/var/lib/postgresql/data healthcheck: test: ["CMD-SHELL", "pg_isready -U lms -d lms"] interval: 5s retries: 10 restart: unless-stopped api: build: . ports: - "127.0.0.1:5000:8080" environment: ASPNETCORE_ENVIRONMENT: ${ASPNETCORE_ENVIRONMENT:-Production} ConnectionStrings__Default: "Host=db;…;Password=${DB_PASSWORD}" depends_on: db: condition: service_healthy restart: unless-stopped volumes: lms-data:
🔗 Host=db — სერვისის სახელი = მისამართი
⏱️ depends_on → API მხოლოდ healthy ბაზის შემდეგ
♾️ restart — როგორც systemd-ის Restart=always
### ნაბიჯი 1 · compose.yaml LMS-ის რეპოს root-ში, `Dockerfile`-ის გვერდით: ```yaml compose.yaml services: db: image: postgres:17 environment: POSTGRES_USER: lms POSTGRES_PASSWORD: ${DB_PASSWORD} POSTGRES_DB: lms volumes: - lms-data:/var/lib/postgresql/data healthcheck: test: ["CMD-SHELL", "pg_isready -U lms -d lms"] interval: 5s retries: 10 restart: unless-stopped api: build: . ports: - "127.0.0.1:5000:8080" environment: ASPNETCORE_ENVIRONMENT: ${ASPNETCORE_ENVIRONMENT:-Production} ConnectionStrings__Default: "Host=db;Database=lms;Username=lms;Password=${DB_PASSWORD}" depends_on: db: condition: service_healthy restart: unless-stopped volumes: lms-data: ``` | ნაწილი | რას ნიშნავს | `docker run`-ში იყო | |---|---|---| | `services:` | კონტეინერების სია; სახელი (`db`, `api`) — შენი არჩეული | `--name` | | `image:` / `build: .` | მზა image / ააწყე მიმდინარე საქაღალდის Dockerfile-ით | `docker build` | | `environment:` | გარემოს ცვლადები | `-e` | | `volumes:` | volume-ის მიბმა; ქვედა `volumes:` — მისი გამოცხადება | `-v` | | `ports:` | `IP:ჰოსტი:კონტეინერი` | `-p` | | `healthcheck:` | ბრძანება, რომელიც ამოწმებს, ბაზა მართლა მზადაა თუ არა (`pg_isready`) | — | | `depends_on` + `service_healthy` | API მხოლოდ **healthy** ბაზის შემდეგ ირთვება | — | | `restart: unless-stopped` | crash-ზე და სერვერის reboot-ზე თავისით ირთვება — როგორც systemd-ის `Restart=always` | — | **`Host=db`** — Compose ყველა სერვისს **ერთ ქსელში** სვამს, სადაც სერვისის სახელი მისამართად მუშაობს. `host.docker.internal` აღარ გვჭირდება. **YAML** — ფორმატი, სადაც სტრუქტურას **შეწევა** (space-ები) განსაზღვრავს, არა `{ }`. მხოლოდ space-ები, არა Tab; ერთ დონეზე — ერთნაირი შეწევა.

### ნაბიჯი 2 · საიდუმლოებები და მიგრაციები **`.env`** — Compose `compose.yaml`-ის გვერდით მდებარე `.env` ფაილს **ავტომატურად** კითხულობს და `${სახელი}`-ს მის მნიშვნელობას უსვამს: ```ini .env (შენთან) DB_PASSWORD=dev ASPNETCORE_ENVIRONMENT=Development ``` `${ASPNETCORE_ENVIRONMENT:-Production}` — თუ ცვლადი არ არის მითითებული, ნაგულისხმევად `Production`. შენთან `.env`-ში `Development` წერია (Swagger ჩანს), სერვერზე — `Production`. ```warn `.env` **არასოდეს** Git-ში — დაამატე `.gitignore`-ში (მე-3 ლექცია). სერვერზე ცალკე `.env` შეიქმნება, სხვა, ძლიერი პაროლით. ``` **მიგრაციები ჩართვისას.** წინა ლექციებზე მიგრაციებს ცალკე SQL სკრიპტით ვუშვებდით. ახლა აპი ჩართვისას თვითონ უშვებს მათ: ```csharp Program.cs var app = builder.Build(); using (var scope = app.Services.CreateScope()) { var db = scope.ServiceProvider.GetRequiredService(); db.Database.Migrate(); } ``` `Migrate()` ამოწმებს, რომელი მიგრაცია აკლია ბაზას, და მხოლოდ მათ უშვებს — იგივე, რაც `--idempotent` სკრიპტი. `depends_on: service_healthy`-ის წყალობით ამ დროს ბაზა უკვე მზადაა. ```note ერთი სერვერისთვის და სასწავლო პროექტისთვის ეს მარტივი და საიმედოა. დიდ სისტემებში, სადაც API რამდენიმე ეგზემპლარად ეშვება, მიგრაციებს ცალკე ნაბიჯად უშვებენ (`efbundle` ან SQL სკრიპტი pipeline-ში). ```

ნაბიჯი 6 · Nginx → კონტეინერი

Nginx არ იცვლება — და ერთი ხაფანგი

location / { proxy_pass http://127.0.0.1:5000; ... }
მე-8 ლექციაში API 127.0.0.1:5000-ზე იყო — კონტეინერი იმავე port-ზე გამოვიდა. 🌐 http://<IP>:8081/api/courses

⚠ Docker ufw-ს გვერდს უვლის

"5000:8080" → ინტერნეტში ღიაა!
"127.0.0.1:5000:8080" → მხოლოდ შიგნით ✓

### ნაბიჯი 6 · Nginx → კონტეინერი Nginx-ის კონფიგი **არ იცვლება**: მე-8 ლექციაში API `127.0.0.1:5000`-ზე იყო, და კონტეინერი ზუსტად იმავე port-ზე გამოვიყვანეთ (`"127.0.0.1:5000:8080"`).
