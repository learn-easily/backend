## ნაწილი 1 · SSH ტერმინალი სხვა ქვეყანაში მდგარ კომპიუტერზე — დაშიფრული და პაროლის გარეშე.
პრობლემა

სერვერი ფრანკფურტშია — როგორ „დავჯდე“ მასთან?

🔐 SSH — Secure Shell

შენი ტერმინალი, ოღონდ ბრძანებები სერვერზე სრულდება. ყველაფერი დაშიფრულია.

$ ssh giorgi@164.90.12.34
giorgi@lms-server:~$ ▊

🤖 პაროლით შესვლა?

Invalid user admin from 45.x.x.x
Invalid user test from 103.x.x.x
Failed password for root from 194.x.x.x
…ათასობით, ყოველდღე

ბოტები ინტერნეტის ყველა IP-ს უწყვეტად ამოწმებენ და პაროლებს არჩევენ

გამოსავალი: პაროლის ნაცვლად — გასაღები. მისი გამოცნობა პრაქტიკულად შეუძლებელია.
### პრობლემა: სერვერი ფრანკფურტშია — როგორ „დავჯდე“ მასთან? სერვერი მონაცემთა ცენტრშია, სხვა ქვეყანაში. ფიზიკურად მასთან ვერ მიხვალ — და არც გჭირდება. **SSH** (Secure Shell) შენს ტერმინალს სერვერს აკავშირებს: შენ კრეფ, ბრძანება **სერვერზე** სრულდება, შედეგი შენთან ჩანს. მთელი კავშირი **დაშიფრულია**. ```console WSL $ ssh giorgi@164.90.12.34 giorgi@lms-server:~$ ``` **პაროლის პრობლემა.** ინტერნეტში ბოტები უწყვეტად ამოწმებენ ყველა IP მისამართს და SSH-ზე პაროლებს არჩევენ (`admin/admin`, `root/123456`...). ახალი სერვერის ლოგში ასეთი ხაზები **რამდენიმე წუთში** ჩნდება: ```plain journalctl -u ssh Invalid user admin from 45.x.x.x Invalid user test from 103.x.x.x Failed password for root from 194.x.x.x ``` გამოსავალი — პაროლის ნაცვლად **SSH გასაღები**.

საკეტი: შეგიძლია ბევრ კარზე დაკიდო — სერვერზე, GitHub-ზე. მოპარვა საშიში არ არის

🔑 პირადი

მხოლოდ შენს კომპიუტერზე. არ გააგზავნო, არ ატვირთო GitHub-ზე. უფლება — 600

### SSH გასაღები: საკეტი და გასაღები SSH გასაღები **წყვილია** — ორი ფაილი, რომლებიც მათემატიკურად ერთმანეთს ემთხვევა: | ფაილი | ანალოგია | სად ცხოვრობს | |---|---|---| | `~/.ssh/id_ed25519.pub` — **საჯარო** | 🔒 საკეტი | სერვერზე (`~/.ssh/authorized_keys`), GitHub-ზე — ნებისმიერ ადგილას, სადაც შესვლა გინდა | | `~/.ssh/id_ed25519` — **პირადი** | 🔑 გასაღები | **მხოლოდ** შენს კომპიუტერზე | შესვლისას სერვერი გამოწვევას აგზავნის, რომლის სწორად „გახსნაც“ მხოლოდ შესაბამის პირად გასაღებს შეუძლია. თავად პირადი გასაღები ქსელში **არასოდეს** მიდის. საჯარო ნაწილის მოპარვა საშიში არ არის — საკეტით კარს ვერ გააღებ. პირადი კი პაროლზე მნიშვნელოვანია: ვისაც ის აქვს, ის შედის შენს ყველა სერვერზე. ```warn პირადი გასაღები **არ** გაუგზავნო არავის, **არ** ჩასვა ჩატში და **არ** ატვირთო GitHub-ზე. მისი უფლება უნდა იყოს `600` (მხოლოდ შენ) — წინა ლექციის `chmod` სწორედ აქ გამოგვადგება. ```

### ნაბიჯი 3 · პირველი შესვლა ```console WSL → სერვერი $ ssh root@164.90.12.34 The authenticity of host '164.90.12.34' can't be established. ED25519 key fingerprint is SHA256:p3Xa... Are you sure you want to continue connecting (yes/no)? yes Welcome to Ubuntu 24.04.3 LTS root@lms-server:~# ``` **fingerprint-ის კითხვა** — SSH გეკითხება: „ამ სერვერს პირველად ვხედავ, ვენდო?“. `yes` — და ის სერვერის „თითის ანაბეჭდს“ `~/.ssh/known_hosts`-ში იმახსოვრებს. თუ შემდეგში ანაბეჭდი შეიცვლება, SSH გაგაფრთხილებს (შეიძლება ვინმე შუაში ჩაჯდა). **მიმოიხედე:** ```console სერვერი # hostname # სერვერის სახელი # df -h / # დისკი: რამდენია თავისუფალი # free -h # RAM # uptime # რამდენი ხანია ჩართულია, დატვირთვა # exit # გამოსვლა — ისევ შენს WSL-ში ხარ ``` prompt-ში `#` ნიშნავს, რომ **root** ხარ. root-ით მუშაობა სახიფათოა — ამიტომ პირველივე საქმე ცალკე user-ის შექმნაა.

## ნაწილი 3 · პირველი დღის დაცვა ბოტები ახალ სერვერს წუთებში პოულობენ. ოთხი ნაბიჯი, რომელიც ყოველ ახალ სერვერზე ვაკეთებთ.
ნაბიჯი 4 · ცალკე user

root-ის ნაცვლად — giorgi + sudo

# adduser giorgi New password: ******** Full Name []: ← Enter-ებით Is the information correct? [Y/n] y # usermod -aG sudo giorgi ← sudo ჯგუფში # rsync --archive --chown=giorgi:giorgi \ ~/.ssh /home/giorgi ← გასაღები მასაც

### ნაბიჯი 4 · ცალკე user root-ის ნაცვლად ვქმნით ჩვეულებრივ user-ს, რომელსაც საჭიროებისას `sudo` შეუძლია: ```console root@lms-server # adduser giorgi # ახალი user — ითხოვს პაროლს, დანარჩენზე Enter # usermod -aG sudo giorgi # -aG: დაამატე ჯგუფში sudo # rsync --archive --chown=giorgi:giorgi ~/.ssh /home/giorgi ``` ბოლო ბრძანება root-ის `~/.ssh` საქაღალდეს (შენი საჯარო გასაღებით) ახალ user-ს უკოპირებს და მფლობელად მას ნიშნავს — ასე `giorgi`-თიც გასაღებით შეხვალ. **ახალ** WSL ფანჯარაში შეამოწმე: ```console WSL $ ssh giorgi@164.90.12.34 giorgi@lms-server:~$ sudo whoami [sudo] password for giorgi: root ``` `adduser`-ში მითითებული პაროლი **შესვლისთვის არ გამოიყენება** — ის მხოლოდ `sudo`-სთვისაა. შესვლა ისევ გასაღებით ხდება.

### ნაბიჯი 5 · SSH-ის კონფიგი: root-ით და პაროლით — აკრძალულია SSH სერვერის (`sshd`) პარამეტრები `/etc/ssh/`-შია. მთავარ ფაილს არ ვეხებით — ვქმნით საკუთარს `sshd_config.d` საქაღალდეში: ```console giorgi@lms-server $ sudo nano /etc/ssh/sshd_config.d/00-hardening.conf ``` ```ini 00-hardening.conf PermitRootLogin no PasswordAuthentication no ``` - `PermitRootLogin no` — root-ით შესვლა აკრძალულია (მის სახელს ყველა ბოტი იცის). - `PasswordAuthentication no` — პაროლით შესვლა აკრძალულია, მხოლოდ გასაღებით. ```console giorgi@lms-server $ sudo sshd -t # სინტაქსის შემოწმება: ცარიელი პასუხი = OK $ sudo systemctl restart ssh # ცვლილების ამოქმედება $ sudo sshd -T | grep -E "permitrootlogin|passwordauthentication" permitrootlogin no passwordauthentication no ``` `sshd -T` აჩვენებს **საბოლოო** პარამეტრებს, რომლითაც SSH რეალურად მუშაობს. **რატომ `00-`?** SSH ერთ პარამეტრზე **პირველ** ნანახ მნიშვნელობას იღებს, `sshd_config.d`-ის ფაილებს კი ანბანის მიხედვით კითხულობს. DigitalOcean-ს იქ შეიძლება უკვე ედოს `50-cloud-init.conf` — `00` მასზე ადრე იკითხება. ```warn **მიმდინარე SSH ფანჯარა არ დახურო**, სანამ **ახალ** ფანჯარაში არ შეამოწმებ, რომ `ssh giorgi@` მუშაობს. თუ რამე შეგეშალა, ძველი სესიით გაასწორებ. თუ მაინც ჩაიკეტე — Droplet-ის **Console** ბრაუზერში. ```

⚠ enable-მდე აუცილებლად allow OpenSSH — თორემ საკუთარ თავს ჩაკეტავ
### ნაბიჯი 6 · firewall: ufw **firewall** — „დაცვა კარებთან“: წყვეტს, რომელ port-ზე შეიძლება ინტერნეტიდან შემოსვლა. Ubuntu-ში მისი მარტივი ინტერფეისია **ufw** (uncomplicated firewall). ჩართვის შემდეგ **ყველა** შემოსული კავშირი იბლოკება, გარდა იმისა, რაც ცალკე დაუშვი. ```console giorgi@lms-server $ sudo ufw allow OpenSSH # port 22 — ჯერ ეს! $ sudo ufw enable Command may disrupt existing ssh connections. Proceed with operation (y|n)? y Firewall is active and enabled on system startup $ sudo ufw status Status: active To Action From OpenSSH ALLOW Anywhere ``` შემდეგ ლექციაზე, Nginx-ის დაყენებისას, დავამატებთ port 80-ს (HTTP), მოგვიანებით — 443-ს (HTTPS). ბაზის port (5432) კი **არასოდეს** გაიხსნება ინტერნეტისთვის. ```warn `ufw enable`-მდე **აუცილებლად** `ufw allow OpenSSH` — სხვა შემთხვევაში firewall შენს SSH კავშირსაც დაბლოკავს და სერვერზე ვეღარ შეხვალ (დაგრჩება მხოლოდ Droplet Console). ```
ნაბიჯი 7 · განახლება და swap

1 GB RAM — და სათადარიგო 2 GB

$ sudo apt update && sudo apt upgrade -y $ sudo fallocate -l 2G /swapfile $ sudo chmod 600 /swapfile $ sudo mkswap /swapfile $ sudo swapon /swapfile $ echo '/swapfile none swap sw 0 0' \ | sudo tee -a /etc/fstab ← reboot-ის შემდეგაც $ free -h total used free Mem: 961Mi 320Mi 410Mi Swap: 2.0Gi 0B 2.0Gi

🔄 apt upgrade

უსაფრთხოების განახლებები — პირველივე დღეს

💾 swap

როცა RAM ივსება, დისკის ნაწილი RAM-ად გამოიყენება. ნელია — მაგრამ პროგრამა არ კვდება

რატომ ახლა: .NET-ის build და ბაზა 1 GB-ში ვიწროდ ეტევა
### ნაბიჯი 7 · განახლება და swap **განახლებები** — ახალ სერვერზე პირველივე დღეს ვაყენებთ (უსაფრთხოების პატჩები): ```console giorgi@lms-server $ sudo apt update && sudo apt upgrade -y ``` `&&` — მეორე ბრძანება მხოლოდ მაშინ სრულდება, თუ პირველი წარმატებით დასრულდა. **swap** — დისკზე გამოყოფილი ადგილი, რომელსაც სისტემა RAM-ად იყენებს, როცა ნამდვილი RAM ივსება. დისკი RAM-ზე ბევრად ნელია, მაგრამ swap-ის გარეშე მეხსიერების ამოწურვისას Linux პროცესებს **კლავს** (OOM killer). ჩვენს 1 GB-იან სერვერზე მოგვიანებით .NET-ის build-იც მოგვიწევს და ბაზაც — swap დაგვაზღვევს. ```console giorgi@lms-server $ sudo fallocate -l 2G /swapfile # 2 GB ფაილი $ sudo chmod 600 /swapfile # მხოლოდ root $ sudo mkswap /swapfile # swap-ად მომზადება $ sudo swapon /swapfile # ჩართვა $ echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab # reboot-ის შემდეგაც $ free -h total used free Mem: 961Mi 320Mi 410Mi Swap: 2.0Gi 0B 2.0Gi ``` `/etc/fstab` — ფაილი, რომელსაც სისტემა ჩართვისას კითხულობს. `tee -a` ფაილის ბოლოს ამატებს ხაზს root-ის უფლებით (`sudo echo ... >> file` არ იმუშავებს — გადამისამართებას შენი user აკეთებს და არა sudo).

### ნაბიჯი 8 · `ssh lms` — IP-ის დამახსოვრების გარეშე `~/.ssh/config` (შენს WSL-ში, არა სერვერზე) — სერვერების „მისამართების წიგნი“: ```plain ~/.ssh/config Host lms HostName 164.90.12.34 User giorgi IdentityFile ~/.ssh/id_ed25519 ``` ახლა საკმარისია: ```console WSL $ ssh lms giorgi@lms-server:~$ ``` `lms` — შენ მიერ მოფიქრებული მოკლე სახელი. ის იმუშავებს ყველა SSH-ზე დაფუძნებულ ბრძანებაში — შემდეგ ლექციაზე ფაილებს ასე ავტვირთავთ: `rsync -avz ./ lms:/var/www/portfolio/`.
