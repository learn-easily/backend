### პრობლემა: `http://164.90.12.34:8081` ახლა ჩვენი სამი საიტი ასე იხსნება: | საიტი | მისამართი | |---|---| | portfolio | `http://164.90.12.34` | | Angular | `http://164.90.12.34:8080` | | LMS API | `http://164.90.12.34:8081` | სამი პრობლემა: - 🧠 **არავინ დაიმახსოვრებს** — CV-ში, კლიენტთან ან მეგობართან ასეთ ლინკს ვერ გაუგზავნი. - ⚠ **Not secure** — ბრაუზერი მისამართის გვერდით აფრთხილებს, ზოგი ფუნქცია (მაგ. Secure cookie) HTTP-ზე საერთოდ არ მუშაობს. - 👀 **ღია ტექსტი** — HTTP-ზე ყველაფერი, მათ შორის ლოგინი და პაროლი, დაუშიფრავად მიდის. კაფეს Wi-Fi-ში ვინც იმავე ქსელშია, შეუძლია ეს მოთხოვნა დაინახოს. გამოსავალი: **დომენი** (სახელი) + **HTTPS** (დაშიფვრა).

### ნაბიჯი 1 · დომენის ყიდვა და DNS ჩანაწერები **დომენი** ყიდვით კი არა, **ქირით** იღება — წლიურად, **registrar**-თან (დომენების რეგისტრატორი). `.com`-ის ფასი დაახლოებით $10 წელიწადში; `.ge` — ქართულ registrar-თან. ```tip სწავლისთვის არის უფასო ვარიანტიც — სერვისები, რომლებიც უფასო ქვედომენს გაძლევენ (მაგ. DuckDNS: `giorgi.duckdns.org`). ყველაფერი, რასაც დღეს ვაკეთებთ, HTTPS-ის ჩათვლით, მასზეც მუშაობს. ``` registrar-ის (ან DNS პროვაიდერის) panel-ში ვამატებთ **DNS ჩანაწერებს**: | Type | Name | Value | შედეგი | |---|---|---|---| | `A` | `@` | `164.90.12.34` | `giorgi.ge` → სერვერი (portfolio) | | `CNAME` | `www` | `giorgi.ge` | `www.giorgi.ge` → იგივე, რაც `giorgi.ge` | | `A` | `app` | `164.90.12.34` | `app.giorgi.ge` → Angular | | `A` | `api` | `164.90.12.34` | `api.giorgi.ge` → LMS API | - **A** — სახელი → **IP** მისამართი. - **CNAME** — სახელი → **სხვა სახელი**; IP-ს DNS მერე თვითონ პოულობს. - `@` — თვითონ დომენი, ქვედომენის გარეშე. - **TTL** — რამდენ ხანს ინახავენ სხვა სერვერები ამ პასუხს ქეშში (ნაგულისხმევი მნიშვნელობა საკმარისია). ოთხივე სახელი **ერთ** სერვერზე მიდის. როგორ გაარჩევს Nginx, რომელი საიტი აჩვენოს — შემდეგ სლაიდზე. ```console WSL $ dig +short api.giorgi.ge 164.90.12.34 ``` ახალი ჩანაწერი რამდენიმე წუთში (ზოგჯერ — საათებში) ვრცელდება. სანამ `dig` IP-ს არ დააბრუნებს, HTTPS-ზე არ გადავდივართ.
ნაბიჯი 2 · server_name

ერთი IP, ერთი port — სამი საიტი

server { listen 80 default_server; server_name giorgi.ge www.giorgi.ge; root /var/www/portfolio; ... } server { listen 80; # 8080 → 80 server_name app.giorgi.ge; root /var/www/app; ... } server { listen 80; # 8081 → 80 server_name api.giorgi.ge; location / { proxy_pass http://127.0.0.1:5000; ... } }
ბრაუზერი ყოველ მოთხოვნაში აგზავნის Host-ს → Nginx ადარებს server_name-ს
### ნაბიჯი 2 · server_name: ერთი IP, ერთი port — სამი საიტი აქამდე საიტებს **port-ებით** ვყოფდით (80, 8080, 8081). დომენებით ყველა 80-ზე (და მერე 443-ზე) იქნება — ბრაუზერი ყოველ მოთხოვნაში აგზავნის header-ს `Host: api.giorgi.ge`, და Nginx მას server block-ების `server_name`-ს ადარებს: ```nginx sites-available/portfolio server { listen 80 default_server; server_name giorgi.ge www.giorgi.ge; root /var/www/portfolio; ... } ``` ```nginx sites-available/app server { listen 80; # იყო 8080 server_name app.giorgi.ge; root /var/www/app; ... } ``` ```nginx sites-available/lms-api server { listen 80; # იყო 8081 server_name api.giorgi.ge; location / { proxy_pass http://127.0.0.1:5000; ... } } ``` `default_server` — თუ `Host` არცერთ `server_name`-ს არ ემთხვევა (მაგ. ვინმემ პირდაპირ IP გახსნა), ეს block პასუხობს. ```console Termius · lms-server $ sudo nginx -t && sudo systemctl reload nginx ``` `http://app.giorgi.ge`, `http://api.giorgi.ge/api/courses` — მუშაობს. port-ები 8080/8081 აღარ გვჭირდება — HTTPS-ის შემდეგ მათ ufw-დან წავშლით.

## ნაწილი 2 · HTTPS — უფასოდ
როგორ მუშაობს

სერტიფიკატი — „პასპორტი“ დომენისთვის

🔐 დაშიფვრა

ბრაუზერი და სერვერი იმ კავშირს შიფრავენ — გზაში არავინ წაიკითხავს

🪪 სერტიფიკატი

ადასტურებს: „ეს ნამდვილად giorgi.ge-ის სერვერია“. გასცემს სანდო ორგანიზაცია

🆓 Let's Encrypt

უფასო სერტიფიკატები, 90 დღე, ავტომატური განახლება — certbot-ით

ჩვენთან HTTPS Nginx-ზე მთავრდება: ბრაუზერი ⇄ 🔒 ⇄ Nginx ⇄ http ⇄ API (სერვერის შიგნით)
### HTTPS: სერტიფიკატი — „პასპორტი“ დომენისთვის **HTTPS** = HTTP + დაშიფვრა (TLS). ორ რამეს აკეთებს: - 🔐 **დაშიფვრა** — ბრაუზერსა და სერვერს შორის ყველაფერი დაშიფრულია; კაფეს Wi-Fi-ში ვერავინ წაიკითხავს. - 🪪 **ავთენტიკაცია** — **სერტიფიკატი** ადასტურებს, რომ ეს ნამდვილად `giorgi.ge`-ის სერვერია და არა ყალბი. სერტიფიკატს გასცემს ორგანიზაცია, რომელსაც ბრაუზერები ენდობიან (Certificate Authority). **Let's Encrypt** — უფასო Certificate Authority. მისი სერტიფიკატები **90 დღე** მოქმედებს და **certbot** მათ ავტომატურად აახლებს. **სად მთავრდება HTTPS?** ჩვენთან — **Nginx-ზე**: ბრაუზერი ⇄ HTTPS ⇄ Nginx ⇄ HTTP ⇄ API. Nginx-სა და API-ს შორის კავშირი სერვერის შიგნითაა (`127.0.0.1`), ამიტომ დაშიფვრა იქ არ სჭირდება. ამას **TLS termination** ჰქვია — და ეს reverse proxy-ს ერთ-ერთი მთავარი სარგებელია (მე-8 ლექცია).
ვაკეთებთ ერთად · ნაბიჯი 3

certbot --nginx — ერთი ბრძანება

რა შეცვალა certbot-მა

Nginx-ის კონფიგი — certbot-ის შემდეგ

server { server_name api.giorgi.ge; location / { proxy_pass http://127.0.0.1:5000; ... } listen 443 ssl; # managed by Certbot ssl_certificate /etc/letsencrypt/live/giorgi.ge/fullchain.pem; ssl_certificate_key /etc/letsencrypt/live/giorgi.ge/privkey.pem; include /etc/letsencrypt/options-ssl-nginx.conf; } server { if ($host = api.giorgi.ge) { return 301 https://$host$request_uri; } listen 80; server_name api.giorgi.ge; return 404; }

## ნაწილი 3 · კონფიგი და საიდუმლოებები LMS-ს ორი საიდუმლო აქვს: ბაზის პაროლი და — ავთენტიკაციის შემდეგ — JWT-ის ხელმოწერის გასაღები. ვინც JWT გასაღებს გაიგებს, ნებისმიერი user-ის სახელით „ტოკენს დაბეჭდავს“.

Request.Scheme = http · RemoteIp = Docker-ის IP — ყველა მომხმარებლის
ASPNETCORE_FORWARDEDHEADERS_ENABLED: "true"
Request.Scheme = https · RemoteIp = მომხმარებლის ნამდვილი IP
Nginx ამ header-ებს მე-8 ლექციიდან აგზავნის — ახლა API მათ კითხულობს
### ნაბიჯი 5 · proxy-ს უკან: API-ს ჰგონია, რომ http-ია HTTPS **Nginx-ზე** მთავრდება (TLS termination). API-მდე მოთხოვნა უკვე `http`-ით მიდის, Docker-ის შიდა მისამართიდან. ამიტომ API-ისთვის: - `Request.Scheme` = `http` — აპის მიერ შექმნილი ლინკები და redirect-ები `http://`-ით იქნება; - `RemoteIpAddress` = Docker-ის შიდა IP — ლოგებში ყველა მომხმარებელი ერთი IP-დან ჩანს. Nginx ნამდვილ მონაცემებს header-ებით გადასცემს (მე-8 ლექციიდან გვაქვს): `X-Forwarded-Proto: https` და `X-Forwarded-For: <მომხმარებლის IP>`. API-მ ისინი უნდა **წაიკითხოს** — ამას ASP.NET Core-ის **Forwarded Headers** აკეთებს. ერთი გარემოს ცვლადით: ```yaml compose.yaml — api.environment ASPNETCORE_FORWARDEDHEADERS_ENABLED: "true" ``` ეს ცვლადი რთავს Forwarded Headers-ს `X-Forwarded-For`-ისთვის და `X-Forwarded-Proto`-სთვის, და ენდობა proxy-ს Docker-ის ქსელიდანაც. ახლა `Request.Scheme` = `https`, IP — მომხმარებლის ნამდვილი. ```note ეს ცვლადი სწორია, როცა API-ზე მხოლოდ Nginx-ის გავლით მიდიან — ჩვენთან ასეა: port `127.0.0.1`-ზეა გამოტანილი (მე-10 ლექცია). თუ API ინტერნეტში პირდაპირ იქნებოდა ღია, ვინმე ამ header-ებს გააყალბებდა. ```
