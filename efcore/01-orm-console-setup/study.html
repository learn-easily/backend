1 · პრობლემა

ნაწილი 1 · ორი სამყარო, ორი ენა

სლაიდი 4

რატომ არ ელაპარაკება C# ბაზას „თავისით“? თუ პრობლემას არ გავიგებთ, გამოსავალი არ დაგვაფასდება.

ერთი და იგივე პროდუქტი — C#-ში და SQL-ში

სლაიდი 5
🟣 C# სამყარო
class Product{    public int Id { get; set; }    public string Name { get; set; }    public decimal Price { get; set; }} var p = new Product { Name = "მაუსი", Price = 45 };

C# ფიქრობს კლასებით და ობიექტებით. ყველაფერი მეხსიერებაშია: პროგრამა დაიხურა — მონაცემი გაქრა.

🗄️ SQL სამყარო
CREATE TABLE Products (    Id INT IDENTITY(1,1) PRIMARY KEY,    Name NVARCHAR(100) NOT NULL,    Price DECIMAL(10,2) NOT NULL); INSERT INTO Products (Name, Price)VALUES (N'მაუსი', 45);

SQL ფიქრობს ცხრილებით და ჩანაწერებით, და მონაცემი მუდმივად ინახება.

ორივე ერთსა და იმავეს აღწერს, მაგრამ სხვადასხვა ენაზე ლაპარაკობს. როგორ ვათარგმნოთ ერთიდან მეორეში?

ვცადოთ ხელით — ORM-ის გარეშე

სლაიდი 6

ასე კითხულობდნენ ბაზას ORM-მდე (ADO.NET — .NET-ის „დაბალი დონის“ გზა):

ADO.NET — ბაზიდან პროდუქტების წაკითხვა
using var conn = new SqlConnection(connectionString);conn.Open(); var cmd = new SqlCommand("SELECT Id, Name, Price FROM Products", conn);using var reader = cmd.ExecuteReader(); var products = new List<Product>();while (reader.Read()){    products.Add(new Product    {        Id    = reader.GetInt32(0),        Name  = reader.GetString(1),        Price = reader.GetDecimal(2)    });}
  • კავშირი — ხელით ვხსნით და ვხურავთ.
  • SQL — უბრალო ტექსტია. Products-ში შეცდომა რომ დაუშვა, კომპილატორი ვერ დაინახავს — მხოლოდ გაშვებისას ჩავარდება.
  • ყოველი სვეტი ხელით, ნომრით გადაგვაქვს property-ში.

16 ხაზი — და ეს მხოლოდ ერთი SELECT-ია. INSERT, UPDATE, DELETE — ყველა ცხრილზე ისევ ასე. (ეს კოდი დასამახსოვრებელი არ არის — მხოლოდ შრომის მასშტაბს აჩვენებს.)

იგივე ამოცანა — ORM-ით: 16 → 1 ხაზი

სლაიდი 7
csharp
var products = db.Products.ToList();
  • SQL-ს ORM წერს ჩვენ მაგივრად.
  • სვეტები property-ებში თვითონ ჯდება — reader.GetInt32(0) აღარ გვჭირდება.
  • შეცდომას კომპილატორი გვაჩვენებს — Products-ს თუ არასწორად დაწერ, კოდი არ აეწყობა.

2 · ORM

ნაწილი 2 · რა არის ORM?

სლაიდი 8

ზოგადი იდეაა, არა მხოლოდ C#-ის: ერთხელ თუ გაიგებ, Java-შიც, Python-შიც, JavaScript-შიც ამოიცნობ.

სამი ასო: O · R · M

სლაიდი 9
  • O — Object: ობიექტი — C#-ის კლასები და ობიექტები.
  • R — Relational: რელაციური ბაზა — ცხრილები, სვეტები და მათი კავშირები (Foreign Key-ები). MS SQL სწორედ ასეთია.
  • M — Mapping: დაკავშირება — რა რას შეესაბამება ერთ და მეორე მხარეს.

ORM — თარჯიმანი C#-სა და ბაზას შორის. ჩვენ ვწერთ C#-ს, ის ბაზას SQL-ით ელაპარაკება.

📘 ტერმინები
ORM
Object-Relational Mapping: ბიბლიოთეკა, რომელიც C#-ის ობიექტებს ბაზის ცხრილებთან აკავშირებს და SQL-ს თვითონ წერს

Mapping: რა რას შეესაბამება

სლაიდი 10
C# · კოდი SQL · ბაზა
კლასი class Product ცხრილი Products
property decimal Price სვეტი Price
ობიექტი new Product { … } ჩანაწერი (ერთი ხაზი)

ORM-მა ეს სამი წესი იცის, და მათით ორივე მიმართულებით თარგმნის.

როგორ თარგმნის ORM — ორივე მიმართულებით

სლაიდი 11

„მომეცი 100 ლარზე იაფი პროდუქტები“:

  1. C# კოდი — db.Products.Where(p => p.Price < 100). SQL-ის არცერთი სიტყვა.
  2. ORM იღებს — მან იცის ჩვენი Mapping.
  3. ORM თარგმნის C# → SQL: SELECT … FROM Products WHERE Price < 100. ეს SQL ჩვენ არ დაგვიწერია!
  4. ბაზა იღებს ჩვეულებრივ SQL-ს და აბრუნებს ჩანაწერებს.
  5. ORM თარგმნის უკან: ჩანაწერები → Product ობიექტები.
