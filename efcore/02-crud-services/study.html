წინა ლექციაზე ბაზაში ჩავწერეთ და ყველაფერი წავიკითხეთ. მაგრამ ნამდვილ პროგრამას მეტი სჭირდება: ერთი კონკრეტული ჩანაწერის პოვნა, მისი შეცვლა და წაშლა. დღეს CRUD-ს ვასრულებთ, ვიგებთ, საიდან იცის EF Core-მა, რა შევცვალეთ, ბაზის კოდს Program.cs-იდან ცალკე სერვისში ვალაგებთ და ბოლოს ვაწყობთ მენიუს — პირველ ნამდვილ კონსოლის პროგრამას ბაზით.

  • კონსოლის მენიუ, რომელიც სერვისს იძახებს

Program.cs
using var db = new DataContext(); var all   = db.TodoItems.ToList();var item  = db.TodoItems.Find(2);var milk  = db.TodoItems.FirstOrDefault(t => t.Title == "რძის ყიდვა");var open  = db.TodoItems.Where(t => !t.IsDone).ToList();var count = db.TodoItems.Count(t => !t.IsDone);
მეთოდი აბრუნებს რას აკეთებს SQL (გამარტივებით)
ToList() List<TodoItem> ყველა ჩანაწერი SELECT * FROM TodoItems
Find(2) TodoItem? ერთი — Primary Key-ით SELECT TOP(1) * … WHERE Id = 2
FirstOrDefault(…) TodoItem? პირველი, რომელიც პირობას აკმაყოფილებს SELECT TOP(1) * … WHERE Title = N'…'
Where(…).ToList() List<TodoItem> ყველა, რომელიც პირობას აკმაყოფილებს SELECT * … WHERE IsDone = 0
Count(…) int რამდენია SELECT COUNT(*) … WHERE IsDone = 0
  • Find მხოლოდ Primary Key-ით ეძებს. თუ ეს ჩანაწერი EF Core-ს უკვე წაკითხული აქვს, ბაზაში საერთოდ არ წავა — მეხსიერებიდან მოგცემს.
  • FirstOrDefault ნებისმიერი პირობით ეძებს: სახელით, Email-ით, და ა.შ.
  • Where აბრუნებს სიას (შეიძლება ცარიელსაც), ამიტომ ბოლოს ToList(). Where-ის გარეშე ToList() არ ვწერთ — Count, FirstOrDefault, Find პასუხს მაშინვე აბრუნებენ.
  • პირობა C#-შია (t => !t.IsDone), მაგრამ ბაზაში SQL-ად მიდის — ბაზა თვითონ ფილტრავს და მხოლოდ საჭირო რიგები მოდის.

TodoItem?-ის კითხვის ნიშანი მნიშვნელოვანია — შემდეგ სლაიდზე ვნახავთ, რატომ.

ვსწავლობ EF Core-ს. მაქვს Entity TodoItem (Id, Title, IsDone, CreatedAt) და DbSet TodoItems. მომეცი 6 პატარა ამოცანა LINQ-ზე (Find, FirstOrDefault, Where, OrderBy, Count, Any) — სათითაოდ. ჯერ მე დავწერ კოდს, მერე შეამოწმე და მითხარი, რა SQL გაიგზავნება ბაზაში. ქართულად.

null — ჩანაწერი არ არსებობს

სლაიდი 12

Find და FirstOrDefault აბრუნებს TodoItem?-ს — კითხვის ნიშანი ნიშნავს: შეიძლება null იყოს. თუ ასეთი Id არ არსებობს, ობიექტი არ გვაქვს.

💥 ასე — არა
var item = db.TodoItems.Find(99); Console.WriteLine(item.Title);   // NullReferenceException

Id = 99 ბაზაში არ არის → item არის null → null-ის .Title-ს ვერ წაიკითხავ და პროგრამა ვარდება. Visual Studio ამას წინასწარ გეუბნება: item-ს ყვითელი ტალღა უჩნდება (Dereference of a possibly null reference).

✅ ასე — კი
var item = db.TodoItems.Find(99); if (item is null){    Console.WriteLine("ვერ მოიძებნა");    return;} Console.WriteLine(item.Title);   // აქ item უკვე null ვერ იქნება

წესი: Find / FirstOrDefault-ის შემდეგ ჯერ null-ს ამოწმებ, მერე იყენებ.

მეთოდი ვერ იპოვა →
First(…) შეცდომა: InvalidOperationException: Sequence contains no elements
FirstOrDefault(…) null

First-ს მხოლოდ მაშინ იყენებენ, როცა ჩანაწერი აუცილებლად უნდა არსებობდეს. მომხმარებელი Id-ს ხელით წერს — შეიძლება შეეშალოს, ამიტომ ჩვენ FirstOrDefault / Find + null-ის შემოწმება გვჭირდება.

ნაწილი 3 · იპოვე, შეცვალე, შეინახე

სლაიდი 13

წაკითხვა ვიცით. ახლა — განახლება და წაშლა. ორივე ერთნაირად იწყება: ჯერ ჩანაწერს ვპოულობთ.

განახლება: იპოვე → შეცვალე → SaveChanges

სლაიდი 14
Program.cs
using var db = new DataContext(); var item = db.TodoItems.Find(2);if (item is null) return; item.IsDone = true;db.SaveChanges();
  1. იპოვე — Find(2) → SELECT … WHERE Id = 2. (null-ის შემოწმება აქაც აუცილებელია.)
  2. შეცვალე — item.IsDone = true ჩვეულებრივი C#-ია. ბაზას ჯერ არ ეხება.
  3. SaveChanges() — ახლა მიდის:
sql
UPDATE TodoItemsSET IsDone = 1WHERE Id = 2

ორ რამეს დააკვირდი:

  • Update() მეთოდი არსად დაგვიწერია.
  • SQL-ში მხოლოდ IsDone წერია — Title-ს და CreatedAt-ს არ ეხება, რადგან ისინი არ შეცვლილა.

საიდან გაიგო EF Core-მა, რომ სწორედ IsDone შევცვალეთ? ამაზეა შემდეგი სლაიდი.

💡

db.TodoItems.Update(item) მეთოდი არსებობს, მაგრამ აქ საჭირო არ არის: ის ყველა სვეტს „შეცვლილად“ მონიშნავს და UPDATE ყველა სვეტზე წავა. გვჭირდება მაშინ, როცა ობიექტი EF Core-ს არ წაუკითხავს (მაგალითად, სხვაგან შეიქმნა). ჩვენ ჯერ ვპოულობთ — ამიტომ საკმარისია შეცვლა და SaveChanges.

Change Tracker — EF Core-ის მეხსიერება

სლაიდი 15

DataContext-ს შიგნით აქვს Change Tracker („ცვლილებების მეთვალყურე“). ის ასე მუშაობს:

  1. Find(2) — ჩანაწერი მოვიდა ბაზიდან. ობიექტს რომ გვაძლევს, EF Core თავისთვის იმახსოვრებს მის „ფოტოს“: Title = "საშინაოს დაწერა", IsDone = false.
  2. item.IsDone = true — ჩვენ ობიექტს ვცვლით. ფოტო იგივე რჩება.
  3. SaveChanges() — EF Core ყველა ობიექტს თავის ფოტოს ადარებს: Title იგივეა, IsDone შეიცვალა → წერს UPDATE … SET IsDone = 1 WHERE Id = 2.

ამიტომ არ გვჭირდება Update(): EF Core-მა თვითონ იცის, რა შეიცვალა. და ამიტომაა SQL-ში მხოლოდ ერთი სვეტი.

📘 ტერმინები
Change Tracker
DataContext-ის ნაწილი, რომელიც წაკითხულ და დამატებულ ობიექტებს თვალს ადევნებს და SaveChanges-ის დროს ითვლის, რა უნდა გაიგზავნოს ბაზაში
Snapshot („ფოტო“)
ობიექტის მნიშვნელობების ასლი წაკითხვის მომენტში
🤖 Change Tracker-ის ახსნა
ვსწავლობ EF Core-ს. ამიხსენი Change Tracker მარტივად, მაგალითით: რა ხდება Find-ის, property-ს შეცვლის და SaveChanges-ის დროს? რას ნიშნავს Entity State (Added, Unchanged, Modified, Deleted)? და რა არის AsNoTracking — როდის იყენებენ? ქართულად.

ყოველ ობიექტს მდგომარეობა (State) აქვს

სლაიდი 16

db.Entry(item).State გვაჩვენებს, რას ფიქრობს Change Tracker ამ ობიექტზე:

Program.cs
var item = db.TodoItems.Find(3);if (item is null) return; Console.WriteLine(db.Entry(item).State);   // Unchanged item.Title = "პურის ყიდვა";Console.WriteLine(db.Entry(item).State);   // Modified db.SaveChanges();Console.WriteLine(db.Entry(item).State);   // Unchanged

SaveChanges-ის შემდეგ ობიექტი ისევ Unchanged-ია: ბაზა და ობიექტი ისევ ერთნაირია, ახალი „ფოტო“ გადაიღო.

რა გავაკეთეთ State SaveChanges აგზავნის
Add(item) Added INSERT
Find / ToList Unchanged არაფერს
property-ს შეცვლა Modified UPDATE
Remove(item) Deleted DELETE

ეს ცხრილი მთელი CRUD-ის საიდუმლოა: Add და Remove ბაზას არ ეხება — მხოლოდ მდგომარეობას ცვლის. ბაზაში ყველაფერს ერთად SaveChanges აგზავნის.

წაშლა: იპოვე → Remove → SaveChanges

სლაიდი 17
Program.cs
using var db = new DataContext(); var item = db.TodoItems.Find(4);if (item is null) return; db.TodoItems.Remove(item);db.SaveChanges();
  1. იპოვე — Remove-ს ობიექტი სჭირდება.
  2. Remove(item) — ობიექტს მონიშნავს როგორც Deleted. ბაზას ჯერ არ ეხება — ზუსტად ისე, როგორც Add.
  3. SaveChanges() — ახლა მიდის:
sql
DELETE FROM TodoItemsWHERE Id = 4
⚠️

ბაზაში წაშლილს Ctrl+Z არ აქვს. ნამდვილ პროგრამებში წაშლამდე მომხმარებელს ეკითხებიან: „დარწმუნებული ხარ? (y/n)“. ზოგი პროგრამა საერთოდ არ შლის — მხოლოდ მონიშნავს (IsDeleted = true) და სიაში აღარ აჩვენებს. ამას „soft delete“ ჰქვია.

ExecuteUpdate და ExecuteDelete — ბევრი ჩანაწერი ერთად

სლაიდი 18

ამოცანა: „წაშალე ყველა შესრულებული დავალება“. რაც ვიცით, იმით ასე გამოვა:

🐢 Remove-ით
var done = db.TodoItems    .Where(t => t.IsDone)    .ToList(); foreach (var t in done)    db.TodoItems.Remove(t); db.SaveChanges();

მუშაობს, მაგრამ EF Core ჯერ ყველა შესრულებულ დავალებას წაიკითხავს და მეხსიერებაში ჩატვირთავს, მერე კი თითოეულზე ცალკე DELETE-ს გაგზავნის. 10 000 ჩანაწერზე ეს ნელია.

EF Core 7-დან არსებობს ერთი ბრძანება:

⚡ ExecuteDelete
db.TodoItems    .Where(t => t.IsDone)    .ExecuteDelete();
sql
DELETE FROM TodoItems WHERE IsDone = 1

და განახლებისთვის — „ყველა მონიშნე შესრულებულად“:

⚡ ExecuteUpdate
db.TodoItems    .Where(t => !t.IsDone)    .ExecuteUpdate(s => s.SetProperty(t => t.IsDone, true));
sql
UPDATE TodoItems SET IsDone = 1 WHERE IsDone = 0

ორივე აბრუნებს int-ს — რამდენი რიგი შეიცვალა.

⚠️

ExecuteDelete და ExecuteUpdate მაშინვე სრულდება — SaveChanges არ სჭირდებათ და Change Tracker-ს გვერდს უვლიან. თუ იმავე ჩანაწერები DataContext-ს უკვე წაკითხული ჰქონდა, მეხსიერებაში ძველი მნიშვნელობები დარჩება. ერთი ჩანაწერისთვის ჩვეულებრივი გზა გამოიყენე (იპოვე → შეცვალე → SaveChanges), ბევრისთვის — Execute*.

CRUD EF Core-ში — სრულად

სლაიდი 19
ოპერაცია EF Core SQL SaveChanges?
Create Add(item) INSERT ✅ საჭიროა
Read ToList · Find · FirstOrDefault · Where · Count SELECT — არ სჭირდება

რამდენიმე ცვლილება შეგიძლია ერთად დააგროვო და ბოლოს ერთი SaveChanges გამოიძახო — EF Core ყველაფერს ერთად გაგზავნის, ერთ ტრანზაქციაში: ან ყველა ცვლილება შესრულდება, ან არცერთი.

Update და Delete ერთნაირად იწყება: იპოვე → შეამოწმე null. ეს ხაზები პროგრამაში ყველგან განმეორდება — და აქ ჩნდება შემდეგი პრობლემა.
